# 10–20 人封闭 Beta：准备方案

状态：**PLAN_PREPARED，0 邀请、0 招募、0 新参与者数据**。本轮只准备，不发送邀请、开通账号、增加遥测或公开下载。维护者先完成获准包的实际发行与支持条件，再执行本方案。

## 目标与人群

验证一个问题：经常把截图交给 ChatGPT 的普通 Mac 用户，能否独立完成首次使用，并在两至四周后主动继续使用，而不是仅在演示中成功。

总计 10–20 人，分两批：先 3–5 人验证安装、权限和求助文案，再补足总数。优先覆盖研究/学习、产品/设计、开发/分析三类既有截图使用者；不要求参与者为测试制造每日使用量。参与者自行拥有可用的 Mac、Chrome 和 ChatGPT 使用权限，使用自己愿意交给该服务的内容。不能上传他人私密信息或工作保密材料。

记录实际 macOS、架构、Chrome 版本、界面语言和常用显示器布局；不采集硬件序列号、账号、聊天链接、窗口标题或真实屏幕内容。Intel 硬件、辅助功能使用者等只有在获准包和相关支持条件满足时纳入对应范围；不要让未验证人群充当未知兼容性的隐性代价。

## 四周节奏

| 时间 | 任务与结果 | 不应做什么 |
| --- | --- | --- |
| 入组前 | 发获准包清单、简明隐私、[参与者任务卡](PARTICIPANT-PACKET.md)、退出方式；可选择不反馈诊断 | 不默认录屏、上传桌面、索要完整日志或使用条款未声明的信息 |
| 第一天，约 15 分钟 | 独立安装/权限，截一张自制无隐私样例，附加到自建草稿；不发送测试消息；记录卡片出现与最终状态分开 | 维护者中途接管后仍记“独立成功”；把微图收起当成最终上传成功 |
| 第 2–7 天 | 自愿在真实需要时使用；遇错按任务卡保留记录；收集首次障碍和恢复体验 | 每天催任务、按是否每日打开给成功评分 |
| 第 2 周 | 一次自愿简短回访：是否再次使用、多少次有实际需求、未用原因、是否回到旧方式 | 把无需求者一概算产品失败，或从分母删除失败安装者 |
| 第 3–4 周 | 一次结束回访：是否持续使用、留用/卸载原因、最有价值与最困扰之处、付费意愿区间（可跳过） | 承诺产品定价、付款、用优惠换好评或要求分享敏感内容 |

## 记录与指标：不埋点

使用本地研究表和参与者自愿报告，按代号保存；联系信息单独由获准组织者管理，不进入源码仓库。原始反馈不公开，公开结果只用汇总。任何存储期限、删除请求处理方式需在实际同意材料中明确，本方案不擅自定义新自动保留/删除策略。

| 指标 | 分母/定义 | 记录方式 |
| --- | --- | --- |
| 首次安装完成率 | 成功打开获准包的人数 / 实际开始安装人数 | 保留系统阻断、放弃、需协助；不用“收到 ZIP”代替完成 |
| 首次附加成功率 | 对应图片卡片出现在正确草稿、正文和旧附件保持的人数 / 实际开始首用任务人数 | START 单列；若最终上传状态未确认，另记 unconfirmed，不能写最终成功 |
| 第一次价值所需时间 | 从开始安装到正确草稿收到首张的时间 | 安装/权限/截图/附加各段可选；成功者中位数及范围，未完成人数单列，不给失败伪造时长 |
| 安全事件 | 错目标、重复附加、正文/旧附件改变、数据丢失、意外公开内容 | 每例保留归因不确定性；不只报百分比，停止扩展调查 |
| 恢复完成 | 实际遇问题且愿意跟进的事件中，找回图片/恢复操作/仍不确定分别计数 | 没遇失败不算恢复通过；找回原图不等于重新附加成功 |
| 第二周再次使用 | 第 8–14 天至少一次自发用于实际需求 / 所有已入组人数；另报有需求子集 | 未回访记 unknown，不能排除后计算漂亮留存 |
| 第 2–4 周持续使用 | 相应每周至少一次实际用途的自愿报告 | 分周给绝对人数；不是每日活跃/后台运行指标 |
| 方法偏好与退出 | Riftlet / 系统拖拽 / 复制粘贴 / 其他；继续、暂留、卸载及原因 | 保留多人多原因与未回答，不只挑好评 |
| 付费意愿 | 自愿意向及理由 / 回答人数 | 研究信号，不是收入或成交；不发起付款 |

10–20 人是发现障碍的早期样本，不足以证明总体转化率、长期可靠性或商业需求。采用绝对人数、版本和场景报告；不在看到结果后更换分母或把中途修复的新包与旧包合成一个“全通过”版本。

## 停止、升级与结项

出现错投、重复、正文改变、原始数据损坏、截图/凭证泄露，停止该问题相关操作和新增分发，保留原包、原失败及最少必要私有证据。组织者处理，参与者不需要清库、改安全设置或反复重传。普通权限/界面障碍按模板记录，修复后只对受影响范围做新版本验证；旧结果不覆盖。

测试中升级需要明确新版本、改动、数据兼容与回退说明，不静默更换包。结束时产出安装漏斗、使用/恢复体验、安全事件、退出原因、待修列表及版本化证据；结论仍由实际结果决定：

- `PERSONAL_BETA_3_ACCEPTED`：只引用原个人交付范围。
- `CLOSED_BETA_READY`：必须满足本轮实际闭测交付条件；此计划本身不授予。
- `PUBLIC_BETA_READY`：还需对外发行、隐私支持及公开范围的独立结论；闭测样本好评不能代替。
- 缺所有者签名/公证条件时明确 `PUBLIC_BETA_BLOCKED_OWNER_CREDENTIALS`，不伪造成功。
