# Bounded original-operation page snapshot

`page-evidence-helper.js` is a lab-only read-only function for the existing exact-tab MAIN-world nonce bridge. It is not packaged, installed, scheduled or automatically invoked. It introduces no GUI transport and does not authorize a click/upload. Pass the original generated asset UUID, operation UUID and positive integer attempt from the private SQLite operation, rather than selecting a new target or guessing from the page URL. All three fields are mandatory. In the existing bridge, evaluate the function source and invoke it with `{assetID: originalAssetUUID, operationID: originalOperationUUID, attempt: originalAttempt}`; JSON-encode that parameter rather than interpolating untrusted source text.

The helper uses three fixed read-only routes: current v11 and historical v10/v9. It visits at most 32 generations and 32 operations per generation in each registry (at most 3,072 operations total), returning at most one exact asset/operation/attempt match. UUID matching is case-insensitive; attempt matching is exact. A duplicate exact operation across generations or versions returns `AMBIGUOUS_ORIGINAL_OPERATION` with no operation result; it never prefers a newer registry over an original historical match. It returns the code-owned `programVersion` (9, 10 or 11), slot indices and attempt without exporting operation/asset IDs, hashes, full targets, conversation identity, filenames, URLs, raw labels or chat text. Original receipts and full target equality must be checked separately in local private database evidence. `BOUND_REACHED`, `GENERATION_CYCLE` and `DIAGNOSTIC_UNAVAILABLE` are incomplete snapshots. No missing event may be inferred from them.

It does not call `captureTarget`, `valid`, `sample`, `observe`, `stopRootMonitors`, a network probe, or any other observer method. It only reads existing operation fields and original attachment-node membership, labels as equality booleans, and the current progress value as a bounded number. It performs no listener installation, DOM/global write, file input, request, cancellation, retry or message send. The helper source contains no account-specific data.

`inputObservedAtMS`, `startObservedAtMS` and `proofCompletedAtMS` share the document's monotonic `performance.now()` timebase. `timeOriginMS` permits comparison with separately collected host timing, subject to clock/transport uncertainty. Final time is a diagnostic value stored only after final proof; it is not a completion criterion. These times do not measure exact SQLite commit, rendered animation or physical network byte dispatch. A missing final diagnostic on an older installed closure remains unknown.

`hasStoredStart` means the operation retains its first qualifying pair, not that the page currently returns `uploadStarted`. The independent `startDisqualified`, `uploadingSnapshot`, current-node and label booleans help interpret that historical pair but do not rerun validity or confer receipt-policy admission. `hasProof` likewise does not revalidate the entire original draft. The actual adapter observation and private full identity comparison remain authoritative.

All three versions retain their installed semantics; this helper does not migrate or stop any registry and cannot promote historical v9/v10 evidence to v11. The v11 implementation fixes native MutationRecord NodeList iteration; this helper cannot repair old v10 event history. The v9 progress diagnostic probe remains unchanged as the source of the original live experiment.

The v10/v11 candidates permit initial missing `aria-valuenow` only while waiting on the original node before any finite sample. Missing after a finite value or a finite→missing→finite coalesced batch still disqualifies start. All three versions require a single original File input/hash, original operation/asset/attempt/full target, unique original card/image and the same precisely labelled progress node with two increasing finite samples below 100, strictly after input. Coalesced regressions and invalid intermediate values disqualify start. This establishes the reviewed DOM progress candidate only. The round-three network probe separately associates exact-name request candidates, response routes and file hashes; cached fetch and unread Request-stream paths remain unknown. Zero observed requests never proves no upload, and either diagnostic alone never establishes safe retry or production admission.

Offline verification: `node --test engineering/evidence/2026-10-27-real-mac-round5/page-evidence-helper.test.cjs`. Tests validate bounds, redaction, readonly behavior and timeline extraction using synthetic objects; they are not live Chrome or real-upload acceptance.
