# Bounded original-operation page snapshot

`page-evidence-helper.js` is a lab-only read-only function for the existing exact-tab MAIN-world nonce bridge. It is not packaged, installed, scheduled or automatically invoked. It introduces no GUI transport and does not authorize a click/upload. Pass the original generated asset UUID from the private SQLite operation, rather than selecting a new target or guessing from the page URL. In the existing bridge, evaluate the function source and invoke it with `{assetID: originalAssetUUID}`; JSON-encode that parameter rather than interpolating untrusted source text.

The helper visits at most 32 generations and 32 operations per generation, returning at most 32 matches. UUID matching is case-insensitive. It returns slot indices and attempts to distinguish matching original attempts without exporting operation/asset IDs, hashes, full targets, conversation identity, filenames, URLs, raw labels or chat text. Original receipts and full target equality must be checked separately in local private database evidence. `BOUND_REACHED`, `GENERATION_CYCLE` and `DIAGNOSTIC_UNAVAILABLE` are incomplete snapshots. No missing event may be inferred from them.

It does not call `captureTarget`, `valid`, `sample`, `observe`, `stopRootMonitors`, a network probe, or any other observer method. It only reads existing operation fields and original attachment-node membership, labels as equality booleans, and the current progress value as a bounded number. It performs no listener installation, DOM/global write, file input, request, cancellation, retry or message send. The helper source contains no account-specific data.

`inputObservedAtMS`, `startObservedAtMS` and `proofCompletedAtMS` share the document's monotonic `performance.now()` timebase. `timeOriginMS` permits comparison with separately collected host timing, subject to clock/transport uncertainty. Final time is a diagnostic value stored only after final proof; it is not a completion criterion. These times do not measure exact SQLite commit, rendered animation or physical network byte dispatch. A missing final diagnostic on an older installed closure remains unknown.

`hasStoredStart` means the operation retains its first qualifying pair, not that the page currently returns `uploadStarted`. The independent `startDisqualified`, `uploadingSnapshot`, current-node and label booleans help interpret that historical pair but do not rerun validity or confer receipt-policy admission. `hasProof` likewise does not revalidate the entire original draft. The actual adapter observation and private full identity comparison remain authoritative.

The v9 candidate requires a single original File input/hash, original operation/asset/attempt/full target, unique original card/image and the same precisely labelled progress node with two increasing finite samples below 100, strictly after input. Coalesced regressions and invalid intermediate values disqualify start. This establishes the reviewed DOM progress candidate only. The round-three network probe separately associates exact-name request candidates, response routes and file hashes; cached fetch and unread Request-stream paths remain unknown. Zero observed requests never proves no upload, and either diagnostic alone never establishes safe retry or production admission.

Offline verification: `node --test engineering/evidence/2026-10-27-real-mac-round5/page-evidence-helper.test.cjs`. Tests validate bounds, redaction, readonly behavior and timeline extraction using synthetic objects; they are not live Chrome or real-upload acceptance.
