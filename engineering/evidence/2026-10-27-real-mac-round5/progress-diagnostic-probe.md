# Initial progress-state diagnostic, not an observer fix

The first round-five operation reached one input and final proof without upload start. Its retained state (`progressNode` absent, `progressValue` null, `startDisqualified` true) is consistent with rejection before storing the first progress node. It does **not** identify which initial value or timing condition caused rejection. Initial absent `aria-valuenow` is a hypothesis awaiting the next independent generated asset's evidence; the prior successful operation must not be reused.

Use `progress-diagnostic-probe.js` only through the existing exact-tab MAIN bridge. First prearm the existing v9 original observer, then invoke `riftletRound5InstallProgressProbe({assetID: newPrivateAssetUUID})` before the new asset is clicked. The asset argument is mandatory and must come from the private store. Installation refuses a previously committed/input operation. It does not prepare or upload anything. A new original operation may be created later by the normal App click.

Read sanitized events via `globalThis.__riftletRound5ProgressProbe.query()`. Call `.stop()` after collection; the probe also stops after 60 seconds, 160 events, or 1,024 mutation records. Other bounds are 32 generations × 32 operations, 256 candidate cards, and 256 added/removed nodes in one record. Stop disconnects only its own MutationObserver, removes only its own change listener, clears its own timeout, and releases page/operation references. The small global API and sanitized event array remain readable; the probe cannot be silently reinstalled over it. It never invokes or stops the original observer, alters progress, hooks networking, changes focus, sends messages, or inputs files.

Binding requires the specified asset's unique original operation, original file input, committed tombstone, inputCount 1, inputSequence, exact generated file name, size and PNG type. It observes the original form only after that input. The original v9 change listener must already exist; if listener ordering prevents correlation, the probe stops with `INPUT_NOT_CORRELATED` instead of inferring an input.

Output contains numeric progress or `missing`/`invalid`, code-owned sequence/time, oldValue classified the same way, node/card membership and label equality booleans, and existing adapter flags. It never returns raw labels, names, operation/asset IDs, conversation IDs, URL, text, file bytes, DOM objects or exceptions. Invalid raw values are not preserved. Callback-time `atMS` is document-monotonic observation time, not the exact underlying mutation timestamp. `oldValue` records provide order within a coalesced batch, while the accompanying current value is the callback-time snapshot. An initial null oldValue can support absent-attribute history; missing or bounded-out logs cannot prove that an intermediate state never happened.

Proposed repair, **not implemented here**: bind the original exact progress node before its first numeric value and allow only `aria-valuenow === null` to wait without start evidence. Preserve the node through that wait. The first finite value establishes a baseline; only a later strictly increasing finite value below 100, with all existing input/hash/identity/time gates, may qualify. Empty strings, malformed/nonfinite/out-of-range values are not the same as missing. After any finite value, missing values, regression and replacement must permanently disqualify start. Removal/replacement during initial waiting must also disqualify. The mutation-record rule must distinguish initial null→first finite from finite→null→finite in one batch; changing only the sample parser would be insufficient. Final proof remains independent.
