## What changed

1. Ordinary observed Chinese Chat composers are identified by the unique marked form, its exact textbox/file input, explicit non-Work/non-home/non-readonly React properties and the current committed business draft key. The draft key differs from the URL. No first-input or URL-as-identity fallback exists. Current fiber membership and `HostRoot.current` are required, including a valid alternate branch; live ancestry was 373 levels, so the bounded limit is 512.
2. Chrome's Apple Events `execute javascript` runs in an isolated world. A read-only main-world probe could not see the isolated v4 registry; main-world React properties were absent from isolated-world DOM wrappers. The App now submits one percent-encoded `javascript:void(...)` expression to the exact PID/window/tab and reads a random nonce DOM receipt through Apple Events. It never resubmits the command when that receipt is lost. Encoding is necessary because URL parsing strips literal line breaks and would corrupt `//` comments. Five-second native event timeouts still apply; the one-second read-loop budget is not a hard total transport deadline.
3. Optional logical draft identity is persisted without rewriting old operations. Only two valid identities in the observed profile can distinguish drafts in the same tab. A legacy nil/unknown identity is still a whole-tab wildcard, including against a newer known identity. Full receipt equality still includes every original target field. Compensation/UNKNOWN never gains retry authority.
4. Input focus authority and original-operation observation have separate lifetimes. Blur/focus/visibility revoke input but retain a still-bound committed observer. Route, mode, business identity, node or original attachment loss remains invalidating. Navigation events invalidate the generation; trusted interaction outside the form revokes input. The MAIN command itself produced zero Navigation events in the live control probe.
5. Native prearming starts before recovery, wakes for activation/wake/new images, and coalesces requests behind one in-flight capture. Stale host epochs cannot publish ACKs. The press boundary only freezes existing authority; it never captures a later target or retains a rejected click for automatic replay.
6. The existing UI/helper explicitly distinguish AppKit mouse and accessibility invocation paths. Opt-in `--acceptance-trace` logs only bounded, code-owned selection fields. A mouse path is not proof of a human physical mouse; a press record is not proof of a completed selection.

### Remaining target-admission defect

A completely unobservable React business A→B→A transition that reuses the DOM and produces no observed interaction/navigation event can still defeat a current-state-only continuity check. The new event guards cover the tested event paths, not that general case. Do not promote this development profile to production or call P0-A/P0-C fully solved. A follow-up must establish a reliable business transition epoch or refuse that unsupported continuity class without timeout/token/DB clearing.
