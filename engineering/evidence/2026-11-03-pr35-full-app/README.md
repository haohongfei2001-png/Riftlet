## Reproduced defect and minimum fix

A normal A input superseded an in-flight read-only observation of B. The cancelled
capture consumed its observation demand, leaving only the one-second fallback.
B's next click was safely refused; no B operation or input was created. The next
ACK arrived 77.73 ms after that click. This was not Core targetBusy or the old
715 ms Apple Events queue delay.

The adapter now reports the **exit of its original file-input transport** once,
before START/completion polling. Main requests one new observation through the
existing single-flight scheduler. The request survives either ordering of that
signal and capture completion. It does not contain a click or target to replay.
The actual accepted-selection FIFO exit also requests observation, covering
validation refusals that never enter append. Independent review moved this signal
away from premature UI settlement. Input exclusion, identity tombstones,
permission/epoch checks, commit uncertainty and original targeted operations are
unchanged. No input is retried or redirected.
