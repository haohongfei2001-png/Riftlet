# Microsoft Edge attachment experiment

The shipping module contains a read-only `EdgeApplicationHost`. It freezes the foreground Edge process birth, active native window and tab, and their URL. Subsequent validation rejects a changed process, selection or address. The read-only `EdgeConversationInspection` evaluates the bundled service-specific inspector only against the frozen native tab and exact address. It retains a short-lived, document-local binding and decodes a bounded result containing enums and a count. Microsoft Edge's scripting definition does not guarantee the isolation of its JavaScript world. A page could influence those observations. This candidate supplies no input or receipt authority. The ordinary App has no route that submits to Edge. The command below builds a separate test executable for the mutating experiment.

On macOS, run the test from the repository root.

```sh
python3 engineering/universal-attachment/edge/verify.py --mode headless
python3 engineering/universal-attachment/edge/verify.py --mode apple-events
```

The verifier checks the installed Edge bundle and its scripting dictionary, creates two 1×1 PNGs with different bytes, starts an ephemeral loopback server and opens a new isolated Edge profile with extensions disabled. It leaves the user's profiles and existing tabs alone. The first command runs the page portion in headless Edge. It checks real HTTP requests for four operations against the pinned draft and exact PNG bytes. Two receive correlated 201 acknowledgements. One receives a correlated 422 rejection. The final failure scenario delivers the bytes but drops the reply, which leaves that original operation UNKNOWN. A later independent operation still succeeds. It also checks duplicate commit, a changed draft, a replaced editor and preservation of the original attachment node, text, unfocused editor and backward selection.

The second command compiles the Swift sender and addresses only the process started by the verifier. It requires that process to be frontmost, a kernel birth match, the complete absolute native window/tab descriptor, the exact disposable draft URL, passive Automation permission, and a successful Edge execute-JavaScript response. Every mutation rechecks the pinned host plus the page's frozen document and composer. Read-only observation follows once-only input. An uncertain reply aborts the run. The same fixture page command is used in both modes. The experiment reads file bytes generated by this verifier, outside all customer databases and screenshot directories.

A headless browser normally has no native foreground window. For the full native route, `--hosted-runner-window` enables an isolated foreground window only on a disposable GitHub-hosted macOS runner. Exit 77 identifies an unavailable prerequisite. An empty profile can also lack permission to execute JavaScript through Apple Events. The verifier leaves all permission settings intact.
