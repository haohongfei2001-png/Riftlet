## 半秒连点时的明确拒绝

在另一个专用临时草稿中，Riftlet 相隔 496.888 毫秒收到两次独立点击。截图 640 进入原草稿并收起；641 在输入前得到明确的 `resolveSelection/nativeEventFailed(-1712)`，没有生成操作或上传，保留可见。原正文、选区和附件保留，未提交消息。

641 先花 87.079 毫秒获取原生身份，再花 36.283 毫秒绑定页面和编辑器。失败发生在复核原活动标签的阶段，总用时 134.686 毫秒。同步读取共用 150 毫秒上限，每次 Apple Event 需要至少一个完整时钟刻度。日志能定位失败阶段，不能区分本地剩余刻度不足与 Edge 的事件超时。后续排队发生在该次绑定之后。[两个鼠标回调、计时和可见性](640-641-ordinary-app.json)

## 缩短原生绑定后的复测

修复源码 `b7a3d4af9e335f19e3ad0d08c9d85426280d9efc` 省去一次同步跨进程读取。在原标签页仍可见并有页面焦点时固定该文档和编辑器，最后再读一次原生选择。150 毫秒上限、写入前的完整身份复核和原操作的一次性输入均保留。[签包身份](rapid-fix-runtime.json) · [原生与 JavaScriptCore 回归](rapid-fix-model-tests.json)

643、644 两次产品选择相隔 483.286 毫秒，分别用 102.065 和 97.814 毫秒完成绑定。后续有两项独立失败。643 在传第六块时收到原生超时，在文件输入前被明确拒绝。644 触发了一次文件输入，仍为 UNKNOWN。两条操作都没有临时草稿路由标记。在原窗口和标签中，记录的文档 ID 与之前的测试相同，但编辑器和草稿代际已变。独立读回发现原路由已改变，随即停止。644 的输入无法归属到已授权的原临时草稿。两张微图都留在屏幕上，两张图均未再投递。[实测原件的独立核查](643-644.json)

在后续产品源码 `1481c74bbb12e997de1149362a7ed45fdb6b2120` 中，已绑定到原点击的分块命令复用本地保存的通道。两次完整原生身份复核之间只读一次原文档能力。为一次性读取保留原一秒总时限，按原 nonce 轮询回执仍使用 250 毫秒的单次上限。明确失败、超时和取消都没有第二次文件调度。新增的诊断只记录阶段、耗时、检查次数和操作标识的摘要。[47 项本机原生／JavaScriptCore 回归](bound-chunk-model-tests.json)
