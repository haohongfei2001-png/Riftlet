# 隔离 Mac 首次使用验收

2026-11-07，在 ARM64、macOS 27.0（26A428）上分别运行了正式起点 `05abf6c` 和修订源码 `153e77bf83366b96789b23fe4b48a1fe644ca42c` 构建的完整 App。两份 App 均从隔离副本启动。每次首次运行使用新的 `--settings-review` UUID、偏好域、SQLite、媒体根和截图来源。该模式允许本地收录，关闭真实浏览器交互及系统授权请求。本机使用已有的 macOS 登录账户。

| 操作 | 实际观察 |
| --- | --- |
| 首次打开 | 两个版本均显示三步向导。修订版首屏说明如何沿用系统截图、把目标 ChatGPT 草稿放在 Chrome 前台，并点击边缘微图。首屏和最后一步都给出菜单栏入口。 |
| 收录与无浏览器点击 | 两次分别用 macOS 截取各自测试 App 的引导窗口。两份 PNG 都自带系统截图标记，均出现可点击微图，原件与各自的私有副本逐字节一致。对该实例自己的微图发送一对经窗口归属确认的软件鼠标事件，微图保留。两份数据库均有 1 个资产、0 个附加操作、0 个 START。 |
| 截图目录失去读取权限，再恢复 | 在当前实例的测试目录撤销 POSIX 读取权限，重新检查后向导显示不可访问。修订版进一步提示按 ⇧⌘5 确认保存位置，并在允许读取后重新检查。恢复目录权限，再次检查，状态回到可读取。 |
| 菜单栏、设置、历史 | 经原生辅助功能操作，从菜单栏实际进入设置、权限与帮助、历史与存储，再打开截图历史。基线曾在无需 Chrome 自动化的同一页要求打开 Chrome JavaScript，修订版已移除此指令。修订版历史侧栏显示“收起不会删除图片”。选中测试记录后，动作说明明确列出了私有副本、系统原图和聊天附件。 |
| 重启 | 正常退出修订包，再用同一 UUID 和 App 启动。首次向导没有自行重开，既有截图仍可见，经菜单栏设置可主动重开向导。两次正常退出后用 SQLite 只读事务对照，资产、操作、START 记录及媒体散列相同。 |

**文件夹选择。** 另一个独立身份的 App 使用真实 `NSOpenPanel` 和产品的目录校验、只读书签实现，仅提供两个专用测试文件夹。通过辅助功能按下该面板的确认按钮，选中正确目录后保存书签。选择另一测试目录时，校验拒绝该选择，面板仍打开，前一份书签字节相同。取消面板也保留书签。完整 App 的确认回调另会重新读取系统截图位置，再接受所选目录。

**权限与目标状态。** 另一个本机探针向本次编译的原生设置和向导控件提供受控状态，15 项检查通过。未检查状态说明须由用户主动申请。拒绝状态提供“系统设置 → 隐私与安全性 → 自动化 → Riftlet → Google Chrome”及重新检查动作。macOS 已授权、Chrome 已关闭、当前无可用聊天、本地模式和离线模式分别保持各自提示。检查按钮只分发一次受控动作。这里没有连接 Chrome、操作实际系统授权或观察新的 ChatGPT 附件。

**未验证范围。** 本机没有独立的交互式 macOS 测试账户，未观察普通 App 触发的首次 TCC 弹窗、用户点击允许或拒绝、Chrome 实际脚本开关，或物理鼠标点击。POSIX 拒绝和受控授权状态均按其各自范围记录。真实 ChatGPT 为 `REAL_ACCEPTANCE_NOT_RUN`。本机 Command Line Tools 缺少 XCTest 模块，正式 XCTest 见本次 PR 的 macOS CI。

**证据身份。** 基线 App 可执行文件 SHA-256 为 `9c7c1f596b7c1d3690407791f0d502b78439367c040e6644fdd116f290238dde`，修订版为 `28fa498a4300b12f23c1554a6c226f59792b3a367ec3f518d46cad8104d7d470`。修订版的首次运行、同包重启和受控状态记录散列分别为 `aa34f23749c8dd990001bafbeba48adf65bc94b535541da02dcf3a7c1b578bb4`、`eb144f6337ebb7477aa1555469c6d3557b8cef9aa7db2ead0224fc066936d8c1`、`a41cea794c587037daf9868eb43415ab1b1f9a28b8e5186b767e0b09265d3de5`。原始窗口、操作记录和测试截图保存在本机私有目录。

首轮状态探针遗漏导航到帮助页。中间 App 检查过早查询辅助功能进程身份，首次运行没有创建测试资产，对空根的重启检查也未完成。独立面板试验早期还遇到测试偏好域与 bundle ID 重名，以及系统未实现测试调用的 `ok:`。这些失败均已保留。最终检查等待确切的测试进程身份，使用单独偏好域，并按下属于该测试面板的真实确认按钮。

## 首轮 CI 后的历史窗口修正

选中截图后，新增的保留说明会参与 AppKit 对窗口宽度的测量。Intel XCTest 对同一 680 × 480 点窗口报告两次 728 点的最小拟合宽度，超过既有 681 点上限。测试断言保持原样。[首轮正式原生 CI](https://github.com/haohongfei2001-png/Riftlet/actions/runs/42370036322)

本机用同一场景创建 1200 × 750 合成 PNG，经真实历史控制器加载并选中，依次切换当前视图、图像网格、当前视图。修正前，三次内容拟合宽度为 707.5、676、707.5 点。提示字段现在按详情栏实际分配的文本宽度换行，原句完整保留。修正后三次分别为 680、676、680 点，窗口始终为 680 × 480 点，选中记录、已解码的图片对象和等比缩放均保持一致。把窗口加宽到 980 点，当前视图的提示恢复为单行，固定宽度的图像网格详情仍按列宽换行。

另从隔离目录运行完整修订包，二进制 SHA-256 为 `eee79ecc82c027b9a374dbe567599a2ba804c5870e740a178c668c7db382b75e`。现有原生历史验收完成 7 项，取得 19 帧自有窗口证据，覆盖两种样式、明暗外观和最小尺寸。同包新进程重启完成 5 项，前后数据摘要相同。两份原始报告 SHA-256 分别为 `2c53e5366d60d6f4f26ab4421c5c7b00218cd5ea71bdf4e9ca775845490d02ac` 和 `a78e4b811fdc43431136dda03223a6bebd2be82c88435dfd28e58e1058fb50e9`。此前的首次使用包与证据仍独立保留。
