# Native file picker experiments

Run `python3 -B Tests/UniversalNativePickerHost/run.py --only webkit` on macOS with an accessible WindowServer and the Apple Swift toolchain. The default fixture creates a nonpersistent WKWebView in an unordered window of a process with activation prohibited. All traffic goes to a temporary server on the IPv4 loopback interface. Two generated PNGs live in a private temporary directory. It has no access to external profiles, cookies, chat accounts or messages.

The test exercises the product module's `NativePickerFileDelivery` with real `WKUIDelegate` open-panel callbacks. It captures the original view/window, document, navigation generation, directory/file descriptors and expected file digest. The handoff checks the frame and actual bytes before releasing the URL. The driver checks that an atomic pathname replacement with identical bytes is refused and that the same callback cannot release a file twice. The server records its first body byte separately from receipt of the entire expected PNG. The draft acknowledges the server reply only after checking its existing editor, text, text selection and attachment nodes. Neither the callback nor the server's first byte alone counts as completion. This validates a cooperating WKWebView fixture. Safari and other external applications own their own UI delegates, and file URLs do not offer an atomic cross-process handoff for subsequently mutable files. [Apple WKUIDelegate documentation](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:runopenpanelwith:initiatedbyframe:completionhandler:))

`python3 -B Tests/UniversalNativePickerHost/run.py --only external-ax` independently checks the result classifier and, on a GitHub-hosted macOS console, creates two private, signed AppKit conversation fixtures in turn. The external observer pins the frontmost receiver's process launch, window, editor and attachment button. The custom AppKit file-list fixture offers two real files in a chooser inside the original window. `AXPickerFileHandoff` chooses the radio control with the fixture-defined AXIdentifier derived from the exact local file URL and byte digest and only presses the pinned submit button after the same chooser reports that exact row selected. Both the wanted and decoy rows must expose their expected identities. Only this purpose-built test app declares that identity format. The second fixture uses a real `NSOpenPanel` sheet with a one-file directory and initial filename. Its observer requires a proven original sheet, exact file URL, selected row and default button. The normal macOS XPC panel service may not expose all these links. Both receivers have automatic deadlines and process cleanup.

Each receiver checks its own original window, text, selection and prior PNG, submits the exact selected file over loopback, waits for the receiver's acknowledgement and attaches the decoded image in its original window. `externalAX` records each result separately. A custom file-list success has no bearing on the system `NSOpenPanel` or external service acceptance. The harness does not request permission, interact with other applications or register any production AX profile.

`python3 -B Tests/UniversalNativePickerHost/detached.py` runs a separate two-process component experiment. Both processes prohibit activation and the receiver window is never ordered. The external process checks advertised AXPress, selects its unique generated radio, reads its selected AXValue and the receiver's acknowledgement, and presses the original enabled submit button once. The receiving process checks its own handler counts and PNG bytes. It exercises the actual `AXPickerActionButton` used by the custom hosted fixture. A hidden test cannot establish a foreground click, an AI conversation upload or system `NSOpenPanel` ownership.

The hosted AppKit file-list run compiles `EdgeConversationPicker` with its controlled fixture initializer and uses that transport's entry, file selection and confirmation. The two-row test validates the original editor and selected range through AX. `externalAX.appkit-file-list.transport` identifies runs of this implementation. The historical receiver logs predate that change.

The ordinary Edge host test first records the two Riftlet mouse-action results. Following two original-window refusals or a proven pre-mouse veto, a separate helper can test the same owned Edge tab with a single generated neutral PNG. It checks the native Edge process/window/tab, the exact loopback document's AX editor, prior image, text and selection, and the native chooser's selected file URL before confirmation. Missing Automation consent refuses before opening the chooser. Its optional receiver records the first byte, complete expected bytes and the original page's acknowledgement independently under `controlledEdgePicker`. The receiver is closed to files throughout the ordinary test. This test-only executable is compiled with `RIFTLET_CONTROLLED_EDGE`; the commercial application has no Edge writer registration.
