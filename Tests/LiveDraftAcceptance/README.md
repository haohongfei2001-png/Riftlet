# Build 53 live draft QA

The two previously recorded operations can be read from the isolated build 53 QueueStore without opening either browser. Supply the original QA root, operation UUID and PNG digest to `python3 read-operation.py`. The command verifies the candidate executable, then returns a sanitized record for that operation. The two captured records are in [build53-exploratory-store.json](../../docs/releases/1.0.7/evidence/build53-exploratory-store.json).

For an authorized, available browser connection, `createLockedDraft` in `locked-draft.cjs` owns a newly created test window and tab. The collector provides the connected Browser object, native application bundle ID, two locators grounded in the live UI (the genuine New chat action and original composer), and its independent read-only `read(tab)` observer. The observer must bind the supplied opaque window/tab handles to the actual browser process birth and native window/tab IDs and return both this target and the currently foreground receiver. Its document, composer, draft generation, navigation and route witnesses must be sampled at the read, with no re-binding to a new target. If the connection or observer is unavailable the live case remains blocked.

After landing on the official home page, the harness rejects a conversation route, existing content or ambiguous editor. It activates New chat and freezes the draft. The seed phase presses individual keys directed to that tab, then Shift-Left and verifies the selected text. No clipboard, global keyboard or Send action is used. With an existing test attachment in the same composer, `beforeClick(requiredPriorCard)` records the selection and member identities. `afterClick(receipt, expectedPayloadSHA256)` reads the same draft after the actual user-path Riftlet click. Successful page-only observation must still be correlated with the independent signed-app action and receipt. The helper covers the fresh draft setup. Saved-chat ownership, a native tray click, elapsed time, cross-run uniqueness, the G4 loop and W0 admission are separate.

Use `withLockedDraft(options, execute)` to cover setup, the test body and cleanup; it returns the callback result and cleanup status. Failed setup and callback errors carry a cleanup status when a tab was allocated and identified. The helper uses the original Tab object's close method once. Uncertain ownership, changed content and a lost close reply are reported separately. An individual `createLockedDraft` caller should await `run.close()` in its own finally block.

If Edge shows the generated QA filename but the signed App has no START, `edgePreviewShape(generatedName)` requires the observer's `locateOriginalEditor(tab, target)` to return the original native and draft identity fields, tab/window handles and a locator uniquely bound to that composer. It uses a read-only evaluation on this locator even after focus moves away. A collector lacking that locator cannot collect the shape. The diagnostic samples the original editor's visible matching preview and its bounded ancestry. It records source type, current/declared source equality, decoded dimensions, child counts and placement of the same-file Remove control. Original URLs, pixel data, message text and generated filename are excluded. No observation of this shape was possible on the historic attempt.

`node --test locked-draft.test.cjs` runs an isolated fake browser with deliberate focus/identity changes. It does not exercise browser keyboard delivery or establish G1/G2/G4.
