# Compiled Swift to local Chrome attachment test

Run `Tests/Issue120Integration/run.sh` on the development Mac with Google Chrome installed. The runner links the debug RiftletAdapters and RiftletCore build outputs. It launches Chrome headless with a fresh temporary profile and a page served on a random loopback port. The simulated site's Content Security Policy permits only its own scripts and HTTP calls, inline image data and no form submission.

A single operation crosses QueueStore, ProviderAttachmentRuntime, Issue120ProviderAdapter, a test-only transport and the actual bundled JavaScript in Chrome. The test imports a generated PNG, persists an invocation, applies a single setter, and requires one input/change in the original local editor. A duplicate append must be refused. The fixture then changes the same accepted card to explicit failure. A new SQLite connection resolves the original invocation for observation and checks the returned card identity. The independent page-side counts also check the prior text, selection and attachment, with zero foreign inputs and sends.

The native window/tab identifiers and transport are controlled here. The same debug-only loopback recipe is bound to the dynamic origin and hashed by Swift and the browser. The package contains no write recipe for a public site. This test covers the connected development code path. It has no physical tray click, native browser permission test, public-site authentication, service failure, signed-App L2 or L3 acceptance. The checked-in receipt records the exact run; a random port legitimately changes its bound-program digest.
