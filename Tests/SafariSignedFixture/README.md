# Signed Safari local QA (no accounts)

Use a disposable, interactive macOS desktop and ordinary Safari. This fixture is intentionally not an attachment-provider route. Do not use another person's Mac, browsing data or unrelated windows, change security preferences from a script, or turn off unrelated Safari security settings. Do not start a billable runner or VM for this check.

## Entry and evidence

1. Run `python3 fixture.py --preflight --dmg /path/to/verified-Riftlet-68.dmg` with Python 3.11+. Preflight matches the known DMG bytes and checks for a display. It cannot verify interactivity or grant consent. Independently validate the DMG/App's notarization tickets and Gatekeeper acceptance, mount the DMG read-only, check the running app is 1.1.0 build 68 from that image, and use a fresh isolated QA account and capture directory. Record Safari/macOS versions, artifact digest, signing results and scope. If there is no approved candidate artifact or interactive isolated desktop, stop and record the corresponding environment blocker.
2. Start `python3 fixture.py --serve /path/to/unused/qa-fixture.png` to check setup. Open the printed loopback URL in a dedicated normal Safari window containing just that tab. In Riftlet, use the real browser connection check in Settings for Safari. macOS Automation consent, if needed, must be granted through the normal prompt for this isolated session. Otherwise mark `BLOCKED_ENV`.
3. In Safari's own UI, show web developer features, then use **Safari Settings → Developer → Allow JavaScript from Apple Events**. Check once with the setting OFF (expect disabled, not a product failure) and once ON (expect connection ready). Restore the initial setting on the disposable session, then close only the test window. Do not change the setting via the CLI. Record both states and actual observed results separately as `SIGNED_NATIVE_SETUP_TRANSPORT`. See Apple's [Developer settings](https://developer.apple.com/documentation/safari-developer-tools/developer-settings).
4. Separately, capture a small synthetic test pattern through the normal screenshot flow in the isolated account; never capture real conversations. Check its SHA-256 and restart the fixture with `python3 fixture.py --receive EXACT_LOWERCASE_SHA256`; reload its new URL once. Drag the corresponding thumbnail once from the signed App to the marked receiver. A valid `SIGNED_NATIVE_LOCAL_DROP` result has one matching file, unchanged original draft, zero input/change/send/submit events, and the original retained after the drag. Keep the origin isolated and record a redacted receipt; the fixture does not inspect the App's store. If the App's verified isolated trace is available, also check zero click transfer operations. Use an independent test proof for these separate claims and mark an unobservable item `NOT_RUN`. Stop the loopback fixture when finished.

## Do not infer a provider result

`--self-test` checks only the fixture server and synthetic file. A fixture does not qualify as a live AI site. The production Safari click path intentionally rejects an unrecognized (including loopback) provider origin. Do not edit routing policy, impersonate any hostname, install a fabricated profile, or substitute WebDriver. This fixture cannot validate native click-to-attach on Safari; leave that provider outcome `NOT_RUN` unless separately observed in an authorized attested session. A site login wall is outside current scope. There is no external network action, submit destination, or provider account in this fixture.
