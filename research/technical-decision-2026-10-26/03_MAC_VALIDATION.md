# Riftlet｜一次真实 Mac 会话的最小验证规程

## 目的与范围

一次准备、一次会话，把候选路线分别判为“可进入正式实现”或“还缺哪项具体证据”。不承诺一次会话一定证明所有目标可行，也不把少数成功样本当长期可靠率。

这是下一轮获准真实环境的执行规格。**本包没有创建原生 App、诊断 extension 或自动操纵聊天的程序；当前真实运行状态仍是 NOT_TESTED。** 操作者应只使用合成图片和独立的可丢弃草稿。

准入分成：

- **INPUT_PROVEN**：新图被目标接纳并追加，未改变已有文字／附件。
- **IDENTITY_PROVEN**：可以唯一关联本次图片、原窗口／标签页／聊天／草稿。
- **READY_PROVEN**：同一附件有正向可用状态，可与占位、上传中、失败区分。
- **RECOVERY_PROVEN**：已分派后的断线／重启不盲重传，能回查或稳定保留 UNKNOWN。

四项分别记录。只证明 INPUT 的路线不能实现“成功吞噬”；普通流程全部 UNKNOWN 的路线也不能以“没有误报”通过。

## 0. 一次性准备

准备受限的研究工作目录，不是正式产品仓库。下一轮允许的小诊断程序包括：

1. 原生小探针：记录前台 PID／窗口、展示合成缩略图、输出本进程窗口与 AX 状态。含透明单画布和逐图小 panel 两种开关。没有 Send／Return 动作。
2. 共享网页诊断 adapter：baseline／input／observe／query 四类操作，分别经 Apple Events 和实验扩展接入。两条路线的实际输入逻辑、成功条件、合成文件保持相同。
3. 低权限 MV3 实验扩展和小 stdio host，仅在下一轮范围明确允许后准备。只允许批准的 ChatGPT 测试标签页。不得为缺少授权打开调试端口、绕过浏览器开关或换工具重复被拒绝的动作。
4. 合成素材：可区分的 A、B、C 三张 PNG；与 A 内容相同但 assetId 不同的 A2；一张足够大以观察上传过程的图；JPEG／HEIF 编码样例（只测声明支持的格式）；12 个轻量队列项。上传名含 UUID，后缀与 MIME 匹配编码。
5. 文字基线：“中文 / English / emoji 🙂”、两行文字、选中范围和一张既有附件。另备同名不同内容的图，以检测错误关联。

事先确定本次会话的许可范围：测试目录、Chrome profile／窗口、合成草稿、需要的 Automation／AX／扩展能力，以及可恢复的网络故障方式。已有授权有效，不在每个用例重新询问。缺少的能力只记录一次 BLOCKED，继续其余独立部分。

网络故障优先仅作用于指定测试标签页。原生客户端若无法局部注入，只有在会话许可覆盖短时断网时才执行，并立即恢复。未获准则该用例 BLOCKED，不用合成 error DOM 冒充真实失败。

## 1. 环境清单只做一次

写 environment.json：

| 字段 | 内容 |
| --- | --- |
| OS | macOS 版本、build、芯片 |
| 浏览器 | bundle ID、完整版本、profile 本地测试代号；Apple Events JS 开关现状 |
| 桌面客户端 | 新版／Classic 的 bundle URL、bundle ID、version/build；安装缺失明确记缺失 |
| surface | Web Chat、Web Work、新版 Mac Chat、新版 Mac Work、Classic；不合并成一个 ChatGPT 标签 |
| 显示 | 内屏／外屏、各自 scale、Spaces／Stage Manager 状态 |
| 截图 | 当前保存目标、浮动预览状态、图片编码；只读，不偷偷修改 |
| 权限 | 实际获准的 Automation／AX／测试 extension／目录能力；适用系统上 NSPasteboard.accessBehavior 与实际提示 |
| 执行器 | 可合法自动执行的动作，及只能由获准操作者正常完成的动作 |

若执行器只是没有 GUI 能力，可由获准操作者在测试草稿正常添加合成图，探针仅观察，用来证明 AX／DOM 语义。标成 observer-only，不能算自动一击输入通过。如果动作本身被策略拒绝，不换入口绕过。

## 2. 第一站 先找成功语义再做 transport A B

### W00 自然附件流程

在 Web Chat 和 Work 各一个独立草稿正常添加 A，分别记录：

1. 空草稿／带合成文字及既有附件的 baseline；
2. 文件输入刚发生；
3. 上传中，必要时受控限速；
4. 页面正向认为该附件可用；
5. 实际失败或中断；
6. 用户移除该合成附件。

只采集 composer 子树和本次文件相关事件。不要导出聊天历史、cookies、Authorization、签名 URL 或无关网络正文。

寻找确定的状态差异与唯一身份：

- 文件名是否完整显示、被截断、替换或丢失？
- 上传前后是否有稳定 attachment/fileId？
- 是否有可解释为“该附件已可用”的属性、状态或 app 事件？
- 如观察页面自己的请求：能否关联输入→文件记录→最终确认→该草稿附件？
- 错误是否暂时中断，页面还会自行重试吗？

卡片存在、send 可点击、spinner 消失、固定等待、一次 200 或 PUT 完成不能单独作为成功。READY 指此刻草稿认可附件可用，不是承诺用户未来的发送请求永不失败。

若 W00 没有充分 READY，仍可做输入实验，但该 surface 不通过严格模式。不要为尚未找到的正向信号写复杂轮询。

### W01 同一 adapter 比较两种传输

顺序：Apple Events JS → MV3 extension。都使用真实 File 和实际 input 原生 setter；若有不同入口，单独记录。仅观察 append，不按 Enter、不触发发送、不清空 composer。

主要目标 surface 各路线正常单图检查 3 次，第二 surface 先跑一轮兼容性检查；出现差异即独立登记。3 次用于发现明显不稳定，不用于宣称 99.9%。

| Case | 条件与动作 | 必须记录／判定 |
| --- | --- | --- |
| W01a | 空草稿，一次缩略图点击加 A | 准确目标、正向 READY、只出现一次 |
| W01b | 多语言文字＋既有 B，再加 A | 原文不变，B 保留，仅新增 A；上传中输入不被旧快照覆盖 |
| W01c | 文字有选区；与既有另一图同名 | 不替换选中文本；不认领 generic filename 对应的旧图 |

记录权限提示、安装步骤、传图字节、click→dispatch→ready、大图分段是否可靠、是否需要 MAIN world。两者均通过且 DOM 足够，纯原生可凭更少组件胜出；只有扩展取得完整回执／稳定绑定时，才能写“当前支持范围需要扩展”。

明确拒绝且未产生副作用时，可在干净测试草稿另试输入方法。已分派但结果不确定时，禁止自动 fallback。

## 3. 第二站 关键反例与恢复

只对通过输入的候选做以下用例，不做全部因素的笛卡尔积；同会话复用素材与观察器。

| Case | 最小操作 | 通过条件 |
| --- | --- | --- |
| W02 网络 | 离线前点击；上传中中断；恢复 | 区分终止失败与未决；无错误 READY；恢复不盲重传 |
| W03 并发 | 同图双击；A/B/C 快点；同时手动加另一图 | 未决同图一次输入；顺序稳定；用户新图不被误认领 |
| W04 生命周期 | 输入前切聊天；上传中切聊天；同 URL 新草稿 | 不转投新目标；旧回执不消费新操作；不只认 URL／documentId |
| W05 多目标 | 两窗口／两 profile，放不同草稿轮流前台点击 | 真实前台目标正确；无法唯一确定则保留，不猜 lastFocused |
| W06 恢复 | 传完但 dispatch 前断开；dispatch 后 ACK 前断开；READY 后本地提交前重启 | 区分确定未输入与可能已输入；后者只回查；日志缺失不等于未上传 |
| W07 用户修改 | 上传中移除 A；失败卡仍留草稿；点重生图 | 不错误吞噬；仅处理自身准确关联且终止的失败项；保护原附件 |

12 项用于待用队列和布局压力，不要求把 12 张同时附到一个草稿。页面数量／大小限制若明确拒绝，则记录并保留截图；不能把“十多张待用”解释为绕过目标限制。

### 网页准入

- 正常流程取得 INPUT＋IDENTITY＋READY，不能以全部 UNKNOWN 通过。
- 已测用例中错误目标、损坏原文、丢失旧附件、假 READY、自动发送、盲重传均为零。
- 网络／导航／观察中断可以 UNKNOWN，记录原因与回查结果。
- 只选一个生产 transport；另一个保留研究结论。
- Chat 与 Work 分开判定。Oracle 拒绝 Work 不能被忽略，也不替代当前 Work 实测。

## 4. 第三站 新版 Mac 与 Classic

按实际存在的客户端 surface 独立记录；不先写完整注入器。

### M00 先观察 AX

采集五组 composer-only AX 快照：baseline、刚加入、上传中、ready、真实 error。记录 role／identifier／label／help／value、可写属性、支持的 actions／notifications。缺少某通知只意味着采用有界 subtree 查询，不是失败回执。

先试唯一 UUID 名的私有 PNG fileURL，再单独试 PNG data；TIFF 只在必要时补充。每次一个 pasteboard item，不把 PNG／TIFF 分成两个图，不加路径文本 fallback。

决定性问题：同一个身份明确的附件是否有正向 READY？若没有，记录该版本 strict adapter NOT_ADMITTED；不反复申请 AX 或增加等待。

| Case | 操作 | 通过条件 |
| --- | --- | --- |
| M01 输入 | 非激活点击；AX Paste 菜单动作，不存在才另测定向 CGEvent | 原应用／输入框保持，可继续打字；只新增图；无发送 |
| M02 保留 | 多语言文字、选区、旧附件、同名不同图 | 不覆盖；新图可唯一关联；不靠全文恢复 |
| M03 切换 | Paste 前后切另一个窗口／聊天 | 不猜错；PID 不被当聊天身份；未决保留 |
| M04 网络 | 正常→上传中→中断／终止失败→恢复 | READY 与错误区分；自行重试未终局时不放行新上传 |
| M05 剪贴板 | 首次程序性读取旧内容／Paste；上传中用户再复制合成文字 | 记录隐私提示与拒绝；不把合成 Paste 默认当用户粘贴例外；不覆盖新复制；恢复核对 marker／changeCount |
| M06 恢复 | 双击；dispatch 后探针重启 | 无盲重传；无法回查则 UNKNOWN；不清空草稿 |

如果只能观察人工粘贴，M00 可以完成，M01 仍 NOT_TESTED。INPUT／IDENTITY 通过但 READY 不通过，应写“可受控追加与保守保留，不能满足成功自动吞噬”，不能修改产品要求包装成通过。

官方 MCP 路径只有未来证明无需日常额外打开、host 广告 openai/message＋image 能力、目标绑定与逐图 READY 后再测。缺能力不得调用基础 ui/message 并假定 send:false 生效；当前无需为未补足前提的路径额外安装服务器。

## 5. 第四站 一个小窗口探针

| Case | 操作 | 产出 |
| --- | --- | --- |
| P01 焦点 | 合成文本框／获准空草稿上显示 2、3、12 项，快速移动后立即点图 | 点击前后前台 PID、焦点窗口／控件、下一次普通字符的去向 |
| P02 穿透 | 单透明画布与逐图 panel；点空隙、圆角、阴影、遮罩外及动画边界 | windowNumber 预测＋下层 click counter 实际结果；hitTest(nil) 不能自证 |
| P03 空间 | 桌面、全屏、Space、Stage Manager | 最低有效 level／collection behavior；截图栏、菜单、Dock 可用 |
| P04 显示恢复 | 内外屏混合 scale；拔接、合盖／唤醒 | 面板可见、锚点／比例／清晰度正确；不用保存时鼠标定来源 |
| P05 系统截图 | 裂缝处于捕获区域；⌘⇧3、⌘⇧4、⌘⇧4+Space、⌘⇧5／定时；预览开关分别记录 | 各入口最终文件是否含裂缝／阴影／编号；不预设 sharingType.none 有效 |

不固定 48 pt、54 pt 或某种造型。先验证机制，尺度来自视觉专项。自包含提供支持边界证据，不新增“所有入口绝对排除”承诺。

## 6. 第五站 文件感知与资源

实际系统截图三次，另做连续三张与休眠唤醒。不要直接生成文件冒充系统截图延迟。

- T0：系统捕获完成；
- T1：完整文件可读；
- T2：私有副本完成、持久入队、缩略图可点；
- 另记点击→输入分派→READY。

浮动预览主要影响 T0→T1；watcher、稳定性和解码影响 T1→T2。必须分别报告。

再用受控分段写入的合成文件验证 validator：半图不入队，重复事件不重复收录；内容相同的两次独立截图仍是两项。应用停止后捕获再启动能补扫，同时不收进此前历史图；换源／目录失效只在获准路径恢复。

静置十分钟采样 CPU、footprint、idle wakeups，再做一次唤醒／屏幕变更。未测前不写“零 CPU”或“仅若干 MB”。无持续指针 timer、空闲轮询和持续动画的设计应得到进程采样支持。

## 7. 会话结束只交五份结果

1. **environment.json**：一次环境清单、权限与阻塞范围。
2. **cases.csv**：caseId、surface、版本、transport、表示、INPUT／IDENTITY／READY／RECOVERY、证据路径、缺口；未测写原因。
3. **events.ndjson**：monotonic 时间、operationId、目标本地代号、事件、局部状态、相关 fileId；无认证、私聊或签名 URL。
4. **receipt-profile.json**：真实身份来源、正向 READY、ERROR／UPLOADING、失效条件、适用版本、fixtures；无证据字段为 null。
5. **verdict.md**：胜出 transport、可支持 surfaces、不准入的具体理由、实际延迟、自包含边界、余下验证点。

失败只触发具体修正／复验，不重新做安装检查或无限切换 GUI 工具。环境阻塞时，现有 SOURCE-VERIFIED 与离线证据仍有效，缺失运行测试保持 BLOCKED／NOT_TESTED。

填写格式示例，**不是本轮结果**：

> 在 Chrome 指定版本、Web Chat 指定 profile 中，某路线 INPUT／IDENTITY 已通过，READY 由记录的正向信号与原草稿成员关系联合证明。Work 缺少具体信号。某版 Mac 只有 INPUT，AX 无法区分占位与完成，因此不启用严格 Mac adapter。
