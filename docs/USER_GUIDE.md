# 使用 Riftlet

适用于普通截图入口。正式版 1.0.1 可从[官网](https://riftlet.com/)下载。首次安装、更新和权限设置见[消费者指南](consumer/README.md)。

## 日常使用

1. 沿用 macOS 截图方式，将截图保存为文件。使用截图工具的“选项”选择保存位置；仅复制到剪贴板的截图不会被文件收录器接收。
2. 打开 Chrome 中可编辑的 ChatGPT 聊天，保留要附加的草稿。
3. 单击边缘微图一次。聊天开始接收对应图片后，微图快速收起；可以继续点下一张。正文保留，消息由你发送。

首次安装不会把保存目录中的全部旧文件导入。正常退出后再启动，系统会沿用既有收录记录，不应把历史截图重新附加。

没有可用聊天或页面未接收时，图片会保留并给出原因。结果待核实时不要通过清空数据库、反复重开或恢复旧记录来强行重传；先检查聊天中的附件，参见[排查说明](SUPPORT.md)。

## 初次安装与连接

个人 Beta 使用已经确认来源与版本的 App；不要用未知 CI ZIP 覆盖当前安装。正式外部分发仍需 Developer ID、公证及干净设备验包；现在没有要求用户关闭 Gatekeeper 的安装步骤。

授权按用途进行，不必一次打开所有系统权限：

| 用途 | 何时需要 | 入口与恢复 |
|---|---|---|
| 读取系统保存的截图 | 收录文件时 | Riftlet 的“允许访问截图位置…”选择它显示的实际系统截图目录。此动作不更改 macOS 保存位置，也不授权其他目录作为新来源。系统设置 → 隐私与安全性 → 文件与文件夹中检查对应权限。 |
| 将文件附加到 Chrome | 开始使用聊天附加时 | 打开 Chrome，再使用 Riftlet 连接/授权动作。被拒绝后到系统设置 → 隐私与安全性 → 自动化，允许 Riftlet 控制 Google Chrome；返回后重新检查。 |
| Chrome 页面脚本 | 聊天附加时 | Chrome 菜单“显示 → 开发者 → 允许来自 Apple 事件的 JavaScript”。这与系统自动化授权是两个独立条件；Riftlet 不代改浏览器选项。 |
| 内置截图 | 首次明确使用内置截图时 | 按 macOS 提示授予所需屏幕录制访问。系统设置 → 隐私与安全性 → 屏幕与系统音频录制（名称因系统版本略异）。只读取系统已保存的截图不需要因此预先请求屏幕录制。 |

Apple 官方说明：[文件与文件夹](https://support.apple.com/guide/mac-help/mchld5a35146/mac)、[屏幕录制](https://support.apple.com/guide/mac-help/mchld6aa7d23/mac)。Chrome 官方说明：[Apple Events JavaScript](https://www.chromium.org/developers/applescript/)。上述说明于 2026-11-06 核对；系统实际授权仍需本人操作。

授权失效时检查当前 App 的来源、安装位置和签名身份。重新安装或更换签名可能影响系统认可的权限，不能保证自动继承；不要重置全部 TCC 或删除浏览器 profile 来解决单项权限问题。

## 停止、隐藏与清空

- 暂停收录：停止继续收录系统新截图；已有微图与历史保留。
- 隐藏裂缝：隐藏边缘微图；收录是否运行由暂停状态决定。
- 关闭内置截图入口：停止该入口；不等于暂停系统截图收录。
- 清空可见队列：收起当前微图，保留原图、私有副本、历史和已有聊天附件。它不是释放磁盘空间，也不承诺批量撤销。

停止操作可能已在当前运行生效，而偏好未成功保存。看到保存失败时，应同时理解当前状态和“重启后未确认”，不能认为已停止就一定保存成功。修正版设置设计按域表达此区别；新六页 UI 尚未安装。

## 更新和卸载

1.0.1 默认每天检查更新。右键点菜单栏图标，选「检查更新…」查看新版并决定是否安装。从 1.0.0 首次升级或手动安装时，正常退出、保留旧 App 和完整数据备份，检查新包版本、来源、签名及数据兼容性。不要在运行中覆盖 App。失败时先停止新版本，再按[发行与回退说明](RELEASE_ENGINEERING.md)处理；新版本已迁移的数据不能任意交给旧版。

退出并移走 App 会停止运行，通常不会自动删除 Application Support 中的历史、媒体、配置、反馈或系统截图。需要保留使用记录时只移走 App。永久数据清除的产品策略尚未决定；不要用不明清理工具删除数据库或媒体目录。详见[数据说明](PRIVACY_AND_DATA.md)。
