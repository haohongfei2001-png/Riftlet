# 外部 Beta 验收准备

本轮不招募、不邀请用户反复测试、不发布新包。个人 Beta 既有五图及最终冷双图证据继续有效；下面是正式对外前需要具备的环境和记录方式，不把未执行项目标记通过。

## 发布候选前提

同一源码、版本/build、实际架构、完整ZIP摘要、签名团队、公证与staple、干净设备Gatekeeper；有可验证旧包与数据备份，明确数据库兼容和回退方式。候选必须先通过完整自动化与独立源码审查。新UI需最终视觉批准，不能用这份计划自动合并视觉方案。

## 有限验收矩阵

| 价值 | 环境与一次有结果的操作 | 记录 |
|---|---|---|
| 陌生用户首次成功 | 干净安装，按需授权，正常截图→自己的可编辑聊天→单击；下一张可连续附加 | 文件收录、首次接收/START/吞噬一致；正文保留、无错投/重复/自动发送 |
| 更新不丢数据 | 已有历史/设置的隔离用户目录，正常退出→验证新包→更新→启动，失败则在备份副本演练回退 | App identity、迁移前后计数/哈希、UNKNOWN不变、旧包兼容结论 |
| 正常授权恢复 | 分别拒绝/恢复目录、Chrome自动化、Chrome脚本；只在用内置截图时处理录屏授权 | 原因提示准确，恢复无需重装或重置全部权限 |
| 使用不中断 | 用户原有窗口/Spaces、多屏断开重接、实际睡眠唤醒与Chrome会话重启 | 是否错投/错误吞噬、有效屏幕回退且偏好保留、冷窗口前置是否可接受 |
| 可操作与可读 | 受支持系统/架构，键盘、VoiceOver、中文输入法、系统减少动态和高对比 | first responder/草稿不丢失、说明不矛盾、原生popover/sheet层级 |
| 真实异常 | 正常使用中首次出现的有结果故障 | 分析既有记录，只有缺关键事实时才安排最小复验；不要求重复五图实验 |

部署目标macOS13+与实际支持承诺分开。优先主力当前Apple silicon系统，其次计划支持的最旧系统与Intel；最终对外支持矩阵由发行负责人决定，不把CI编译当实机兼容。

## 最小非敏感指标

默认不新增遥测。使用已有可选诊断或本地受控结果：版本/build/架构、明确错误类别、功能是否完成、操作耗时分段、是否需要人工恢复。统计需带样本数、环境和未完成数量，不能只报告成功样本。

不收集截图、聊天正文、URL/标题、光标文本、文件路径、数据库或浏览器身份；不把内部operation/asset标识自动发往公开服务。需要关联单次故障时，本地记录由用户自行控制，提交前按明确范围去隐私。反馈只依据用户发送意图，诊断可预览且新草稿默认关闭。

## 留待人工决定

批准候选外观、保留/永久删除策略、实际公开支持平台、Apple开发者凭据与签名身份、公开下载及反馈隐私声明。缺少这些决定时工程工具、离线测试和文档仍可完成；不能以此宣称产品已公开就绪。
