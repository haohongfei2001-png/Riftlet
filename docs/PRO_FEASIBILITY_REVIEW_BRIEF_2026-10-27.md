## 0. 身份与目标

担任独立首席 macOS 原生架构师、浏览器适配工程师、屏幕捕获平台专家及产品可靠性审查人。

审查目的不是重新做一次 Riftlet 通用架构研究，也不是讨论是否应该保留“一次点击”或“使用原生 macOS 截图”，而是针对两个现实中的产品缺口提出**真实可行、有证据、代价可控的技术方案**，并给出直接可落地的验收规格：

- **A：当前 ChatGPT 对话有可用发言框，用户没有把输入光标放进发言框，能否直接点击 Riftlet 一次附加截图？** 这是已确定的产品需求。
- **B：用户使用已有的 macOS 系统截图入口，如何尽可能避免截入 Riftlet 自己的裂缝/缩略图？** 这是需技术实证的困难目标，不是预先假定所有场景可以完全实现。

次要但关联的边界：**C 无效目标点击的轻量反馈**、**D 自动归档与鼠标/队列正在交互时的冲突**；只需评审可行的最小实现/验收，不扩大到产品重设计。

## 2. A｜未聚焦发言框的一击附加：独立裁决

必须区分以下状态：
1. Chrome/ChatGPT 是前台，正确标签和草稿在前台，发言框存在，但光标在聊天正文或页面空白处。
2. 同一前台页面，用户刚刚点击过侧栏、其他控件或已有回答；检查是否发生业务草稿变化。
3. 浏览器地址栏获得焦点、弹窗遮住页面、多个编辑器/发言框、ChatGPT 正处于 Work/其他不支持 surface。
4. Riftlet 原生非激活微缩图获得物理 mouseDown/mouseUp；冷首击、新页面未预 arm、Apple Events 延迟和点击前后目标切换。
5. 新版 ChatGPT macOS 客户端及 Classic，是否必须聚焦 AX 编辑器，是否可安全定向 Paste、通过原生附件动作附加而不丢选区/改写文本。

审查现有 Web JS `document.hasFocus()`（页面/窗口焦点）与 editor `document.activeElement`（输入框焦点）的本质差别；`outsideInteraction` 使 input authority 撤销时的重新预绑定/瞬时校验要求； File/DataTransfer/input setter+change 是否无需人为聚焦 editor。不得以通用浏览器猜测取代实测源码。讨论 AX/Pasteboard 的限制时，禁止提议选择正文后盲目 Ctrl/Cmd+V 或覆盖全文。

交付：
- **按真实目标类型分别给出可行 / 条件可行 / 不可行或未证明**；
- 最小必要源码改动位置、所需权限、回退策略、风险、性能影响；
- 正反例测试矩阵与可证明的冷首击验收条件；
- 优先复用已有绑定/验证路径；不要建设第二套通用鼠标/键盘模拟框架。

## 3. B｜现有 macOS 系统截图排除 Riftlet 自身：独立证伪

不能混淆“调用我自己的 ScreenCaptureKit 时设置排除过滤器”与“控制 Apple 系统 Screenshot.app / Cmd-Shift-3/4/5 截图结果”。

必须核查 Apple 当前官方文档及与 macOS 真实版本相关的行为，特别是：
- `NSWindow.SharingType.none` 的当前含义及是否已经不再用于截图保护；
- `ScreenCaptureKit.SCContentFilter` 排除应用/窗口的生效对象究竟是谁；
- macOS 系统快捷键、区域/窗口/全屏、Screenshot.app 截图工具栏、浮动预览、计时、多显示器和不同 Space/全屏下的区别；
- 使用公开事件监听/截图发生前暂时隐藏原生 NSPanel 是否真正能提前得知并在像素捕获前隐藏，竞态、事件 tap/TCC/焦点影响、键盘布局/定制快捷键、鼠标选择拖框、用户时间成本；
- 若无法可靠排除，仍保留用户系统截图习惯时有哪些低干扰退路（用户主动隐藏/暂停、特定入口差异化支持/清楚告知等），不能擅自替换全局系统截图服务或做不可信的像素后修补。

**现有真机证据：** Round 2 观察到真实系统截图含裂缝缩略图；但当时真实 App/辅助程序可能同时运行，不能无证据归因。明确如何隔离来源、复现及记录设备与 OS。

交付三层结论：
1. 已有一手 API/系统机制证明能够做什么；
2. 哪些方案必须靠真机验证，是否有不可避免的竞态或权限成本；
3. 公开发行时可否承诺“完全不进入系统截图”，如果不能，应使用什么可信的产品边界与最小替代方案。

不允许以未经验证的私有 WindowServer/CGS 接口作为发布依赖；避免增加截图引擎、必须新快捷键或高权限作为默认前提。如果探索某条路线成本过高或成功率不可验，应明确**拒绝该路线**。

## 4. C/D｜两项轻量体验机制

**C：** 当前无有效发言框/无附件输入能力/权限不足时，截图不消失不吞噬；提供不抢焦点、不弹成功提示的短暂按压→恢复反馈，以及按需 tooltip/菜单原因。分清由本地确定的无效输入与提交后的 UNKNOWN。无新日常操作。

**D：** 自动归档到期时，hover/按下/连续点击/正在位移动画/排队上传中的截图不能突然从指针下消失。明确可持续检测条件、不轮询/不过度耗电、在鼠标离开后延迟归档、重启/睡眠唤醒/时钟变化边界。无需指定一个未经批准的归档小时数。

## 5. 最终交付格式及工程边界

以独立技术裁决报告形式给出：
1. **执行摘要**：A/B/C/D 一项一项明确结论、可信度、首版是否阻塞、退路及代价。
2. **事实证据表**：实际检查过的仓库提交/行号、Apple 官方来源、真实 Mac 用例、PASS/FAIL/NOT_TESTED，不混用模拟与真机证据。
3. **两项高风险方案的比较与明确选择**：A 至少一个最小可行路径，B 要么可执行路径与实测计划，要么说明没有可验证的系统级排除能力并提供实用退路。
4. **最小实施规格**：分模块建议、状态/事件边界、兼容与权限、真机接受/拒绝标准，优先复用已有 W2/N1/M1。
5. **新增真机验收矩阵**：与现有测试去重；物理 first click、未聚焦发言框、现有草稿内容保留、自己被截图拍入来源隔离、截图延迟和多显示器。
6. **发行前剩余风险排序**：列出不可省略的 P0 和可推迟的 P1；不产生大量无关功能和新基础设施。

**禁止：** 不修改 GitHub 代码/决策/PR，不合并、不部署、不启用生产适配器，不改变系统快捷键/截图目录或私有权限，不购买服务，不发送 ChatGPT 消息，不删除真实数据。只做研究；如具有经过授权的真机环境且任务授权支持可控实验，可以限定使用合成测试图并记录事实，不作未经批准的配置变更。当前缺少可操作真机时直接给出阅读证据与清晰的 NOT_TESTED，不编造 PASS。

最终以“这个产品现在最小改动应该怎么实现、哪些不能保证、如何稳定交付”作明确裁决，不把问题留给用户自行选择技术栈。
