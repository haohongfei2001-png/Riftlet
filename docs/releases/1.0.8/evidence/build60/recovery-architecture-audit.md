# Explicit UNKNOWN recovery in build 60

The frozen product source is `711cee3a1c7033ce4925082a83099b00da7087c6`. Three independently sealed build 59 Edge databases contained real original system PNGs, a returned input invocation, an `inputTriggered` receipt, a durable `unknown` operation, and zero original STARTs. The three source fingerprints, PNG digests and six new before/after backup fingerprints are in [the accompanying JSON](recovery-architecture-audit.json).

For each archive the audit copied the database and matching PNG to a new private directory. One Core process opened the copy, staged an explicit selection and cancelled its prepared successor before input. Another process opened the persisted state, ran startup recovery, staged a new explicit selection, delivered one controlled append and recorded an attachmentAccepted START. Five families of original-writer callbacks were applied after cancellation and again after the third attempt. The original owner and invocation IDs were taken from the archival dispatch checkpoint. The verifier compared the SQLite backups produced immediately before and after the final selection, retaining the input-free second operation as part of the before baseline. All three before/after pairs passed. Original archives were reopened read-only and rehashed. This evidence covers the production Core path and SQLite with a controlled browser adapter. It does not provide a real-site G4-C or a signed-App mouse event.

## Reviewed components

- [AcceptedSelection](../../../../../Sources/RiftletCore/AcceptedSelection.swift) serializes cancellation with a one-use SQLite dispatch authorization.
- [QueueStore](../../../../../Sources/RiftletCore/QueueStore.swift) and [SQLiteDatabase](../../../../../Sources/RiftletCore/SQLiteDatabase.swift) atomically append the predecessor association, preserve the retired source and restore it as active on input-free cancellation.
- [TransferCoordinator](../../../../../Sources/RiftletCore/TransferCoordinator.swift) requires explicit current-click authorization, pins the predecessor, resolves the complete original target and runs a direct recovery check before staging. The [page resource](../../../../../Sources/RiftletAdapters/Resources/chatgpt-web-20261027.js) repeats it at the setter boundary.
- [HistoryPresentation](../../../../../Sources/RiftletUI/HistoryPresentation.swift) retains uncertain-state semantics and rejects handled or missing images. [RiftHistoryController](../../../../../Sources/RiftletUI/RiftHistoryController.swift) rechecks the selected operation before and after displaying its sheet.
- [RiftPanelController](../../../../../Sources/RiftletUI/RiftPanelController.swift) ties the press to the real original row window and visibility revision. [RiftletMain](../../../../../Sources/RiftletApp/RiftletMain.swift) consumes the staged operation/revision when dispatching the later click.
- [The offline verifier](../../../../../Tests/PreClickLease/g4/verify_unknown_recovery.py) checks source bytes, full targets, distinct operation/invocation, one new START and predecessor relationship, and unchanged historical rows. All four verifier test methods passed, including tampered backup, conflicting target, reused invocation and replaced PNG cases.

Run the [archive audit](../../../../../Tests/PreClickLease/g4/audit/run_archives.py) with the three private database/PNG pairs. The separate headless check uses `RIFTLET_NATIVE_CASE=owned-original-failure-card RIFTLET_REQUIRE_CHROME=1 node --test Tests/WebPageProgram/chrome-input-resource.test.cjs`. The targeted invocation passed 15/15 with zero skips, including its process cleanup controls. Both adapter-family branches ran in actual headless Google Chrome against a local test application, each with 51 native setters, 51 changes, zero sends/submits, 23 rejected error-card shapes, four retired cases and 14 recovery scenarios. The native Edge binary and ChatGPT's website were outside this controlled run. No product change was required by these results.
