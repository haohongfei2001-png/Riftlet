# Original-document delivery decision

## Product path in build 54

`RiftletMain` calls `WebAttachmentAdapter.targetForClick()` during an ordinary screenshot press. `ChromeAppleEventsExecutor` reads the frontmost browser, verifies its kernel birth and obtains the active native window/tab. It addresses that PID and tab using Apple Events, and enqueues a fresh click UUID. The short `pinTarget` program runs in the browser, captures the actual editor/form, document root and Navigation API entry, and installs lifecycle listeners. Edge also verifies the relationship between its Apple Event and page execution worlds. The asynchronous reply must match the click, native destination and original witness. The returned `TargetLease` carries document, composer, draft and click identities. The `BrowserHost` abstraction under development in #122 does not run in this 1.0.7 binary. [Frozen native entry](https://github.com/haohongfei2001-png/Riftlet/blob/95d8cf80a46def6d15076e8e22872fec63f4ce3f/Sources/RiftletAdapters/ChromeAppleEventsExecutor.swift) · [Click witness](https://github.com/haohongfei2001-png/Riftlet/blob/95d8cf80a46def6d15076e8e22872fec63f4ce3f/Sources/RiftletAdapters/ChromeClickDocumentWitness.swift)

`TransferCoordinator` persists independent dispatch intent in `QueueStore` before entering file input. Chunks, commit and read receipts carry the operation and original target; writes also bind the invocation. A document-local relay processes the command. Only the current operation on the original page can consume it. The setter receives the chosen `HTMLInputElement` object and a single screenshot `FileList` in the renderer. Synchronous site handlers may run between `input` and `change`. After possible input, an uncertain reply permits only observation. Previously recorded operations remain readable. There is no product keyboard step between the native receiver and the file setter. [Coordinator](https://github.com/haohongfei2001-png/Riftlet/blob/95d8cf80a46def6d15076e8e22872fec63f4ce3f/Sources/RiftletCore/TransferCoordinator.swift) · [Baseline page resource](https://github.com/haohongfei2001-png/Riftlet/blob/95d8cf80a46def6d15076e8e22872fec63f4ce3f/Sources/RiftletAdapters/Resources/chatgpt-web-20261027.js)

## Public mechanisms and their authority

| Mechanism | What the actual side effect addresses | Lifecycle, setup and decision |
| --- | --- | --- |
| CGEvent / Accessibility keyboard | A process, an application AX object, or the currently active application. Keyboard focus determines the final control. The SDK explicitly excludes passing an editor AX object to `AXUIElementPostKeyboardEvent`. | AX or event posting permission cannot make an old key document-bound. Returning focus can restore the apparent precondition. No production keyboard fallback. [Apple AX](https://developer.apple.com/documentation/applicationservices/1462057-axuielementpostkeyboardevent) · [CoreGraphics](https://developer.apple.com/documentation/coregraphics/cgevent/posttopid(_:)) |
| AX attribute or action on an element | An AX element may expose settable selected text or a value. Chromium implements editing actions including replace-selected-text. Support and edit semantics depend on the receiver. | Distinct from focusing, then sending a key. No documented operation ties that write to a Riftlet click, navigation generation or continuously active draft. `cannotComplete` leaves delivery uncertain. Changing the whole value is unsuitable for a live draft. [Apple attribute write](https://developer.apple.com/documentation/applicationservices/1460434-axuielementsetattributevalue) · [Chromium Cocoa editing actions](https://github.com/chromium/chromium/blob/main/ui/accessibility/platform/ax_platform_node_cocoa.mm) |
| Apple Events / browser scripting | A native tab specifier; Chromium resolves its primary main frame when the command executes. A subsequent command can reach a replacement at the same URL. | Retain the document-local click/operation capability inside the addressed page. A replaced document has no corresponding operation. Needs the browser's JavaScript-from-Apple-Events setting and macOS Automation permission. Chrome and Edge share native routing; Edge has a separate execution-world check. Safari's `do JavaScript ... in ...` also names a document/tab at the automation layer. A cold Safari tab index has already been observed to retarget. [Chromium implementation](https://github.com/chromium/chromium/blob/main/chrome/browser/ui/cocoa/applescript/tab_applescript.mm) · [Prior Safari evidence](https://github.com/haohongfei2001-png/Riftlet/tree/a9a1c03c9bd0b0d834cc6f9a4f99492cbfa12db2/engineering/preintegration/issue-120/hosts) |
| Official QA browser handle / locator | A handle can continue to address a tab when inactive. A dynamic locator resolves against the document at use. Indexed AX keys attempt focus before delivery. | A key sent through one Edge handle entered the replacement QA document. All five tab identity domains remained consistent. A provider handle or a fresh focus check cannot close this gap. [Measured A/B result](https://github.com/haohongfei2001-png/Riftlet/blob/a9a1c03c9bd0b0d834cc6f9a4f99492cbfa12db2/engineering/preintegration/issue-120/build54-target-safety/official-control.json) |
| Native host plus browser-side receiver | Native process/window/tab select the transport. A revocable document-local receiver captures the exact node, consumes each invocation once, and calls a fixed method with that object as its receiver. No later recipient lookup. | Selected for attachments. Preserve original editor/form pin and behavior without editor focus at click. Retire on another editable target, document/window lifetime changes or removal of a frozen owning ancestor. File setter, input and change each use the original receiver; site reentrancy between stages requires separate checks. Once the setter may have run, retain UNKNOWN and original bytes. |
| Browser extension with document addressing | Chromium `scripting.executeScript` can target `tabId` and `documentIds` in a chosen world. Safari supports document IDs in Web Extensions from 18.4. Native Messaging transports extension messages; it supplies no document identity of its own. | A stronger browser-level starting point for a future product. Extension installation, site grants, native-host registration, per-browser distribution and support would be required. A cached document retains its ID across BFCache, and a rebuilt editor can share both the tab and document. Lifecycle retirement and an exact element receiver remain necessary. No extension or new site permission is added in this candidate. [Chrome scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting#type-InjectionTarget) · [Document lifecycle](https://developer.chrome.com/docs/extensions/reference/api/webNavigation#frame_ids) · [Microsoft native messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging) · [WebKit document IDs](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/#reliable-document-identification) |
| Browser file chooser, WebDriver or debugging transport | A chooser acts on a browser-owned file control, and WebDriver can address an element. Neither supplies the original external-click identity or continuous draft ownership by itself. | A chooser adds UI and can outlive the original selection. Enabling remote debugging or setting up a separate automation profile changes installation and user workflow. Keep the single explicit attachment handoff. Avoid a chooser, clipboard, simulated drag or global input fallback. [W3C element send keys](https://www.w3.org/TR/webdriver2/#element-send-keys) |

## Decision and limits

Implement a private, one-use method bound to a particular renderer object. Ownership changes retire it permanently, including a move away and back in one synchronous page handler. A consumed invocation cannot select a replacement node. Keep the product's exact HTTPS origin boundary, original relay and once-only SQLite dispatch. Maintain independent evidence for the browser's real semantic text edit on a self-owned page, OS keyboard events, real file delivery, and signed-app/service acceptance. No production text or send operation is introduced.

The first browser witness occurs after the OS click is observed. The published Apple Event vocabulary contains a tab specifier and script, without a browser-generated document ID sampled atomically alongside the external tray event. The click deadline bounds latency; elapsed time cannot prove that an unseen same-URL replacement or A→B→A did not occur before witness installation. Direct a deterministic test at that interval. A fully established document capability protects subsequent delayed delivery. Any unresolved first-witness or real-key guarantee remains an admission blocker even if every post-witness test succeeds.
