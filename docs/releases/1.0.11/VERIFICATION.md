# Riftlet 1.0.11（66）验收记录

2026-11-25，build 66 的验收状态为 **PARTIAL**。用户仍可从官网和 Sparkle 稳定源取得 1.0.10（65）。1.0.11 的仓库找回修复已合并，实站无目标恢复还有可见失败。[产品 PR #134](https://github.com/haohongfei2001-png/Riftlet/pull/134) · [当前正式发行](https://github.com/haohongfei2001-png/Riftlet/releases/latest)

## 本地仓库找回

在 1.0.10 的隔离 SQLite 库中，点过且没有附加目标的第 1 张截图被 20 张更新截图挤出最近列表。原 PNG 字节仍在，完整仓库能找到该图，重新启动后按钮和底层恢复调用仍拒绝它。当时 21 张截图均没有附加操作。

使用同一批旧数据打开修复版，真实 AppKit 仓库按钮向回调交付了一次正确的截图 UUID。恢复只改变本地可见性，文件输入和新操作均为零。重新主动点选才产生新操作和一次输入。点击尚在处理中、已有历史操作但活动指针为空、缺失或已清理的图片均被拒绝。5 份旧工程档案逐字节保留。[独立源码复核及用例](https://github.com/haohongfei2001-png/Riftlet/pull/134) · [工程入口核销](https://github.com/haohongfei2001-png/Riftlet/issues/91)

## 真实 ChatGPT Temporary Chat

测试使用正式签名 App、独立截图库、普通 Chrome 和 Edge 已登录的专用草稿。图片是 macOS 对专用测试窗口的真实截图。通过软件生成的 AppKit 鼠标事件点选经核验的 Riftlet 行。原窗口、标签、文档、编辑器、文件输入和附件卡分别取证。

| 场景 | Chrome | Edge |
|---|---|---|
| 单张截图 | 一组通过，另一组在写入文件前失败 | 通过 |
| 连续两张，保留正文和旧附件 | 通过 | 通过 |
| 最近历史中主动重新附加 | 通过 | 通过 |
| 无目标点击，再回到草稿从历史点选 | 复现输入前失败 | 复现输入前失败。另一次出现新卡，已记录一次 input/change，逐卡像素及 START 未获证实 |
| 发送、提交和重复输入 | 完整取证的单图及双图／重选场景均为零 | 完整取证的单图及双图／重选场景均为零 |

Chrome 双图及重选在同一个草稿内取得四组匹配结果，包含先置入的附件。每次有效输入均有一次用户点选、一个操作和 invocation、一份 PNG 对应的网页原卡像素及一个最终持久化 START。第二张的 START 晚于网页确认。关闭后的数据库复核确认四份 START，原正文和原卡保留。

两款浏览器的无目标恢复失败均发生在第二次主动点选。原草稿先显示四个禁用文件字段，随后显示四个启用字段。附件入口从折叠变为展开，产品未取得可归属的选择器，因 `pickerNotInvoked` 结束。两组网页输入、发送及表单提交均为零。Edge 的一次记录可确认准备凭据早于字段启用，实际点选晚于启用。该次观察没有记录字段的 DOM 对象身份，尚不能判断启用时是否发生替换。Edge 补验在同一原始草稿中保留原文和已有附件，完成种子、双图和历史重选四次明确点选。每次均有唯一输入、原卡像素与持久化 START，零发送及表单提交。其他未取得原目标或前台切换的运行按各自的停止点记录。两个浏览器都完成了专用窗口清理。最新回执包含逐组分类。[实站结果摘要](https://github.com/haohongfei2001-png/Riftlet/pull/134#issuecomment-7153415408)

## 后续候选 build 67

另一个已登录的 Edge 临时草稿提供了字段变化的独立现场证据。页面年龄从 2493.2 ms 到 2893.7 ms 时，文档、表单、编辑器、附件按钮和四个文件字段均是同一批 DOM 对象。四个字段原位启用，其中只有一个普通文件字段。观察期间未启动 Riftlet，未执行文件输入。这次对象连续性与较早的真实点击失败分别取证。

build 67 在原先已绑定附件按钮的情形下，保留同一表单中一开始就存在且暂时禁用的唯一普通文件字段。用户明确点图且原字段已就绪时，写入前仍要确认当前附件路由唯一选中同一对象。字段被替换、移动或出现歧义时继续使用原按钮的既有规则。无新权限或后台轮询。build 67 的签名包及其实站、安装和实际更新结果独立记录。
