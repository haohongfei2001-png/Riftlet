# Riftlet 1.0.4 最终产品与交互规范

状态：**APPROVED FOR IMPLEMENTATION BY THIS TASK**，不是软件实现验收。日期2026-11-17。基线、证据、范围分别见[BASELINE](BASELINE.md)、[AUDIT](AUDIT.md)、[IMPLEMENTATION_PLAN](IMPLEMENTATION_PLAN.md)。普通设计选择以下文为准；实现者只在发现相互矛盾、原生平台限制或具体安全反例时提出带证据的替代，不把视觉参数重新交给用户决定。

## 1. 产品原则与默认行为

Riftlet帮助用户把刚截的图自然附加到当前Chrome ChatGPT草稿。用户只需了解“截图、点一下、在原草稿继续写”；App自己负责安全收录、队列、归档、恢复和可靠状态。未发生真实匹配START前，不能说“已交给ChatGPT”；任何时候不自动发送消息。

| 项目 | 真正全新档案默认 | 升级/已有档案 |
|---|---|---|
| 桌面形态/数量/位置 | 托盘、每页3张、leftMiddle；按现有可用屏幕选定 | 保留三形态、旧字段缺省microSlit、legacy绝对位置和显示器偏好 |
| 窗口外观 | 跟随系统 | 保留浅/深/系统原选择 |
| 显示桌面截图 | 开启 | 保留已有隐藏；隐藏不停止收录 |
| 内置截图 | 开启，默认窗口；首次实际调用才请求相关屏幕录制许可 | 保留入口关闭、默认方式和三常用键 |
| 闲置归档 | 2分钟；与现有interaction fence/唤醒宽限一致 | 保留关闭和任意有效旧时长，不在升级时量化 |
| 到达动效 | 无 | 保留显式none/magnet；Reduce Motion仅覆盖effective值 |
| 托盘材质/透明度/相机 | 现有system材质；新字段nil按既有palette计算 | 不迁移旧whole-tray tint为body color，不清自定义色 |
| 更新/登录启动 | 每天检查更新；安装由用户；登录启动仍由系统真实状态决定 | 不新增自动安装，不静默注册登录项 |

**全新档案判定：** 只在现有初始化路径能证明没有旧数据库/媒体、首用状态、偏好或备份等任何既有profile证据时，明确写入新默认。丢失或损坏一个JSON、旧JSON缺desktopForm、用户已收录但未完成引导，都不是新用户。解码器现有fallback原样保留。新字段逐key加入原配置owner，其他字节/未来raw值按现有partial patch规则保留；不为默认更换建立第二套配置系统。

## 2. 设置系统

### 2.1 信息架构

采用**四个紧凑顶部工具栏页签：通用、外观、截图、帮助**。不用品牌占位侧栏，不改成可横向滚动的网页卡片，不引入新UI框架。`RiftSettingsCenterController`、`SettingsProductHost`、`SettingsStateModel`继续分别负责AppKit呈现、真实状态聚合、编辑/确认。

| 页签 | 首屏主层，按顺序 | 渐进层/异常条件 |
|---|---|---|
| 通用 | 登录时启动；当前版本+检查更新；每天检查更新 | 登录批准/失败的当前下一步；更新失败时官网下载；构建号与诊断不常驻 |
| 外观 | 显示桌面截图；窗口外观；形态；共享renderer样例；屏幕边缘；托盘背景透明度；相机颜色 | 多屏/断开的显示器选择；风铃排列；“更多”含每页数量/到达动效；旧非默认材质/几何才出现“旧版自定义” |
| 截图 | 截图来源目录末级名+位置动作；内置截图开关及默认方式；闲置后从桌面收起；打开截图仓库 | 目录失效当前修复动作；托盘常用键；折叠“本机存储”；已有非预设归档值；旧暂停用户恢复收录 |
| 帮助 | Chrome连接的当前状态+一个必要动作；重新查看使用说明；反馈 | “诊断”折叠含重新检查本地副本、版本详情、复制必要诊断；无异常不堆检查按钮 |

全量保留/合并/隐藏/移除及源码字段在[SETTINGS_INVENTORY](SETTINGS_INVENTORY.md)。该表为迁移对照，不以页签重排重写旧值。

### 2.2 尺寸和布局

- 默认**设置内容区域640×560pt（顶部页签与正文合计）**，最小600×460pt采用同一口径，系统标题栏另计；窗口可调整，正文有效宽度最多720pt并居中。记忆合法窗口大小，脱离屏幕时安全夹取。
- 左右正文边距24pt；分组间24pt；组标题到第一行12pt；普通行最小44pt，两行解释最小60pt；同组8pt节奏；标签/控件16pt间距，短说明距标题4pt。使用Auto Layout的对齐矩形，阴影不参与几何对齐。
- 工具栏使用图标+文字可访问页签，选中只一个。标题层级不超过页标题/组标题/正文三级；内容自然增长时纵向滚动，不能裁掉底部“更多”或末项按钮。较小窗口允许滚动，不压缩控件字号。
- 常规标签左对齐、开关/选择器尾端对齐；长解释换行，避免解释与控件上下错位。英语、中文及200%辅助放大不截断关键动作；视觉/键盘顺序一致。
- 原生NSButton保持intrinsicContentSize、系统controlSize regular、自然宽度和标准focus；不设统一stretch button宽、不为普通按钮自画投影。小型图标动作的点击热区至少28×28pt，常用行内按钮实际热区至少32pt高；系统开关/选择器可保持其标准尺寸，通过行空间提高可点性。

### 2.3 共享视觉token

| 类别 | 统一规格 |
|---|---|
| 字体 | 系统SF；页标题20pt semibold，分组13pt semibold，正文13pt regular，次要文字12pt；不可缺少信息不低于12pt；日期/容量可用monospaced digits |
| 文本色 | `labelColor` / `secondaryLabelColor` / `tertiaryLabelColor`按真实重要性；不把低对比灰用于必要操作或错误 |
| 背景 | 原生window/control背景与系统material；避免整页浅绿底/成排装饰卡片；强调色仅用于当前选择和必要强调 |
| 强调色 | 保留Riftlet青绿识别色；正文链接、focus与系统选择状态使用语义accent，不强改系统switch颜色 |
| 圆角 | 原生控件交给AppKit；自绘分组/内联反馈8pt、预览外壳12pt；托盘按独立已定比例 |
| 分隔 | 仅在实际组/职责分界使用semantic separator、单物理像素；不要每条解释加横线 |
| 阴影 | 常规设置控件不加自绘shadow；浮窗/托盘只一个明确层级的共享shadow处理；浅深强度分别token化 |
| 焦点/悬停 | 鼠标悬停不抢key window；键盘focus清楚可见且不只靠颜色；disabled仍可辨，tooltip不作为唯一说明 |
| 动画 | 简单状态/颜色过渡100–140ms，折叠160ms ease-out；不得给安全START/归档添加任意等待。Reduce Motion关闭位移、缩放和弹性，保留必要即时反馈 |

复用轻量token、SettingRow/Section/InlineIssue/Disclosure与现有ProductCopy即可。不建立设计系统包管理、通用插件体系、第二份业务状态或自定义全部原生控件。

### 2.4 保存、错误与低频控制

所有可见选项反映owner的effective值。离散选择立即提交；拖动外观滑杆/颜色选择实时内存预览，mouseUp或键盘调整合并后提交，键盘/颜色panel连续变化静止250ms合并一次。关闭设置先flush最后有效意图；有明确失败才显示一处就地短错误与“重试”，正常状态没有“已保存”提示雨。

保存失败撤回临时预览到最后持久化值，同时保留待重试意图；错误不会停止收录、重建库或复位其他域。中文marked text不能在IME组合中提交/截断；隐藏无效字段不阻塞当前形态的合法改变。任何恢复按钮列清其范围，只恢复对应字段，旧非默认几何恢复不得暗中更换屏幕、形态、位置、归档或动效。

每页数量保留用户控制：托盘1–4，其他形态1–10并按实际屏幕容量显示；存储的超有效上限值不在未编辑时强制重写。动效只有无/磁力吸引。三常用键仅托盘且内置入口启用时展开，以三槽图示配置自动/留空/窗口/区域/全屏，保持主默认键在既有位置。旧custom/violetGlass及几何仅在既有非默认时“旧版自定义”出现；可调原合法范围并恢复指定字段，新用户普通入口不提供这些工程数值。

“旧版自定义”的显隐依据**原文件中有效、明确的自定义证据及该字段已知的历史默认**，不能比较整个已解码对象与1.0.4新构造默认来猜。缺outerInset派生14pt、legacy位置或缺形态字段本身均不触发该区；明确保存的非默认outerInset=22pt应可见可编辑。缺键与显式值必须在读取层保持可区分；若显式旧值的默认来源确实无法判明，保守保留其渐进可编辑入口，不猜测清零。显示/隐藏区块本身不写回任何字段，更不把14pt改成6pt。

归档预设1/2/5/10分钟/关闭；已有3.5分钟等合法旧值保留精确选择“自定义：3.5分钟”，直到用户主动选新预设。存储折叠首次打开才后台测量并缓存；显示“占用XX”，不显示“可清理XX”。列表/网格只在仓库工具栏出现，旧视图偏好保留。

## 3. 托盘外观与个性化

### 3.1 几何与动作不可重设计

继续使用`RiftTrayLayout.make`、`RiftTrayMenuState`和现有命中/队列owner。宽度以目标显示器**逻辑宽度1/8**计算，按scale对齐并夹在visibleFrame；归一化基宽246、圆角24、两侧内距7、列间距5、图片槽高80、底部18、行基线115，单行高115/双行212。不引入第三行或固定巨大空壳。

两列、最多四截图。相机作为队列末尾特殊项；展开时三常用键和主默认键在既定一行。**先有一张再展开仍一行；展开后新图进入才向上长第二行；三图展开保留B/C，A按现有displaced/priority状态上移。** 真实资产顺序和UUID不随视觉交换改变。缩略图保持Fit原比例，长/宽图留白属于正确行为；遮挡独立clip且不改原件。

hover仅视觉反馈；mouseDown后的身份reservation、动画中点击安全、滚轮/惯性节流、Escape/点击外部收起、预览、归档和恢复延续现有契约。外观变化不重建传输operation，不变更hit identity revision，不创建第二个可点击托盘，不抢原草稿。

### 3.2 背景透明度

新增可选字段`trayBackgroundTransparency: Double?`，有效`t∈[0,0.75]`。nil/缺字段为恢复默认，保留现有renderer默认：现代玻璃t=.47（wash alpha=.53），legacy t=.32（alpha=.68）。本值是材质wash控制，不宣称跨系统/壁纸的光学透光率相同。

普通界面一行“背景透明度”，两端“更清晰／更通透”，一个恢复该值的小动作。视觉不常驻alpha数字；AX提供当前值和可调整范围。仅**背景材质/底色层**使用`alpha=1−t`；保留原renderer blur策略；窗口alpha固定1，图片、文字、相机、键帽、focus和输入区域不一起变淡。

| 系统状态 | 实际渲染 | 用户值 |
|---|---|---|
| 常规 | 依t和renderer计算背景 | 保存t或nil |
| 减少透明度 | wash alpha=1、blur=0；滑杆暂停并短注系统原因 | 不覆盖t；系统关闭后恢复 |
| 增加对比度 | wash alpha至少.86；边界semantic label 1pt | 不覆盖t |
| 两者开启 | 减少透明度优先；保持高对比边界 | 不覆盖t |

监听系统外观/辅助功能变化后，**静止且无待处理动画的托盘也必须立即失效palette/material/key/rim并重绘**。不可仅调用motionPolicyChanged后等待下一张截图。采用2.4节保存节奏，不按每帧写JSON。

### 3.3 相机实体颜色与层次

新增`trayCameraBodyColor`：nil为“跟随外观”，基色取既有palette.ink；自选为不透明sRGB的8位RGB值，序列化为规范`#RRGGBB`字符串（大小写宽容读取，仅用户编辑时写大写；不接受alpha），**不得复用trayTintHue/Strength**。只对新字段做验证与容错，不改变整份配置格式/未知字段保留规则。

普通控件为“跟随外观”+五个色样+原生NSColorPanel自定义（关闭alpha）。确定色样：紫`#8067C7`、蓝`#367DD9`、青`#278F88`、珊瑚`#C96A58`、石墨`#545B65`。颜色名称/选中标记对AX可读，选中不只靠颜色。用户自选黑、白和高饱和色也合法；不偷偷改色相来补对比。

保留`drawCamera`原28×24 silhouette、凸起取景部、镜头中心(14,13.8)、尺度及光学中心，在原路径内新增**浅浮雕实体**：中性接触阴影→薄下缘→body front→顶部薄亮边→中性镜头环/镜片→小高光。主色只进入body mask；外键帽、底脚、玻璃、其他截图方式图标、图片、镜片保持独立。

固定上左光源。linear sRGB基色C，亮面`C+0.22×(1−C)`、暗缘`.72×C`作为共享推导，转换回sRGB后绘制；镜头不涂成实心同色圆。小尺寸仍能辨认镜头/机身/薄边；不做占满键帽的写实相机。边界与邻接背景目标对比≥3:1，使用独立中性轮廓/镜头保证，保持黑白极值的体积。hover最多轻微提亮实体边缘，pressed沿用按键反馈，不能因换色移动布局。

**旧版整盘色继续生效且保持可编辑；新机身色与其正交。** 切主题、形态、浅深模式不删除用户机身色；nil仍按当前旧palette联动。透明度和机身色分别恢复，禁止“恢复默认”一次清掉其他用户设置。

### 3.4 外框与阴影

不提供边框色/粗细/圆角/阴影四组新设置。普通边线单物理像素（`1/backingScale` pt），用semantic separator与内部弱亮边形成一条清楚轮廓；高对比1pt。保留原圆角比例。外部投影和键帽足边使用不同职责的共享token，**避免系统阴影与自绘阴影重复叠黑**。

以现有原生shadow机制为基准，只保留一个外部投影owner；如需要改为自绘，必须同时关闭等价系统shadow并以实拍比较证明收益。深色系统键帽足边不得形成近白“台座”，将足边亮度改由当前key/material语义推导，匹配紫色态的重量；这来自本轮原生图对照。投影方向可向下，不能把正常下投影当成“偏心”强行移到中心。布局、光学中心与投影包围盒分别验收。

### 3.5 预览与最终视觉证据

外观页约140pt高的样例区域，显示来自bundled synthetic图的三图托盘/当前形态，复用实际appearance resolver及绘制函数；按适合窗口的比例缩放并注明“预览”。旁边/下方紧凑位置示意只负责屏幕边缘和显示器，不用宽壁纸画布承担材质预览。样例不注册input、hotkey、capture或browser capability，不读取私人最新截图。

预览与实际托盘共享当前临时外观，取消/写失败按owner回滚；不以预览结果假称真实AppKit验收。最终提交同一RC、同尺度、同合成素材的实拍：默认、透明最小/最大、五色、黑白、自定义、浅深、复杂背景、辅助功能组合。通过mask比较说明只有目标层变化。设计SVG只说明布局关系，示意紫相机不是nil默认紫色的承诺。

## 4. 首用、权限与功能发现

首用最多两个必要阶段：**接收截图**（系统实际文件夹需要时授权）→**附加到ChatGPT**（只在用户选择启用时逐步处理Chrome自动化/JS菜单条件）。不先请求屏幕录制，不强迫选形态/位置。默认托盘已可用，位置在设置中按需调整。

首屏一句话说明“截图后，点托盘里的图片即可附加到当前ChatGPT草稿”；用简短两步图示，不解释input、owner、START、receipt。能处理系统截图后即可完成本地首张成功；Chrome步骤可选“稍后”，局部使用不被阻断。权限提示描述下一步收益；被拒时显示对应系统设置入口，不能所有权限一起请求。

红关闭、Cmd-W、Esc取消、明确“稍后”统一记录deferred；已授权进度保留，下次普通启动不再自动打断。设置中主动重新查看可再次打开；主动完成才completed。review模式的`hasPresented`特判不能作为普通行为验证。

帮助Chrome区每次只有一个主动作：未运行→打开Chrome；自动化未允许→允许连接/系统设置；JS菜单条件未满足→显示明确可执行菜单路径；条件就绪→检查连接；连接成功→短状态，无常驻重复按钮。探测只读，不自动附加或触发无上下文TCC。普通页面状态变化及时更新，不能把“连接正常”解释成“此图已附加”。

首次收录用原生必要反馈指向真实托盘。没有图时，相机/空态说明提供开始方式；不自动制造演示资产进入用户真实仓库。首次真实附加失败在原位置显示原因/下一步；不弹多重确认，也不把未知结果给“再试一次”。

## 5. 全局语言、仓库与错误反馈

面向用户统一“托盘、截图仓库、从桌面收起、恢复到托盘、已交给ChatGPT、结果待核实”。“归档”作为仓库状态可保留，但不等于删除；避免Queue/START/UNKNOWN/journal/SQLite等内部词进入正常UI。中文和英文同时更新ProductCopy，长英文和实际系统IME另验。

菜单栏继续既有四项结构和顺序；状态仅在实际有用时展示，不为配色/诊断增加菜单项。设置、仓库、首用、反馈弹窗共用字体/间距/语义颜色、自然按钮和错误组件；反馈草稿/发送渠道保持现状，不接入新的共享反馈平台。

仓库toolbar保留搜索、状态筛选、日期范围、列表/网格；搜索针对**全库元数据**，先query/filter再分页，每页上限200，按捕获时间+稳定ID排序。搜索文件名/编号/日期等已有元数据，不做OCR。默认日期“全部”，常用“今天/最近7天”，自定日期渐进展开，不增加常驻复杂筛选面板。查询变化取消/丢弃旧结果，保留稳定选中ID和滚动锚点；新图到来不将手下条目替换，可显示轻量“有新截图”刷新动作。

恢复只能沿用Core合法资格；START、缺媒体、输入不明不能被“恢复到托盘”赋予新传输权。对用户明确展示状态与唯一必要动作：输入前确定失败→可重试；匹配START→已交给ChatGPT；未知→查看原对话/保留记录；缺副本→重新检查；读取失败→短错误+重试，不能显示空库掩盖错误。

错误出现在发起操作的窗口/条目附近，不只藏status tooltip；必要AX宣告一次，不在每次refresh重复播报。正常成功无额外弹窗/通知。开发细节可复制到诊断但不能含聊天文本、个人图片、tokens或全量数据库。

## 6. 架构边界与升级

继续AppKit和现有模块；渲染纯函数、偏好模型与输入/持久化owner分离。设置组件可共享，业务意图不可共享成全能巨型view model。`RiftletMain`集成、QueueStore协议、CI、refs与准入由同一集成负责人掌握，并行分支不得互相覆盖。

升级新字段只做向后兼容读取与局部保存；保留未知值、媒体UUID/hash、journal/SQLite、folder bookmark、登录状态、历史视图、反馈草稿和原单实例锁。UI精修不要求数据库破坏性迁移。全库查询若需要索引，使用可重复、事务化的增量索引迁移并测中断；不能重建数据库。

性能预算、真实原生场景和RC验证以[ACCEPTANCE](ACCEPTANCE.md)为最终门。工程发现新问题时先在对应已有Issue补证据、优先级和最小修复，不自由加入新的设置、目标平台或传输方式。
