# Riftlet 1.0.6 候选验收

**暂缓扩大推广。** 以下按同一最终签名候选 1.0.6（36）逐项判定。已公开版本为 1.0.5（31）。

## 发行基线与候选

PR #114 已合并至主线 `9fd8ad15fca043915069904113e5fb67d82b4948`。实际跟随官网取得的公开 v1.0.5 DMG 为 12,686,160 字节，SHA-256 为 `99276347932e231adf743664a54cfc782d8e345d89221587d54b7299a5c9f315`，签名 stable feed 指向同一资产。正式源码采用 B/G/H 准入及五项远端检查。

候选 build 36 产品提交为 `4ed6cbede7260fb857d98bc2a23ef9240870c32e`。DMG 为 13,281,863 字节，SHA-256 为 `9481d9afa784f7bcc723b7888eb7dcbf16f9860ace64e6765adb2b29f02dd727`。App 与 DMG 均已通过 Apple 公证、装订及 Gatekeeper。本地 Swift 应用编译通过；实际运行四组生产页面程序回归 201/201，发行脚本使用真实 Sparkle 工具及临时签名材料，11 项均通过。真实网页与原生 App 的结果见下表。

## V2 真实异常的归属

| 验收格 | 36 实测 |
| --- | --- |
| 明确预输入拒绝 | **PASS**。在测试窗口的空白页单击正常截图，原生记录 invalidTarget。图片仍 pending/visible，operation/START 保持 11/11。 |
| 进入 UNKNOWN、按需核对和明确再次附加 | **PASS**。独立 ChatGPT 测试标签离线时点图，仓库显示“结果待核实”。只读检查前后 operation/START 都是 12/11。“重新附加”显示重复风险，确认后仍为 12/11。恢复该标签正常网络，随后一次自然单击才创建同一 asset 的 attempt 2，变为 13/12。旧 attempt 1、UNKNOWN、原因及本地已处理标记都在，未自动发送。 |
| 真实服务明确失败 | **PASS（原尝试无 START）**。真实原草稿随后在原附件卡上显示“上传未成功”，卡上的文件名与旧 operation 匹配；它与新授权后正常显示的同图、此前附件同时可见。 |
| 已有 START 的同一卡随后明确失败并在仓库找回 | 受控原卡回归通过。真实服务上须同时看到该 operation 先取得 START、该附件随后明确报错，以及仓库对应动作。前一格的红色卡片没有先获 START，不计入本格。 |
| App 重启、预算用尽及原页关闭 | **部分实测**。已登录草稿的 2.6 MB 测试图一度显示灰色卡。按原身份只读继续观察到迟到的 START。保留 Chrome、退出重开 Riftlet，再核对时 11 个 operation 和 11 份 START 均相同。另在隔离 Mac 上验证原页仍存活、旧观察已退休以及真正关闭标签三种状态。临时无权后恢复、Chrome 进程 ID 复用及不同 profile 抗混淆另有受控覆盖，未穷举真实 profile 与进程复用。 |
