# Riftlet 1.0.6 候选验收

**当前暂缓扩大推广。** 安装候选是 **1.0.6（38）**，产品提交 `7e44fd3040af32dc8e53bffac5256ac3cc992767`。公开 Release、官网下载与签名稳定清单仍提供 1.0.5（31）。

## 安装包与变更

最终 DMG 为 13,298,749 字节，SHA-256 为 `14085326e9ed36dde6a370f36e9cfd1a65ae688f37159fc2a67527d1fa406b28`。App 可执行文件 SHA-256 为 `47a5a203719cec88ca76e4e27eb6cbaa7805ba46b673919aaab5ef367119851a`。arm64 / x86_64、Developer ID、App 与 DMG 的 Apple 公证、装订及 Gatekeeper 均通过。声明最低系统为 macOS 13.0。[发行回执](evidence/package-build38.json)

基线为 PR #114 的主线合并 `9fd8ad15fca043915069904113e5fb67d82b4948`。独立核验过公开 1.0.5 DMG 的 12,686,160 字节、SHA-256 `99276347932e231adf743664a54cfc782d8e345d89221587d54b7299a5c9f315`，下载按钮、Release 和签名 feed 与其一致。[实际官网下载及签名核验](evidence/public-v1.0.5.json)

36 的 Intel 原生故障测试发现，持久化输入意图后资产 JSON 损坏时，保存 UNKNOWN 的保护逻辑重复解码坏行。37 在原事务内以资产与活动操作 ID 核实归属。原夹具修前能重现，修后 A 的 UNKNOWN / invocation / 零输入均保存，B 独立成功。重启回归现验证恰好一次原 invocation 的只读检查。装饰窗测试分开验证同步所有权和建窗超时回退，发行 App 沿用系统 Core Animation 时钟。故障详情可见[36 的 Intel 正式作业](https://github.com/haohongfei2001-png/Riftlet/actions/runs/44316646141/job/134844416984)。

37 实机发现，原 Chrome 进程退出后，仓库复查误提示开启自动化权限。38 将接收端失效和授权被拒分别处理。

## 同一候选验收

**V1 · 真实草稿。** 已登录 Chrome 的同一份未发送临时草稿先后出现八张不同的测试图，顺序、文字与选区均保留。冷首击、暖首击及三组双图各自只创建一次操作和一份原卡 START。三对鼠标按下间隔为 611.1、769.8、586.1 ms。点击至观察到收起的上界为冷 2.030 秒、暖 2.871 秒，中位 2.308 秒，p95 及最大均 2.871 秒。八次样本只描述本次运行。切到另一标签后，仓库能精准返回原草稿；空白页上点击不增加输入。[逐图测量](evidence/v1-host-build38.json)

**V2 · 异常处置，部分通过。** 登录测试草稿的第 9 张图在离线时显示“上传未成功”，原操作保留 UNKNOWN、无 START。用户在仓库主动核对、确认可能重复，两步结束时仍为 9 个操作、8 份 START。恢复联网后，下一次自然点击才创建同一图片的 attempt 2 与第 9 份 START，草稿同屏显示原失败卡和新图片。仓库的取消、主动收起和“已处理”也在普通 App 上核对。原进程已退出时，38 正确提示“原附件现已无法核实”，并提供本地处置入口。

另一张较大 PNG 经限速 95.25 秒获得自己的 START，8.74 秒内确认该测试标签已离线，此时它自己的缩略图已经出现。保留原 Chrome，正常重启 Riftlet 后按原身份重查，11 个操作和 10 份 START 保持不变。**同一原卡已有正面 START 后再出现真实失败的恢复路径仍未触发（NOT_RUN）**。受控测试覆盖该状态转换。真实页面已验证用户主动再次附加，无需服务端终止证明，Riftlet 不会自动重试 UNKNOWN。

**V3 · 资料治理。** 隔离 Mac 的普通管理窗列出 24 份可移出的私有副本，标明其中 6 份没有已核实的外部原件。实际移至系统废纸篓的集合含 4 张曾在真实 ChatGPT 取得 START 的图。旧 UNKNOWN 和两条预输入失败仍可查看。正常退出、重启再找回后，28 张图的身份及散列、8 个操作和 5 份 START 与原库一致。[资料核对](evidence/guest-a-build38.json)

**V5 · 用户升级。** 在隔离签名清单中，已公开 1.0.5（31）和同营销版 1.0.6（35）均通过 Sparkle 正常发现更新、安装并重启，运行中的可执行文件与正式 38 的散列相符。31 的 19 张旧图、48 个文件以及 35 的 28 张旧图、57 个文件均保留；旧操作、START、目录书签、偏好与反馈草稿通过核对。31 的 9 项新增收录逐一匹配其已有原件。真实 macOS 13.0、物理 Intel 和多物理显示器均为 NOT_RUN。[升级前后对照](evidence/v5-upgrade-build38.json)

签名包两个架构的受控自检、201 项生产网页程序回归、11 项真实 Sparkle 工具回归通过。独立编译的 Core/Capture 原生故障夹具验证普通 START、无 START 的 UNKNOWN、在途、错误、唯一副本、T1/T2/T3 和三个导入中断点。系统废纸篓与真实浏览器结果单列。[原生故障回归](evidence/v3-source-build38.json)

本次 Release 组件使用 1,000 个有原件与私有副本的 1024×768 PNG，首屏摘要 13.75 ms，完整校验与并发工作 1.96 秒，20 张新图收录的 p50/p95 23.17/25.81 ms。[千图组件基准](evidence/v6-source-build38.json)

先前构建的结果分别保留原身份。[37 登录草稿](evidence/v1-host-build37.json) · [37 升级](evidence/v5-upgrade-build37.json) · [36 验收报告](https://github.com/haohongfei2001-png/Riftlet/blob/58e61278f5f658cd9eaed53460c36461bab82f4c/docs/releases/1.0.6/RC_REPORT.md)
