# Riftlet 1.0.6（42）候选验收

**推广结论：暂缓扩大推广。** 42 已修复可重现的漏接收与误接收。真实草稿完成正常附加及“用户可见异常→核对→明确授权再附加”的人工闭环。对于先取得正面 START、收起缩略图、原卡随后明确失败并由 App 找回的顺序，受控 Chrome 已验证，本次真实 ChatGPT 草稿仍未出现。公开入口维持 1.0.5（31），PR 保持开放。

产品提交为 `3ab118d590c911a52e4110094f78ae1f480927f2`。开发基线 `9fd8ad15fca043915069904113e5fb67d82b4948` 为 PR #114 合并后的 main。[Issue #115](https://github.com/haohongfei2001-png/Riftlet/issues/115) · [build 40 的原始报告](https://github.com/haohongfei2001-png/Riftlet/blob/f87add807d666434fc14e778496d646b9465899d/docs/releases/1.0.6/RC_REPORT.md) · [build 41 的原始报告](https://github.com/haohongfei2001-png/Riftlet/blob/2c7326316c04ab692154c3b2976f5c798de15e21/docs/releases/1.0.6/RC_REPORT.md)

## 本轮关闭的两个缺陷

- **漏掉接收。** 在受控真实 Chrome 中，本次原图预览出现 20 ms 后就被同卡错误替换，build 40 可能在两次原生读取之间漏掉它。42 在原草稿编辑区观察实际页面变化，记录可确认的接收证据，主动观察最多 10 秒或 64 批变化。遇到丢回复、重启或人工续查，未落库的原 START 能按原身份再读。它落库后，再读同卡的当前状态。每次用户附加都只进入一次文件输入。时序对照原始收据覆盖 40→41，42 的完整受控 Chrome 回归再次覆盖该案例。[时序对照](evidence/inter-poll-handoff.json)
- **把别的内容当成当前截图。** 独立复核发现，build 41 可因帮助按钮图标、隐藏图片、外图、未定量或零进度条错误收起缩略图。42 在提交返回、普通读取和后台观察三条路径使用同一归属判定。可见预览或有效定量进度须属于本次附件；派生 blob 必须有输入后签发的证据。缓存实际逐出旧记录后，新图仍可正常附加，旧图不能借用新图名称。41 的 15 个阴性场景中有 11 个假 START，42 的全部 15 个阴性场景正确拒绝；另 9 个长期使用与兼容场景全部符合预期。[独立负例与正例](evidence/preview-ownership-build42.json)

网页回归 225 项和本地真实 headless Chrome 检查 35 项均通过，包括双图、原卡失败、邻卡正常、丢回复和一次输入。两者各自的触发条件见回执。真实服务另行验收。

## 同一签名候选的验收

**安装包。** 正式 DMG 为 13,326,172 字节，SHA-256 为 `a9037d17d079c2ae6ed62693c4523e2f8b3543d0943dd00e8a79270c9069fde1`。App 与 DMG 均经 Developer ID 签名、Apple 公证并装订。两个 Gatekeeper 检查、签名包 arm64 与经 Rosetta 的 x86_64 自检、11 项 Sparkle 工具测试均通过。最低声明为 macOS 13。[正式包身份](evidence/package-build42.json)

**V1 · 一次自然点击。** 已登录的 Chrome 草稿中，冷、暖首击与三组快速双图分别产生八个操作和八份 START，八图在原草稿按顺序可见。文字、非空选区、前序附件与未发送状态均保留。三组点击间隔为 451.6, 416.7, 374.1 ms。点击到观察到收起的上界，冷、暖为 3.747、2.461 秒；八次的 p50/p95/最大为 2.213/3.747/3.747 秒。[逐次原操作及时间](evidence/v1-host-build42.json)

在独立匿名草稿中，普通虚拟鼠标冷首击取得一个原操作、一个 START 及一张新卡，原文和未发送状态保持。点击时确定目标耗时 32.16 ms，观察到收起的上界为 670.62 ms。登录草稿用普通指针事件完成，匿名与登录结果按各自样本报告。[匿名实机记录](evidence/guest-a-build42.json)

**V2 · 真实异常、核对与处置。** 无可用草稿时，点击后图片仍可用，操作数及 START 数保持 8/8。在登录的原草稿中，旧错误卡可从仓库核对，确认重新附加后保持 9 个操作与 8 份 START。恢复网络并重新点击后建立单独的第 2 次操作，新操作有独立 START，旧 UNKNOWN 和旧红卡保留。[原操作与新授权](evidence/v2-host-build42.json)

对另一次 182,112 字节的输入使用 3G 节流并仅阻断实际后处理请求，规则恰好命中一次。约 +1.5、+2.2、+3、+5、+7 秒，草稿中显示一个灰色占位块；+10 秒，该位置出现与本次文件前缀相符的红卡。程序保持可见的 UNKNOWN，未产生假 START。邻近的正常图和旧错误卡均保留。正常附加中未观察到可明确归属、在原图预览出现后还会执行并可被中断的接收步骤。在不更改网页内容或重放输入的前提下，本次无法实测“同一正面 START 后再失败”的服务格。将这格记为未验证；它与服务端永久终止证明、允许自动重试是三项不同的事实。自动重试保持关闭。

**只读续查。** 匿名冷首击的原卡在八轮自动观察后仍可人工核对，第八次在点击后 411.18 秒，随后手动核对在 418.31 秒内完成。保留 Chrome，改到空白标签，退出重启 Riftlet，核对成功并返回原草稿。超过 613 秒后，同页仍开着，核对已明确提示无法核实；关闭原标签后，返回草稿也给出对应提示。全程保留 33 张图、9 个操作、6 份 START，重复输入为零。自动轮次按隔离进程实际记录计数，原生桥的自动观察日志未打印操作 ID。对旧 UNKNOWN 单独实测取消、明确同意、收起和标为已处理，旧操作未改写。[同一张图的观察预算、重启及过期](evidence/guest-a-build42.json)

**V3 · 已附加的截图也能整理。** 普通管理窗将 24 份副本移到系统废纸篓，其中 4 份已有真实附加回执，6 份没有已验证的外部原图。实际退出、重启并找回后，32 张图的身份和内容、8 个原操作、5 份 START 均保留。另在发行源码测试覆盖留存入组、外部原件改变、在途保护、导入中断和跨进程恢复。[普通 App 回执](evidence/guest-a-build42.json) · [受控文件故障](evidence/v3-source-build42.json)

**V4 · 真实界面和权限。** 在独立 Mac 用户中，首次选择「稍后」后正常退出再启动，选择仍有效。截图权限缺失时，App 打开了正确的系统设置页。中英文四页设置、浅深色、仓库默认和 680 × 480 最小窗、列表/网格及键盘搜索均有实拍。最小窗完整显示 Search，真实 VoiceOver 字幕读出 Search screenshots、搜索框角色、日期、状态和网格选择。资料管理窗已验证孤儿副本从 0 增至 1 并在找回后减至 0。[普通 App 和辅助功能](evidence/guest-b-build42.json)

在已有录屏授权的宿主上，用同一个签名 App 的内置窗口截图选中专用测试色块。中文标注绘框、撤销、再绘、退出保护，遇到真实保存失败后选择重试，成功存入派生图并保留原图。英文标注在保存失败后选择 Keep Original，新入库图与捕获原图的 SHA-256 完全相同。这两次截图使用了宿主已有的授权。全新用户在系统内完成授权，以及 Chrome 自动化权限先拒绝后重新授予，均记为 NOT_RUN。[双语标注及原件哈希](evidence/markup-host-build42.json)

**V5 · 更新与公开通道。** 公开 1.0.5（31）和同营销版 35 均通过隔离签名 Sparkle 清单完成实际下载、安装及重启，运行中主程序哈希与正式 DMG 一致。另从公开 1.0.3（25）手动替换，12 份原文件哈希、旧记录、书签与反馈草稿均保留。公开 Release、实际官网按钮和签名 stable feed 本轮核对均为 1.0.5（31），完整下载的 SHA-256 为 `99276347932e231adf743664a54cfc782d8e345d89221587d54b7299a5c9f315`。[升级实测](evidence/v5-upgrade-build42.json) · [线上三入口核对](evidence/public-v1.0.5.json)

**V6 · 长期使用初测。** 在 2 核、4 GiB 隔离 Mac 上给普通 App 装入 1,000 张实际 PNG，管理窗显示完整数量的首屏观察上界 1.357 秒（含输入、截屏与 OCR）。核验期间新增 20 张，收录 p50/p95/最大为 318/494/660 ms；更改规则、打开历史时再新增 20 张，对应为 303/391/411 ms。40 张全部具有独立身份，数据库、原件与副本哈希一致。进程资源、实际磁盘增量及采样范围见回执。[普通 App 的 CPU、RSS、读写和时序](evidence/guest-b-build42.json) · [发行组件测量](evidence/v6-source-build42.json)
