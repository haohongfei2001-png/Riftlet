# Riftlet｜公开发行前基础体验契约（2026-10-27）

**状态：用户已确认的产品目标；实现方式、技术风险和实测结果仍须单独验证。** 本文补充而不覆盖 [快速吞噬正式交互契约](INTERACTION_CONTRACT_2026-10-27.md)。仅约束产品验收与技术研究，不改变当前工程准入、生产上传开关、macOS 截图方式或 Draft PR #1 的现有任务所有权。

## 1. 发行前必须具备的普通使用行为（P0）

### R01｜前台有可用发言框即可单击附加，不要求先把输入光标放进去

- 当前前台窗口/标签是**明确、受支持的 ChatGPT 草稿**，存在唯一的、可输入附件的有效 composer 时，用户从侧栏、聊天正文或页面空白处直接点击 Riftlet 的截图，**应正常追加附件**。
- **发言框存在与否**、**光标是否位于发言框**、**当前页面/前台窗口身份**是三个不同条件。不能因编辑器没有焦点就要求用户先在发言框点击一次；也不能把后台/不可见/不唯一的 composer 当成当前目标。
- Riftlet 点击不得激活自己、偷换目标、覆盖原文字、破坏选区、替换现有附件、自动发送消息。目标身份必须在点击边界冻结，在输入边界再次验证。若无法安全满足，不吞噬、不发送附件，并给出轻量的可理解反馈。
- 对 Web（Home Chat + 已有对话）和 Mac 客户端（新版 Chat/Work、Classic 如实际支持）分别研究、实现与真机验收，**不能将一种适配器的成功推广到其他适配器**。Web 最新实验证据里的 `document.hasFocus()` 不等于 composer 本身必须为 activeElement；真实可行性待专项核实。
- 验收矩阵：编辑器已聚焦/未聚焦、页面正文/侧栏/聊天历史被点击过、已有文字/选区/附件、跨对话和多窗口、浏览器地址栏与弹窗、首次冷启动首击、真实鼠标点击，成功与失败均记录精确目标及一次输入计数。不要用预先聚焦发言框的脚本来替代本项。

### R02｜无效点击必须有轻量响应，而不是悄悄无效

- 无当前受支持的 ChatGPT 草稿、无可用发言框、无附件输入能力、缺少权限或附件源文件暂不可用：点击后**不吞噬、不消失、不上传到其他窗口**。
- 保留极轻、短暂的按压/回退反馈；必要时在 tooltip 或菜单栏解释失败原因。正常成功仍**不弹成功 Toast/通知**，用户从原 ChatGPT 草稿附件获知状态。
- 与首次首击稳定性共同验收：避免没有焦点就拒绝、以“再点一次”或“先等预绑定”作为日常补救。

### R03｜自动归档绝不打断正在进行的操作

- 归档倒计时到达时，如果微图正在 hover、鼠标按住、按住移动（以后若启用）、正在点击动画/重排或正在执行未决上传选择，不立即将它从鼠标下移除。
- 用户操作结束、状态明确后再安全归档。失败重生的图也遵守同一生命周期。
- 睡眠唤醒、时区/DST/系统时间变化、批量达到超时阈值时，不应出现不可控的集中闪烁/移动，或把正在交互的条目归档。
- 自动归档仅改变 Riftlet 的可见/内部历史状态，不删除系统原图和 ChatGPT 草稿附件；具体超时数值仍待调校。

### R04｜保留系统截图习惯，审慎处理“Riftlet 被截图拍进去”

- 用户的既有 macOS 系统截图入口保持有效，不增加日常快捷键，不默认替换为 Riftlet 自己的截图引擎。
- 将**尽可能避免裂缝/缩略图污染用户截图**列为重要体验与隐私问题，必须真机验证 Cmd-Shift-3/4/4+Space/5、截图工具栏、延时/浮动预览、多屏/Stage Manager/全屏等；记录不同 OS 版本、具体来源和失败范围。
- **技术可行性先行**：Apple 的 `NSWindow.SharingType.none` 是旧机制；ScreenCaptureKit 对自有捕获可排除窗口，**不能直接推导系统 Screenshot.app 必然允许 Riftlet 排除自身**。不得将“全入口保证排除”假定已实现、也不得为达成无根据的承诺引入竞态严重的按键拦截、偷偷篡改原截图像素或强制改用户截屏习惯。
- 需要 Pro 输出多路径可证伪评估（公开 API、捕获前暂隐竞态、不同截图入口、替代方案与实际局限），并由独立真机验收裁决是否及如何进入发行范围。不可实现的场景要提供诚实说明和尽可能低干扰的用户控制，而不是硬凑一个不稳定补丁。

## 2. 成熟 macOS 消费级软件的最低体验闭环

| 领域 | 产品目标与最低验收方向 | 阶段 |
| --- | --- | --- |
| 首次安装/权限引导 | 引导截图来源、Chrome Apple Events/客户端授权；检测权限不足并解释；不要求用户熟悉终端；可完成一次真实截图→单击→草稿附件演练 | 发行 P0 |
| 支持范围/版本兼容 | 明示已验收 OS、Chrome、网页语言/普通会话、Mac 客户端和文件格式；不支持安全拒绝、不猜目标，不宣传未准入能力 | 发行 P0 |
| 暂停收录与隐藏裂缝 | 两个独立、清晰可访问的操作；隐藏不等于停止收录、暂停不等于删除。会议、录屏、敏感资料时用户可迅速控制 | 发行 P0 |
| 内部截图历史 | 简洁、可查找的时间顺序预览，已吞噬/已归档/异常可找回并按实际安全路径再用；不是复杂编辑器或 OCR 图库 | 发行 P0 |
| 图像格式与质量 | 常见系统截图、不同尺寸/编码/HDR 处理有明确支持矩阵；不会静默损坏细小文字、模糊转换或丢失源文件 | 发行 P0 |
| 保留和磁盘空间 | 轻量空间用量、有限存储、可恢复清理；严格区分隐藏/归档、删除 Riftlet 私有副本、用户系统原图和 ChatGPT 附件 | 发行 P0 |
| 原生几何/无障碍 | 可调整显示器/边缘与合理尺寸，尊重减少动态效果、键盘/VoiceOver 可操作路径；不遮挡关键系统区域 | P1 分层实现，核心命中/穿透仍是 P0 |
| 用户反馈与本地诊断 | 可用文字提交 Bug/建议；轻量、明确授权的诊断信息，默认不上传截图、消息、路径、token；可聚合以便单人维护 | 公开推广前 |
| 可靠更新和回退 | 签名/公证/可信安装、版本兼容提示、更新出错的恢复路径、数据迁移保留、适配器改版失效安全降级 | 发行 P0 |
| 实际用户可用性 | 对约 5–10 位目标 Mac 用户进行首装、冷首击、日常连续使用、错误恢复与截图历史找回观察，记录阻碍点，不以测试数量替代使用结果 | 公开推广前 |

## 3. 明确不要求加入首版的功能

不因本文件自动扩展为 OCR、AI 命名、云同步、Windows、通用剪贴板库、大型截图编辑器、任意应用上传或按住拖动。拖动目前仅为候选；任何新入口不得损害截图→一次点击的基础流程。

用户已经确定：**无成功提示；真实上传开始后的极快吞噬；失败准确判定后重生且可点击；UNKNOWN 入内部历史；单张/批量清空只改 Riftlet 可见性，不碰 ChatGPT 附件。** 本文件不重新争论这些原则。

## 4. 研发分工与证据边界

1. **现有工程负责人/Codex：** 继续未完成的 W2/N1/M1、目标身份、首击、迟到故障与真正系统截图闭环；只按已经核实的差异实施上述功能，保留成功及 safe-retry 独立准入和现有源图/数据库。
2. **独立 Pro 专项（研究、裁决；本轮不开发）：** 优先审查 R01 与 R04 的真实可行性/成本/风险，附带验证 R02/R03 的产品细则。见 [Pro 技术研究任务书](PRO_FEASIBILITY_REVIEW_BRIEF_2026-10-27.md)。可采用不同候选方案进行事实比较，但不得改写用户批准的“一次点击”和“系统自带截图”使用前提。
3. **产品/交互负责人：** 将用户控制、菜单、内部历史、安装与实际用户测试转为轻量验收设计；无需全部在当前 W2 真机验收期间同时实现。
4. **发布门槛：** 正式产品验收以实际平台证据为准。研究未完成 ≠ 已实装，测试通过某个实验范围 ≠ 全功能通过。需对难以保证的截图自排除给出可信限制或可行替代，不许通过虚假 PASS 宣传。

**只读决策文档更新；不修改 App 代码、默认权限、真实截图/ChatGPT 数据，不合并 main 或发布。**
