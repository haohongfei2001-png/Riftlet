## R1-A：先消除确定的错误目的地

从仓库根执行：

```sh
env -u RIFTLET_PAGE_PROGRAM_SOURCE node docs/quality/evidence/attachment-foreign-picker-repro.cjs "$PWD"
```

首版基线运行此脚本时foreign setter/change为1且退出0，表示当时**漏洞仍存在**。原脚本与失败回执是历史缺陷见证，不能直接当绿灯。PR #101已增加正式反向断言：无归属input收到0 setter、0 change、0 File；实际结果见工程进度。复现仅使用合成图片和本地fixture，不为继续交付反复运行原基线。

删除`sole untied + discovery timeout → execute`的安全晋升；保留能证明属于原composer的input、显式控制关系、同步入口调用或已绑定popup。不要借全局唯一、靠近、等待时间或“没有看到相反owner”代替正面归属。匿名异步picker若与页面无关活动不可区分，应在写入前可恢复结束；若真实ChatGPT确需该路径，先补真实窄证据再实现，不改写全页Timer/Promise来编造因果。

必要反例：真正入口惰性、真实picker超时才出现、两个匿名picker、相反owner、旧/新附件混合、切tab/navigation/editor重建、lost reply。保留原草稿、选区、旧附件和其他截图；当前setter/change至多1。现有测试若认可不安全情形，必须说明设计修正并更新，不偷偷删掉红用例。

## R1-B：恢复必须以“尚未外部输入”分界

prepared仅在旧进程遗留、无dispatch intent、无input调用凭证时收尾为可由新点击重试；使用现有数据库事务语义，新点击重新绑定当前真实目标。不要恢复旧内存FIFO，不在启动时append。旧UNKNOWN、START、dispatchIntent、compensated的operation/receipt/时间戳/文件必须保持。

对坏`rift-configuration.json`/`lifecycle-settings.json`保留原始字节，分别采用安全内存默认/暂停自动归档，继续初始化收录/历史。参照ArrivalMotionPreferences的现成模式，不另建通用配置框架。现有未知presentation值及未来字段保留；现有JSON没有schemaVersion，不编造全格式版本检测能力。UI恢复按钮只重置相关偏好，严禁删库/清空media。

运行中的重新检查要能验证原位恢复的missing文件；验证UUID和内容hash，不能同名即通过。保留队列身份与归档状态，恢复媒体不触发附件。先隔离数据根逐项注入故障，再以真实App强退/重开验证，绝不修改用户生产库作测试。

## R1-C：流畅性不能换来选错聊天

现在每个Apple Event可同步等待5秒，常见点击连续两次，部分fallback更多；这不是“整次最多5秒”。目标是主线程无长等待。先定义点击瞬间绝对进程/window/tab身份怎样取得：可使用短且有界的同步身份快照，然后把URL/DOM等工作放到后台并固定该身份；或提供确能绑定点击时刻的原生异步协议。不要把`activeIdentity`延后读取后宣称仍是点击时目标，也不要拿过时缓存猜目标。

Mac故障注入要测浏览器卡住时panel/历史/设置仍能响应、失败可恢复；同步部分超出预算则在输入前结束。之后用同一签名候选执行[验收矩阵](ACCEPTANCE_MATRIX.md)R1门槛：冷首图、连续第二图、正文/旧附件、无焦点、切tab、确定失败、lost reply和重启。真实ChatGPT不可达则保留`BLOCKED`，其他工程继续，不能以网站demo或控制fixture代替。
