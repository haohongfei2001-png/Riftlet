# 设置、首次使用与原生界面专项审计

审计基线：`44f745a15ecb3682a9da0bda17f17a5d9fc1f07e`（main），正式发布 `v1.0.1`。审计时间：2026-11-14（Asia/Shanghai）。此报告是源码与既有视觉证据审阅；本轮执行环境为 Linux，没有声称运行 AppKit、真实 macOS 设置窗口或真实 ChatGPT。

## 结论

设置的主要问题不是需要另一套视觉框架，而是**同一界面暴露了太多实现参数，并同时使用三种保存方式**。已经有一套可复用的原生界面、统一状态投影、异步保存回执与失败保留机制，应保留这些有效部分，压缩公开设置面。

现行四页为「外观与布局 / 截图 / 使用与历史 / 权限与帮助」。桌面形态、显示器、位置、主题立即保存；尺寸、色调、数量、动效时长只更新草稿，需要「应用参数」；归档菜单选项也只是草稿，需要另一个「保存归档时限」。用户必须知道控件背后的保存域，才能判断点击是否已经生效。该行为由源码明确实现，不是推测视觉印象。

源码还确认：切换形态后隐藏的无效参数仍可能阻断保存；「稍后设置」没有真正的延后状态；托盘允许填写 5–10 张但实际最多显示 4 张。优先修这些具体摩擦，再实施信息架构精简。

## 可独立执行的问题

### QA-SET-001｜P2｜普通设置混用立即保存、布局草稿和归档草稿，公开界面承担过多工程参数

**位置**：`RiftSettingsCenterPages.swift:26–119,166–195,201–260,292–313,351–365`；`SettingsStateModel.swift:373–428`；`RiftSettingsCenterController.swift:363–471`。

**现状与复现**：在「外观与布局」选一个形态立即生效，再拖动「可见截图」或「色彩强度」，桌面不随之持久变更，要找到底部「应用参数」。再到「使用与历史」选择另一个归档时限，还需单独保存。关闭窗口时出现「继续编辑 / 不保存 / 应用并关闭」，其中“不保存”只丢弃尚未应用的数值，保留刚才已保存的其他设置。源码和关闭文案都明确承认这种混合状态。

**影响**：所有改设置用户，频率中，修改成本中；用户会把仍未保存的菜单选项误认为已生效。公开的最小点击区域、行内留白、编号间距、四个毫秒时长、原始配置文件入口使消费者需要理解内部参数。

**裁决**：采用下文四页 IA；常规有效选择立即保存，滑杆在手势结束提交，文本在确认/失焦后提交且不提交 IME 未确认文本；保留 owner/revision、写入失败回滚与确切 pending target。删除公开的工程级尺寸/时长入口（保留文件兼容读取和内部审阅能力），不增加第二套设置存储。归档预设立即保存，现有小数值可被保留与显示，不强制重置。

**最小实施范围**：现有 Pages/Rendering/Controller 和 StateModel 的提交入口；不重写 Core、数据库或附件 engine。不要为此再建立通用设置框架。

**验收**：每项公开偏好的一次有效操作后，当前窗口、实际桌面、重开设置和重启结果一致；磁盘写失败显示一句就地错误及重试、仍显示真正生效值；快速连续修改不会被旧回执覆盖；切页面/关窗口不再要求用户理解多种保存域；输入法组合文本无误保存。

### QA-SET-002｜P2｜切换桌面形态后，隐藏的无效参数仍阻断保存

**位置**：`RiftSettingsCenterPages.swift:78–95`；`RiftSettingsCenterRendering.swift:185–200,309–328`；`SettingsStateModel.swift:301–315,439–452,465–479`。

**复现条件**：当前是微缝，展开高级详细参数，在「缩略图最大宽度」输入 `abc`（或把数值留空）；随后选择「截图托盘」。形态选择立即持久化，`numberedThumbnailSettings` 被隐藏，但 `includedInLayoutDraft(.fitWidth)` 仍为 true，`layoutPatch()` 仍解析隐藏文本并失败。隐藏的 fitHeight、rowPitch、numberFontSize、numberGap 等有同类风险；微缝的 hiddenFraction 在托盘也隐藏但仅对 windChime 排除。

**证据**：源码确定的隐藏与校验集合不一致；本轮未运行原生复现。现有 custom tint 已有“失活草稿不阻塞其他布局”逻辑，说明可沿用当前机制解决，无需新抽象。

**建议**：以实际生效/可编辑字段统一计算 form-specific draft inclusion；失活字段的文本保留，切回时恢复，但不得阻断当前形态的保存和正常退出。QA-SET-001 删除工程控件前也应先修这个局部问题，避免错误被 UI 隐藏。

**风险**：不能清空所有旧数值来“解决”阻断；不改用户已保存的其他形态配置。

**验收**：微缝 fitWidth 非数字→托盘→修改有效托盘字段可保存；切回微缝仍可修正原草稿；对每个仅某形态显示的字段做同类转换，失活字段不会混入当前提交。

### QA-SET-003｜P2｜「稍后设置」每次重启都会重新弹出引导

**位置**：`Sources/RiftletApp/FirstUsePreferences.swift:17–31`；`RiftOnboardingController.swift:547`；`RiftletMain.swift:220–227`；`docs/consumer/QUICK-START.en.md:4`。

**复现条件**：全新安装，打开引导，点「稍后设置」，退出并重启。`recordPresentation()` 写入 `started`，`deferSetup()` 只关窗口，`needsAutomaticPresentation` 对所有非 `completed` 状态均为 true，因此下次仍自动弹出。文档明确允许只使用本地历史的人选择稍后，这些用户会反复遇到引导。

**影响**：所有暂时不连接 Chrome 或只用本地功能的新用户；不是权限安全问题。

**建议**：新增明确的展示级 `deferred` 状态；用户主动稍后后不在每次启动强弹，可在菜单「完成设置…」和真正受阻操作的就地提示返回。未完成不等于已授权，不改变任何权限或附件准入；崩溃中断的 started 与主动 deferred 分开。

**验收**：首次打开→稍后→重启不弹；菜单可恢复引导；首次配置崩溃后可恢复；completed 不重复打开；任何展示状态都不能伪造 Chrome/文件权限。

### QA-SET-004｜P2｜托盘「可见截图」接受 5–10 张，实际硬上限为 4 张

**位置**：`RiftSettingsCenterPages.swift:114`；`SettingsStateModel.swift:102–106`；`RiftTrayLayout.swift:47`；`RiftSettingsCenterPreview.swift:24–31`。

**复现条件**：选择托盘，设置「可见截图」为 10、应用，准备至少 10 张可见记录。设置与 JSON 是 10，实际 `capacity = min(menuOpen ? 2 : 4, c.visibleCountPreference)`，一页最多四图；预览还写“10 张（示意前 4 张）”，使用户以为只是预览缩略显示。

**裁决**：托盘继续保持已确认的两行两列，不扩大产品形态。该选项移入桌面的少量高级选项，托盘范围只提供 1–4，默认保留 3；微缝/风铃按实际可容纳上限呈现，不能共用虚假范围。配置中旧 5–10 不静默重写，展示有效上限，只有用户明确改该项才保存新值。

**验收**：托盘设置、预览、实际容量一致；菜单展开保持当前四键与原有截图身份；翻页不丢图；切到微缝/风铃时原有合理偏好保持。

### QA-SET-005｜P3｜引导称「选择截图文件夹」，但文件选择器只允许当前系统截图目录

**位置**：`RiftOnboardingController.swift:306–311`；`RiftletMain.swift:951–979`；`FirstUsePreferences.swift:42–56`。

**复现条件**：初次无访问权限时，用户按按钮标题选择自己想收录的另一个目录，校验会拒绝；产品实际不支持该按钮更改截图来源。

**裁决**：改为「允许访问截图文件夹…」，在其上显示实际系统保存位置；路径正常时不显示重复解释。更改系统截图位置属于系统「截屏→选项」中的行为，只在来源无效时给一句准确提示。不要为修文案扩展成任意文件夹监控。

**验收**：按钮、选择器标题与真实操作一致；选错目录只给一次明确恢复指导；授权不改变系统截图位置。

### QA-SET-006｜P2｜更新和版本被收进「权限与帮助→关于与诊断」，日常偏好也与历史混放

**位置**：`SettingsProductPresentation.swift:5–21`；`RiftSettingsCenterPages.swift:201–260,292–327`；`RiftControlCenterController.swift` 的常规 popover 仅在检测到新版本后出现更新按钮。

**现状**：设置默认打开「外观与布局」；登录启动在「使用与历史」，外观在第一页，更新开关与主动检查在帮助页的诊断折叠区，原始配置文件入口紧邻更新。公开发行后，更新是日常产品能力，不应归类为诊断。

**建议**：按下文 IA 移至「通用」首屏；菜单现有右键「检查更新…」保留；帮助只放故障修复、引导和反馈；不增加营销式大版本卡片。此项可与 QA-SET-001 同一个 PR，但单独验收更新可发现性与开关语义。

**验收**：首次打开设置一眼能定位当前版本、检查更新、自动检查；更新失败仍可查看原错误/重试；新版本提示无需先打开高级区；不改变 Sparkle 签名和用户决定安装的边界。

### QA-SET-007｜P2｜面向英文官网的首用/权限/设置仍全部硬编码中文

**位置**：`RiftSettingsCenterPages.swift`、`RiftOnboardingController.swift`、`RiftControlCenterController.swift`、`Resources/Info.plist` 的四种权限用途字符串；`Resources/` 未含对应本地化资源；`docs/consumer/QUICK-START.en.md` 通过括号中文帮助用户寻找控件。

**证据与范围**：源码确认没有这些核心流程的英文资源，不是宣称系统无法显示中文或每个用户都受阻。英文官网已经提供英文发现/下载路径，进入 App 后切换语言造成认知断层。

**建议**：质量整顿内补齐中文/英文首用、权限用途、设置、菜单、历史核心操作和错误恢复文案；按系统/应用语言自动选择，不再增加语言选择器。先稳定中文 IA，再抽取 string keys，避免翻译旧冗余文字。此项排在 P1 和主要设置修复之后，可独立成 PR；未完成时支持说明应直说 App 当前主要为简体中文。

**验收**：中文和英文系统账户中相同流程可独立完成；按钮不截断，VoiceOver 有对应语言名称；权限描述来自 InfoPlist.strings；网址、协议字段、日志事件和持久化 key 不翻译；不制造更多重复说明。

### QA-SET-008｜P2｜旧设置/动效控制器仍作为产品模块和 GUI 验收的一部分，当前界面覆盖需区分

**位置**：`Sources/RiftletUI/RiftSetupController.swift`、`RiftSettingsForm.swift`、`ArrivalMotionSettingsController.swift`；`Sources/RiftletGUIAcceptance/AcceptanceWindowScenes.swift:42,112,257`；`Tests/RiftletUITests/UnifiedSettingsTests.swift`、`RiftSetupControllerTests.swift`、`QuietEdgeSettingsTests.swift`。

**证据**：正式 host 使用新的 `RiftSettingsCenterController`；旧 GUI scenes 仍实例化上述旧控制器。这些不是完全未引用的“死文件”，而是历史验收/测试继续使用的实现；不能把旧界面窗口截图或旧测试数量当成现行设置验收。

**建议**：先明确现行设置/首用/菜单的测试与截图入口；将没有产品消费者的旧视图移到历史 fixture/验收支持 target，保留必要回放能力，不同时维护两份用户设置。只移除确认无消费者的代码，不删除历史证据文件。不以新增“相同控件存在”测试代替实际保存与恢复用例。

**验收**：正式 App 可达图只含一个设置实现；正式 UI 验收运行当前 SettingsProductHost；保留 old evidence 的源 SHA、来源标记；全套必要当前流程仍测到，不能靠减少断言变绿。

## 关联其他审计项

- **QA-DAT-001（存储负责人）**：坏 `rift-configuration.json` / `lifecycle-settings.json` 会让 `RiftletMain.start()` 在 383–405 提前抛错，表现为外观或归档偏好损坏使整个应用不能完成初始化。设置开放“打开配置文件”会放大该风险。恢复必须保留原件、截图/数据库/UNKNOWN；应支持隔离损坏偏好后的安全默认或明确恢复入口，而不是删库重装。
- **QA-DAT-003（存储负责人）**：历史容量/删除语义缺口。设置本轮只提升容量状态与管理入口可发现性，任何真正删除策略必须单独设计，并保护原图和不确定附件。

## 新信息架构与交互裁决

保留一个原生设置窗口、四个一级页面，沿用现有 AppKit、原生开关/选择器和状态所有者。新的导航不是四张大卡片。

| 页面 | 首屏内容 | 仅需要时出现 | 从此页移走 |
|---|---|---|---|
| 通用 | 登录时启动；外观（跟随系统/浅色/深色）；版本与检查更新；每天检查更新 | 登录项待系统批准、更新失败行 | 原始配置文件、调试信息 |
| 桌面 | 当前形态与小型实际布局预览；位置；显示器；当前形态相关的材质或风铃排列 | 自定义色调/强度；极少量高级外观项 | 毫秒时长、点击区域、行内留白、编号字号等工程参数 |
| 截图 | 系统截图位置与一行状态；内置截图入口/默认方式；闲置后归档；本机存储与打开历史 | 当前权限不足的恢复动作；常用键自定义；不完整容量结果 | 历史视图样式（放回历史窗口）；暂停/隐藏（菜单快捷状态） |
| 帮助 | Chrome 连接状态及一个主恢复动作；重新查看引导；反馈与建议；使用说明 | Chrome JavaScript 的必要步骤；高级诊断导出 | 更新、日常偏好、原始 JSON 编辑入口 |

### 用户路径

1. **普通用户首次安装**：单一引导窗口先说明“截一张图，点边缘缩略图加入 Chrome 的 ChatGPT 草稿”。只显示当前缺失的两个必需条件：截图目录访问、Chrome 连接。连接完成后提供「开始使用」，同时说明消息由用户发送。位置已有可用默认值，移为此窗口可选项，不强制第三页选择。
2. **只想暂时使用本地截图**：点「稍后设置」，保留正常收录和历史，不重复强弹。后来第一次附加受阻，在当前截图附近显示简洁恢复入口，打开同一个引导状态，不重新从介绍走三页。
3. **改外观**：菜单→设置→桌面；选择立即作用到原有安全的布局调度器。正在点击/动画中的布局仍延后到安全边界，反馈“操作结束后应用”只在该状态出现，不长期解释。
4. **权限拒绝恢复**：帮助直接显示当前阻碍（例如「需要允许 Chrome 自动化」）和「打开系统设置…」。回到 App 后用现有被动重检刷新；只在确实还未确认时保留「重新检查」，不同时展示多套相同动作。
5. **查看历史**：菜单→截图历史。列表/网格切换属于历史窗口工具栏的视图偏好，与历史实际显示同步。
6. **升级**：菜单原有检查入口或设置通用；看到版本、说明、立即/稍后选择；更新内部的签名校验、正常退出和数据保护保持。

## 逐项设置处置表

“删除”均指**从普通用户界面删除工程参数**，不删除旧配置字段/历史偏好/用户数据。默认值列是当前源码默认，除非明确标注为裁决；已有有效偏好一律优先保留。

| 当前项 | 当前默认/真实含义 | 处置与新位置 | 迁移/实现影响 |
|---|---|---|---|
| 桌面形态 | 无 storedForm 时微缝；托盘/风铃/微缝均可用 | 保留，桌面 | 不擅改已发布默认；旧折页/口袋兼容映射不改 |
| 风铃排列 | 旧风铃缺值时整齐；其他缺值时错落 | 保留，桌面且仅风铃显示 | 保留现有“旧选择不变”规则 |
| 屏幕边缘 | 左中（新配置） | 保留，桌面六点位置 | 不新增布局模式；旧绝对位置仍可读 |
| 显示器 | 首次写入当时首块屏幕 ID+UUID | 保留，桌面 | 引导“使用主显示器”实际是选择当时主屏，不宣称动态跟随；同名屏加序号 |
| 回到已选显示器 | 仅临时 fallback 时可用 | 保留为就地恢复动作 | 不改 disconnected preference 或偷换屏幕 |
| 托盘材质 | 系统玻璃 | 保留，桌面 | 系统/紫蓝/自定义三项；不另增皮肤 |
| 玻璃色调 | 255°（自定义 dormant） | 保留，仅自定义展开 | 滑杆手势结束保存，隐藏草稿不阻塞其他项 |

## 视觉与可访问性可验收规格

1. **维持原生而压缩层级**：沿用现有 814×580 pt 作为默认窗口，716×450 pt 最小尺寸，侧栏缩到 164–176 pt 后由实拍确定；内容左右边距 24 pt；页标题 20–22 pt semibold；正文/控件 13 pt；辅助状态最低 11 pt。一级页面每页不超过两个必要段落。正常行高 36–40 pt，有一句必要说明的行 48–52 pt。使用系统 separator，不额外套圆角卡片。
2. **首屏密度**：默认通用页在 716×450 pt 可见版本、检查更新和登录启动；桌面页在该尺寸能看到形态、位置、屏幕，其他项目可滚动。不要通过缩到 9–10 pt 塞进首屏。
3. **预览**：最多一处当前形态预览；使用实际产品 layout/rendering 的合成 fixture，标签明确为预览。不要让示意图宣称10张却实际仅4张。截图规范用无隐私素材：0/1/3/10记录，三形态左右边缘，1×/2×、明/暗、减少动态效果/透明度/高对比度。
4. **错误**：错误紧跟所属行，一句原因+一个恢复动作；不重复页顶、页尾、Toast和行内四处。成功默认静默，以实际生效的控件状态作为反馈。正常状态不长期显示“已读取”“已确认”等审计语言。
5. **原生核查**：完整键盘导航、Tab顺序、Escape、VoiceOver名称/值、中文输入法组合文本、滚动和最小尺寸。菜单显示的暂停/隐藏状态与设置/重启一致。显示器断开后保留原偏好并给一个明确恢复动作。
6. **交付截图**：同一源码/安装包、同一窗口尺寸、同一系统外观和合成资产；拍改前/改后四页、错误态、引导暂缓重开和三形态。记录源码 SHA/版本/架构/缩放，不能用 PR58 老画册或设计稿冒充1.0.1修复实拍。

## 保留的有效机制

- 设置仅投影状态，不在 render/update 中申请权限、写文件、发附件或抢焦点。
- owner/revision、明确写入意图、失败 pending target、域间串行与过期回执保护。
- 显示器 UUID 与临时 fallback 分离；不能把断屏临时位置写回用户偏好。
- 旧配置与未知 presentation 字段保真；删除界面参数不等于删除兼容解码。
- 隔离 settingsReview 域不能写用户真实偏好/登录项/系统权限。
- 减少动态效果、减少透明度、高对比度继续跟随系统，不再制造重复开关。

- **SET-A（先做，范围小）**：QA-SET-002/003/004/005；每个都是明确当前行为修复，既有页面先变可靠。与 QA-DAT-001 同步但不要争抢 RiftletMain；由主集成负责人统一改动。
