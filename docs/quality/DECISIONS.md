# 当前质量设计裁决

1.0.10（65）确立点选后进入最近历史的交互。D15 规定点图时没有草稿的恢复条件，发行及验收记录见[当前状态](ITERATION_STATUS.json)。历史决策及其证据保留当时的版本。[修订前全文](https://github.com/haohongfei2001-png/Riftlet/blob/933a6f32c90908f034137ee32ff05273b615913b/docs/quality/DECISIONS.md)

| ID | 裁决 | 依据与实施边界 |
|---|---|---|
| D01 | 一次点选附加到正确草稿，消息由用户发送 | 正式目标为普通 Chrome、Edge 中可编辑的 ChatGPT 网页草稿，点选时验证原窗口、标签、文档和编辑器 |
| D02 | 超时不能使无归属input合法 | QA-ATT-001已受控复现；保留可证明的动态/hidden/portal/重建路径，无法区分的匿名异步picker在写入前结束 |
| D03 | 每次点选后图片移出活动托盘并进入最近截图 | 无目标、失败和结果未知遵循同一可见性规则。START 仍只表示原草稿实际接收本图 |
| D04 | 最近截图保留 20 张，用户再次点选才会发起新附加 | 上滑查看历史，下滑返回托盘。失败不重建活动卡片，不自动重试；保存原图、操作与 UNKNOWN |
| D05 | 旧prepared仅在能证明从未dispatch时恢复为可显式重试 | QA-ATT-002；不恢复旧内存FIFO，不碰dispatchIntent/START/UNKNOWN，不自动开始附件 |
| D06 | 纯偏好损坏不得阻断收录与历史 | 保留原始字节，采用会话安全默认，坏归档策略先暂停自动归档；修复该偏好不重建数据库、不删除图片 |
| D07 | 设置导航为通用、附加、截图托盘、截图、帮助 | 一份AppKit界面和同一owner；常规有效变更即保存，失败就地反馈；保存安全机制保留 |
| D08 | 工程参数退出普通设置，已有偏好无损兼容 | 毫秒时长、点击区、编号间距等由软件负责；不是删除配置字段或重置用户视觉 |
| D09 | 保留三形态、当前默认、托盘2×2与已确认位置/比例 | 不因个人审美推翻风铃/微缝/托盘；托盘数量只显示可实现范围，最大4，原数值不静默改写 |
| D10 | “稍后设置”成为明确展示状态 | 不再每次启动强弹；不伪造权限完成。位置默认可用，不强制初次多做一次选择 |
| D11 | 历史/存储入口按用户任务组织；不默认删除 | 保留查看用量与当前原件；主动清理语义先设计，计数/范围/可恢复性明确。任何真正永久删除或迁移另行审查，不混入P1修复 |
| D12 | 沿用Sparkle、SQLite与现有可靠恢复机制 | 不为了少代码去掉签名、事务、journal、hash、identity及owner/revision；减少无效工作而非重做框架 |
| D13 | 当前入口短小，历史一次归档；当前状态单一 | AGENTS/产品/治理/执行入口已重整；旧证据按旧SHA保留，测试pass不等于真实服务pass |
| D14 | 发行使用现行独立复核、双架构 CI、签名、公证和稳定更新流程 | 审查结论与每一候选的公开状态记录在当前状态及对应发行记录中 |
| D15 | 1.0.11 通过仓库已有按钮找回点击过但从未开始附加的截图 | 只扩展到 traySelection、swallowed、pending、无活动指针、无任何持久化操作且点选已结束的记录。恢复只回到托盘，用户再次点选才允许输入 |

正式源码和准入流程见[主线治理](../MAINLINE_GOVERNANCE.md)。历史设置设计和原始产品决定分别见[设置方案](SETTINGS_REDESIGN.md)和[历史快照](history/docs_DECISIONS.before-20261114.md)。
