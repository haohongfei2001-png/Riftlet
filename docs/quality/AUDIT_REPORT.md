## 判断

Riftlet的核心产品方向成立：照常截图，在桌面边缘找到图片，一次点击交给正确的Chrome ChatGPT草稿，由用户发送。正式产品已有三种桌面形态、历史、首用引导、内置截图/标注、私有反馈及Sparkle更新；没有理由为质量整顿扩平台或重做产品。

但本次不能给出“已达到成熟商业软件质量”的结论。生产附件脚本仍能把图写入无归属picker；prepared中断恢复、偏好损坏降级与主线程浏览器调用存在可定位缺陷。设置公开过多工程参数、保存语义混杂，正常START也会被展示为长期待核实。更直接的机会是删掉用户不该承担的判断，同时保留目标身份、一次输入、原图、UNKNOWN与发行签名这些有实际风险依据的约束。

共 **22项：P0 1 / P1 4 / P2 15 / P3 2**。P1中三项是核心源码确认缺陷，另一项是当前候选真实服务验收缺口，不是一项新复现的应用故障；远端保护按P2治理债务单列。所有条件、修复建议和验收见[台账](ISSUE_REGISTER.md)和各Issue。

## 排序与第一修复切面

1. **QA-ATT-001 / P0**：删除“唯一无归属picker等到超时就合法”的晋升；先证明0误投，再验证真实ChatGPT仍能冷首击和连续两图。不能只让模拟用例变绿。
2. **QA-ATT-002、QA-DAT-001 / P1**：prepared仅对确定未dispatch的操作恢复；坏外观/归档偏好安全降级，历史与收录继续工作。禁止删库、自动重传或改旧UNKNOWN。
3. **QA-ATT-004 / P1**：移除会阻塞AppKit的长时间Apple Event等待，同时保留点击瞬间的绝对目标身份。把所有读取简单丢进Task会改变绑定时点，不能接受。
4. **QA-DAT-004 / P2**：重新检查需能识别运行期间原位修复的私有文件，按UUID/hash确认，不借此重新输入。
5. **QA-REL-001 / P1验收缺口**：上述同一候选包在Mac与真实ChatGPT完成冷首图、连续第二图、草稿/旧附件保留、正确目标和失败恢复。未执行就保持阻断状态。

修复成本、影响人数、频率和回归风险已逐项列入台账；通常只有特定异步/异常条件触发的缺陷也不能因频率未知而忽略错误附件风险。远端保护QA-GOV-002并行推进，不允许阻断其他可独立修复工作。

## 设置与设计裁决

主信息架构定为 **通用 / 桌面 / 截图 / 帮助**。通用承载启动与更新；桌面保留形态、位置、显示器及少量确有价值的外观选择；截图承载系统截图目录访问、历史与归档；帮助承载真实故障恢复、引导、反馈，技术诊断折叠。

正常有效操作直接持久化，滑杆在手势结束提交，文本在确认/失焦后提交且保护IME。失败显示有效值与一句就地错误，旧回执不得覆盖新设置。毫秒动画、最小点击区、编号间距等退出普通设置，由产品保证合理值；兼容读取旧值，不静默重置。托盘保留2×2，数量范围必须与真实能力一致。“稍后设置”不能每次重启再弹。更新不再藏在诊断里。

完整逐项处置、默认值、迁移、用户路径与可测视觉规格见[设置重设计](SETTINGS_REDESIGN.md)。没有以旧截图伪装当前原生设计验证；实作后需按矩阵提供同源同包前后截图。
