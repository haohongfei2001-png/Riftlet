## 1. 独立裁决：不要再次全面研究，推进已经确定的最小工程路径

| 子项 | 结论 | 对首版的约束 |
| --- | --- | --- |
| **Web：未聚焦输入框仍单击附加** | **条件可行，有代码基础。** 现有 File/DataTransfer + files setter/change 路径不要求 `document.activeElement === editor`；但不保证冷首击及刚点击正文/侧栏后立即选图。 | **P0**：在真正前台/当前有效草稿中不需先点发言框、无需等待或再次点击；保留身份验证与已有草稿内容。 |
| **Mac 客户端** | 未证明。基础 AX/NSPasteboard 协调与测试不代表当前版本具有无损、非编辑器聚焦的附加入口。 | 每个 bundle/version/surface 分开准入；不可盲去掉 `requireFocus`，不能发普通 Cmd-V 赌当前焦点。Web 的独立通过不应等 Mac。 |
| **原系统截图自我排除** | **没有可直接用于所有 Screenshot.app/快捷键入口的公开平台排除契约。** | 首版不能承诺自动隐身；**可靠、持久的用户主动隐藏裂缝**是当前低风险方案。自动监听截图快捷键来藏窗仅可作 P1 有界实验，绝不把竞态方案当默认安全保证。 |
| **无效点击反馈** | 小改动可行。 | 能证明未输入：短按压→恢复，原图保留，可按需查错误；已提交但没回执：UNKNOWN，不能谎称未输入。无成功 Toast。 |
| **自动归档不打断点击** | 以现有 UI/Core 为基础可做，必须覆盖异步间隙。 | P0：交互锁持续至 prepare 持久化或明确取消，延迟自动归档回执不能覆盖已被用户接受的点击。 |

## 2. Web：具体优先修复的根因

1. **调查真实冷首击的时间顺序，不是盲目增加等待。** 分别记录：原目标完整 ACK 到达原生执行器、完整 ACK 发布到主线程、真实 `NSEvent` 的发生时间、截图 assetId 与 target/draft identity。只有完整且同身份的证明早于点击，才能允许处理其发布延迟。不得在点击后从“新的当前草稿”获取身份再追认旧点击。
2. **普通正文/侧栏互动的资格撤销与重新预绑定时序。** 页面表单外可信交互目前会撤销 input authority；有图约 1 秒/无图约 3 秒的常规回补可能遗漏紧随其后的物理首击。可使用新图/激活/唤醒和微图 hover 等机会提前预绑定，但**hover 不是用户必经步骤**；本质仍是原点击前证明与同步目标复核。
3. **安全释放退休空页面 generation。** 上限 32 代，若大量无操作的失效代无法回收，久用会进入拒绝状态。只允许清理没有活跃操作、没有仍须观察的 UNKNOWN/成功墓碑、没有有效 Native 引用的退休空代，不丢原操作。
4. **可用 composer 谓词。** 可见/可编辑、非 inert、没有阻挡模态、附件入口未禁用、唯一有效 composer；正常隐藏的 `input[type=file]` 不需要自身可见。保留原草稿/用户文字/已有附件及选区。
5. **达不到真机 P0 时的条件性替代方案。** 先完成上述低侵入改动并真实计数首击失败。若结构性问题为“新页面点击前根本没有身份可证明”，停止反复调整定时器，比较 MV3 常驻扩展 + Native Messaging 的提前观察能力。**扩展也不能凭空解决同 URL/同 DOM/同 React 状态、无人察觉的业务草稿 A→B→A 连续性问题**；不能把换传输当万能解决。

**当前不应做：** 新的通用键鼠模拟系统、强制聚焦编辑器、切到任意后台 ChatGPT、从未确认身份的后来目标重放原点击、以 `input.files` 调用成功等同于最终 READY 或 `uploadStarted`。

## 3. Mac：必须单独取得真实能力证据

新版 ChatGPT Mac、Classic、Chat/Work 必须独立检查版本与 AX 树，确认有没有**精确对原 composer 附件的原生动作**。存在该动作才有希望不改变旧焦点/选区地附图。临时聚焦→Paste→恢复仅保留为有界研究，必须验证失焦输入、中文输入法选区、粘贴板复制竞争、超时已执行等情况；不允许撤销焦点检查后盲发 Cmd-V、Cmd-A 或重写旧文本。

尚未准入的客户端不得在官网/安装文案中宣称支持。至少 Web 经过完整实机验收可先独立形成一个范围诚实的首发能力。

## 4. 截图自包含：独立功能与明确代价

**Apple 一手资料：**
- [`NSWindow.SharingType.none`](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none)：macOS 不再使用的遗留常量，Apple 明确不建议用它隐藏或排除截图内容。
- [`SCContentFilter`](https://developer.apple.com/documentation/screencapturekit/sccontentfilter)：为**使用该过滤器的捕获流**筛选窗口/应用；不会自动改写另一个捕获客户端（系统 Screenshot.app）的规则。
- [Chromium AppleScript 指南](https://www.chromium.org/developers/applescript/)：Apple Events JS 需要用户显式允许；Native Messaging 扩展是替代集成途径。

**首版最小可靠措施：**
- 在 UI 控制器增加持久 `userHidden` 意图，所有 row panel/装饰线一并隐藏；新图、补位、屏幕重排、唤醒、应用重启或迟到动画**都不能自行解除隐藏**。
- 隐藏与“暂停收录”“清空队列”“自动归档”完全不同。隐藏时仍可收录并保存记录、观察旧上传；不会删除 macOS 原图或 ChatGPT 草稿附件。
- 对普通系统全屏/区域截图，不能承诺自动排除 Riftlet。首版应明确告知需要无干扰画面时可先隐藏；这有额外人工成本，不能把它包装为原两步操作的同等体验。
- 下一轮真机先跑四种来源隔离：两者退出、仅正式 App、仅 GUI helper、两者同时运行。分别验证截图内究竟是哪一组缩略图、编号与线，不根据已经混杂的样本草率归因。
- 性能分别测 **T0 取像完成、T1 完整文件可读、T2 缩略图首帧可点**。历史约 61.5 秒为截图快捷键调用返回至文件 mtime 的时间差，不能当成 watcher 的耗时或已完成用户感知延迟。

**产品风险提示：** 手动隐藏是可控退路，不是彻底解决截图污染。公开发行前必须测实际发生频率和用户是否可接受；若经常截入敏感历史图，应提高该问题的发布优先级，而不是仅在文案中披露。

## 5. 无效点击与闲置归档的最小状态保护

- **确定未输入**：当前没有有效 composer/权限或输入前失败，微图短暂按下后复位，不吞噬，按需说明原因；下次正常可直接点击。
- **已实际开始上传**：正向关联证据成立后触发非常快的吞噬；草稿里的附件就是用户确认来源，不额外弹成功 Toast；后台单独记录 READY/UNKNOWN/失败。
- **上传结果未知**：不自动重试、不让已吞噬 UNKNOWN 在裂缝中永久卡住；原操作观察与新截图选择分离。
- **判定明确或极高可信失败**：按照既有已批准契约重生**普通、立即可点击**截图，继续正常使用/归档生命周期；分类准入必须排除旧上传有可能迟到成功的重复风险。
- **自动归档**：`mouseDown` / AXPress 固定 assetId 和交互版本，保护至操作意图准备妥当；`NSTrackingArea` 跟踪 hover，必要时检查静止鼠标下窗口新出现；本地交互/动画中不执行造成跳位的归档；归档提交前和渲染前均比较交互版本；唤醒重算；避免持续全局鼠标轮询。归档小时数尚未批准。

## 6. 建议的顺序与工程验收

**接现有负责人，不开第二套工程：**

| 优先级 | 责任线 | 明确任务 / 证据 |
| --- | --- | --- |
| 1 / P0 | W2 + UI + Core | 冷首击 ACK／主线程发布／NSEvent 三时点 trace；修未聚焦正文互动后的预绑定资格空档；有效 composer 谓词；退休空代回收。**物理鼠标首次点击**及完整草稿身份必须通过。 |
| 2 / P0 | Core + Adapter | 按 PR #4 分离 `uploadStarted` 与 `verifiedReady`，可见/隐藏/归档独立持久化，正常快吞噬、UNKNOWN 后台观察、失败重生可再次点击、不同截图继续处理。 |
| 3 / P0 | UI + Capture | 独立、持续的隐藏意图；无效点击轻反馈；归档至 prepare 的选择保护；真实截屏自包含来源隔离；T0/T1/T2 延迟。 |
| 4 / P0 | W2/N1 | 真机矩阵：未聚焦 editor/正文/侧栏，旧文字/附件/选区，页面切换 A→B→A，地址栏/模态，多截图接近连续点击，失败/UNKNOWN/重启；无错图与无重复。 |
| 独立准入 | M1 | 取真实客户端 AX/动作/剪贴板证据，某个 surface 未通过不拖住 Web。 |
| 有条件 P1 | 专项验证 | 被动自动隐藏截图入口、有证据的 MV3 fallback、进一步性能调优与其他语言/客户端覆盖。 |

**工程纪律：** 不覆盖现有 W2/N1/M1 进度，不删旧 UNKNOWN/审计，不重新建传输，不改 main/发布/启用生产注册表。以上全部是待实施/验收事项，不能因为 Pro 报告“条件可行”而标记 PASS。已批准产品要求始终优先于旧的“READY 才吞噬”的 UI 规则。
