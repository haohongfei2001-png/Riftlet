# 预测截图入口：固定模式槽与持续截图

本增量以 `1920e0562db893a3292af89a89270a26ddb46a5f` 的最新统一内部 Beta 为基础，位于独立分支 `codex/predictive-capture-entry-20261028`。它实现创始人本轮确认的截图入口，并保存可离线打开的[高保真交互参照](../design/capture-entry/README.md)。正式工程分支、main、原来的上传准入和历史证据不由本增量改写。实施期间正式 Beta 从 b4bcfa 更新到 1920e056；本分支保留该更新的等待/取消反馈、所有 Feedback hook、原审计及完整证据，只叠加当前截图入口。

## 最新用户决定

1. **截图成功不是退出截图模式。** 一次截图成功只将新图收录进现有队列；工具条保持展开，当前模式保持选中，可以继续截图。明确点击活动模式的取消盖片或按 Esc 才退出。
2. **三个模式槽固定。** 设置决定下一轮会话的默认模式及槽位。会话内点击另一种模式只改变选择，不交换模式图标。活动模式的原槽显示 X；取消盖片在固定槽之间移动。退出后入口仍收回到原底部位置。
3. 保留已批准的细窄玻璃、时空裂缝意象、独立图标/背景透明度、方向预测、早显示与较迟消失。没有使用图标模糊、缩放或横向滑入代替透明度。

### 固定排列（从底部向上）

| 设置中的默认模式 | 底部原入口 | 第二格 | 第三格 | 顶部 |
| --- | --- | --- | --- | --- |
| 窗口（初始） | 窗口 | 区域 | 全屏 | 三点 |
| 区域 | 区域 | 窗口 | 全屏 | 三点 |
| 全屏 | 全屏 | 区域 | 窗口 | 三点 |

例如默认窗口：点入口后，底部窗口槽显示取消；点第二格区域后，第二格成为取消，底部重新显示窗口；再点底部窗口即可切回。每次只改选中态，三个模式都始终可达。设置在当前会话中改变默认值，不重排正在使用的槽位；下一次展开才使用新设置。

### 光学和几何

- 相机线条和背景分别计算 alpha。图标 full/start 半径为屏宽的 `0.35 / 0.60`，背景为 `0.08 / 0.46`；退场外半径为入场的 `1.5` 倍。
- 图标响应 rise/fall 为 `18 / 170 ms`，背景为 `96 / 150 ms`，每帧上升/下降限幅独立。速度、朝向与最多 `700 ms` 的预测使线条更早稳定。参数是实现值，不是已实测的端到端延迟结论。
- 原入口中心保持不动，上方通过同一玻璃表面展开；取消盖片独立移动，基础模式图标不移动。
- 一个装饰面板完全透传鼠标；真正输入只在相机/三个模式/三点的小面板上。待机只观察鼠标事件，不拦截键盘，不请求屏幕录制权限。
- 新安装只把未经改动的旧默认布局调整为本参照的间距；已有自定义几何不被覆盖。长队列在入口下方排布，不能挤占工具条；无可见图片时没有裂缝线。

## 截图状态与边界

打开入口直接启动默认模式。切换模式立即改变下一次选择，取消正在拖动但尚未确认的区域。已经确认并执行中的截图保留当时冻结的模式、目标和选项；随后切换不会错把旧结果当成新模式。截图成功清除本次请求并重新待选，保持同一展开会话。

Esc/取消使会话身份失效并终止自有截图子进程。旧异步完成不能重新打开选择层或提交成新会话结果。菜单和标注窗口暂停选择层并清除未完成手势，关闭后需要新的完整点击；不重放菜单关闭点击。

区域和全屏曝光前，选择层保持键盘接收能力但透明，host 临时隐藏其他 Riftlet 可见窗口。引擎检查 WindowServer 中自己的面板已经不可见/透明才拍摄，否则明确失败，不把 `sharingType.none` 或一个固定延时当作自排除证据。曝光结束恢复同一模式、alpha、展开进度和队列；这是短暂自排除，不是自动收回工具条。

系统录屏许可只在明确开始截图时请求。窗口模式使用冻结的窗口 ID 和 owner PID；计时后、启动前及返回后复核身份。区域/全屏使用全局 Quartz 点坐标，包含多屏负坐标，不把 Retina backing scale 误乘到系统截图参数上。屏幕布局变化使旧选择失效。

## 数据和原有上传契约

截图保存在现有私有根的 `captures/`，权限为目录 `0700`、图像 `0600`。系统输出的原始字节不转码、不伪造系统截图标记；完成后的文件直接进入原有 staging/journal/media/SQLite v3 收录路径。自有输出目录纳入存储用量统计；现有系统截图目录观察器继续运行。

有真实系统截图元数据的原 PNG 仍须通过原 importer 和现有候选的格式/身份预检。缺少该元数据的真实图，以及标注生成的新图，记录为新增 `applicationScreenshot` 来源；它们可以本地保留，但不能借用系统截图或 synthetic 的 upload-start、complete、safe-retry profile。本次不新增任何准入 profile，不修改 Web/Chrome 输入代码、旧 UNKNOWN、草稿锁或媒体。

**兼容性：** 数据库 schema 仍是 v3；新来源值是显式的前向数据变化。写入 `applicationScreenshot` 后，早于本增量、只认识两个 origin 值的旧程序不能被当作安全回退读取器。不要用清库、删原图或重传旧项解决回退；保留此版本或后续兼容版本。

## 2026-10-29 统一候选的后续来源收紧

上文按真实系统截图元数据区分内置原件的描述保留为历史实现记录。最新 `6b60f67f6d35272eecff901c507bd75a77874ed6` 所携带的实际区域截图组件证据确认：由应用启动的系统截图命令也会写入真实系统 xattr，该标记不能独自证明它属于此前独立准入的原始系统截图来源。

本轮统一候选因此通过专用 built-in 导入 API 将新的内置原件和编辑结果都记录为 `applicationScreenshot`，与既有 Core 对“Riftlet 内创建/编辑的真实图像”的来源定义保持一致。原始 PNG 字节及真实 xattr 不被伪造或改写。即使其格式符合既有候选要求，这些新内置截图仍只具有本地收录资格，不能借用 systemScreenshot 或 synthetic 的 upload-start、completion 或 safe-retry profile。这是对未经单独准入路径的收紧，不是新建上传许可；未来若要开放，必须提供该来源自己的实际端到端证据和独立准入审查。

已有系统截图目录的观察、原始系统截图的受限候选能力、历史资产、UNKNOWN、原图、SQLite v3 与全部原上传证明要求保持。去重若命中其他历史 origin，只拒绝新内置导入，不重新标记旧记录。入口、三种选择模式、标注、本地历史和后台既有操作不删除。

输出改为私有隐藏暂存目录内的普通 PNG 叶名，完成后排他发布为隐藏最终原件，避免系统命令拒绝隐藏叶名及观察器重复收录。非空失败输出保留。新的统一源码必须重新通过准确组合 CI；自有不透明合成窗口的单次实际 CLI 区域探针只证明组件链路，不能冒充真人选择、入口三模式、多显示器或真实上传验收。具体 source、结果与 NOT_RUN 范围见本轮统一证据与交付报告。
