## 普通用户入口

在 macOS 打开工程制品中的 **Riftlet.app**。首次普通启动显示一个原生「开始使用与运行状态」窗口；以后从菜单栏同名项目重新打开。首次展示记录独立于 SQLite、隐藏、暂停和权限，关闭窗口不等于授权。背景收录、状态变化、截图点击不会自动重开引导。

窗口显示系统截图位置、实际目录访问结果、收录开关、裂缝隐藏/无图状态、待核实数量、当前附件能力、明确的格式/版本范围及按需存储用量。正常成功没有 Toast 或通知。

- 「查看截图位置」只打开实际目录；不是目录时拒绝，不启动任意文件的关联应用。
- 「允许访问截图位置」使用 macOS 原生文件夹授权面板，只接受重新读取的系统实际截图位置。不会写系统截图偏好，不把其他文件夹当截图来源；文件夹书签只存在本机。
- 「重新检查」重新读取位置、恢复目录监听和扫描。暂停时不会启动收录；检查与暂停/继续互斥，检查期间对应按钮禁用，隐藏和历史仍可操作。
- 「文件访问设置」打开系统设置的文件与文件夹权限页；若系统不支持直接定位，回退到系统设置应用。界面文字也保留手工导航说明。实际 OS 页面定位仍待真机验证。
- 隐藏与暂停是独立的持久控制。没有可见截图也没有裂缝，不表示权限失败。截图可能包含 Riftlet；隐藏仍是当前可靠的用户控制入口，不能声称系统自动排除已实现。
- 菜单「打开离线合成演示」启动独立 Simulation 数据目录，不读取真实截图或连接 ChatGPT。几何 JSON 调校保留在工程子菜单，基础设置无需终端或修改文件。

## 当前能力和按需权限

普通模式仍是本地收录，`UnavailableAdapter`、生产开始/完成/安全重试准入保持关闭。窗口明确说明 **授权不会开启未启用的真实截图附加**。ChatGPT Mac、其他浏览器及 Work 不宣传为已支持。

只有独立 `--web-acceptance` 或 `--system-screenshot-candidate` 模式需要 Chrome：启动先调用 `AEDeterminePermissionToAutomateTarget(..., false)`，没有权限则只恢复本地操作事实，不发页面观察、捕获或新输入。只有窗口中的明确权限动作可在状态为未请求时调用 `true`；已拒绝时提供「隐私与安全性 → 自动化 → Riftlet → Google Chrome」恢复路径，绝不重置 TCC。Chrome 未运行时不启动或激活它。权限检查按已观察的 PID + launchDate 复核，不按 bundle ID 启动其他实例。

Chrome 自身「显示 → 开发者 → 允许来自 Apple 事件的 JavaScript」是另一个条件；此实现只解释，不代改、不把 OS 授权当成该设置已开启。是否能读取实际页面仍由现有 Web 实现与证据决定。

**首用原增量与本地 Codex 的最小边界（历史）：** 当时所有 Web/Chrome 源文件、页面协议、正常化器、uploadStarted 判据、profile、Core/SQLite v3、旧 UNKNOWN 与补偿记录保持原样。App 在 Web arm、用户点击选择、后台观察之前新增只读权限检查；鼠标原事件冻结的完整 lease 原封不动通过检查，不重捕获、不延迟重放被拒点击、不新发旧 UNKNOWN。恢复及完成记录读取成功后，才安装一次 armer/watch。这些检查增加了 App 阶段耗时，必须在下一轮原始点击→输入/开始延迟中实际测量，不能沿用此前 3.40 ms callback 当新路径时延。后续候选归一化scope与本地preflight变化见上方最新契约，不影响这些权限约束。

首次设置窗口不会在生成图 `--web-acceptance` 启动时自动抢焦点；本地Codex可从菜单明确打开权限状态入口。真实截图 `--system-screenshot-candidate` 与普通capture一样，首次自动显示一次设置引导，后续日常截图/点击不重开。首次配置不是冷点击验收；完成设置后须重新按实际原点击目标测量。生产准入是另一项独立集成决定，没有可绕过生产限制的配置开关。

## 收录与存储保护

- 单帧 PNG、JPEG、HEIC/HEIF、TIFF；128 MiB、160,000,000 像素、单边 50,000 像素现有上限保留。多页 TIFF、PDF、动图不收录。只有带正向系统截图元数据的新文件才会产生格式/尺寸反馈，普通桌面文件不被误称截图。
- 原文件、私有副本字节、SHA256、编码、颜色元数据和方向标记保留，不进行重新编码。EXIF 旋转仅用于缩略图解码，持久像素尺寸仍是原始编码尺寸，避免破坏已有上传身份。原纵横框可能产生留边，物理显示/命中与 HDR 视觉效果尚未验收。
- 每份新私有复制前，检查同一 staging 文件系统可用块，要求源文件大小加 4 MiB 工程元数据余量。不是容量预留、总保留配额或清理授权；后续真实 IO 失败仍走原持久恢复。已有 journal 的恢复不因新复制余量被阻塞。
- 按需统计媒体、staging、journal、数据库逻辑大小；不轮询解码、不自动删除、不过度宣传可释放空间。所有 SQLite 迁移、媒体与旧操作恢复继续使用既有实现。
- 错误分为来源不可访问、位置偏好不可读、不支持格式、尺寸超限、空间不足、私有写入失败、恢复记录异常、私有副本缺失。对无法读取容量的情况不伪称已证明空间不足；目录访问失败不伪称上传失败。
- 位置偏好只在真实 `ENOENT` 时回退系统默认目录；访问拒绝/损坏不静默回退桌面。切换失败可保留旧监听，但旧目录成功不能消除新位置失败或冒充新目录可读。

## 构建与自动验证入口

```sh
swift test --parallel
swift test --skip-build --filter RiftSetupControllerTests
swift test --skip-build --filter ReleaseCaptureTests
python3 -m unittest discover -s Tests/Packaging -v
bash scripts/build-macos.sh
build/Riftlet.app/Contents/MacOS/Riftlet --first-use-self-check
```

这些是工程/CI 入口，不是普通用户设置步骤。首用自检不打开窗口、不读取真实截图目录、不访问 Chrome、不请求权限；输出 `PERMISSIONS_NOT_REQUESTED; GUI_NOT_RUN`。原生窗口测试只证明软件窗口/控件行为，须读取详细输出确认是否实际执行或跳过。HEIC 编码器及 POSIX 拒绝测试的跳过也必须单独记录。

打包在全新 staging 组装、逐字节核对页面资源与许可、验证 plist/可执行文件结构后 ad-hoc 签名；成功才替换仓库生成的 App，失败保留之前制品。不操作安装目录。保持 bundle ID、数据目录、版本 `0.1.0/1` 与最低 macOS 13 不变；`Riftlet` 为显示名。Developer ID、hardened runtime 发行签名、公证、Gatekeeper 发行验收、自动更新均未实现/未发行，不要求此轮提供凭据。
