# Riftlet — visual and interaction design commission

**Current user interaction overrides this historical visual commission.** Follow [INTERACTION_CONTRACT_2026-10-27.md](INTERACTION_CONTRACT_2026-10-27.md): actual upload start → very fast swallow; confirmed/high-confidence failure → rebirth; UNKNOWN after start → hidden locally; zero visible screenshots → zero slit. This is product direction, not an assertion that any design is approved or native animation is tested.

**Current requested next work: design**, not formal development.

## Challenge
Create an unusually small native-feeling **spatial rift**, not a conventional screenshot shelf with a decorative line. The edge itself should seem to hold and swallow coin-sized screenshots, with the least possible work-space disturbance. The everyday interaction must remain a direct one-click hit on the screenshot; hover-only expansion cannot be a required first step.

## Fixed interaction
System screenshot → a thumbnail emerges from the rift → click once for the **click-time current ChatGPT draft** → immediate light press response → **upon positively evidenced start of upload**, a **very fast swallow animation** completely removes that thumbnail from the rift, regardless of eventual READY. Definitive or extremely high-confidence actual upload failure causes rebirth; post-start UNKNOWN stays hidden in Riftlet's local history, never blindly reuploads. With no visible thumbnails, the slit itself vanishes completely. **Never auto-send.**

## States to visualize at realistic size
Truly empty desktop **without even a slit**, one image emerging from a forming rift, typical **three-image** queue, unusually long **10–12 image** queue, multiple aspect ratios, current ChatGPT web and macOS windows, pointer/click targets, immediate press feedback, **upload-start-triggered fast swallow**, later success with no further visual motion, strong-failure reverse rebirth, and post-start UNKNOWN remaining hidden in internal history. Include explicit single/bulk removal and long-unused auto-archive cases. Also a minimal standalone history/details window without turning the rift into a file manager.

Design at realistic 13-inch MacBook and external-monitor scales. Compare **2–3 genuinely different visual directions**, choose one with rationale, give size/motion/spacing/contrast specifications, and distinguish actual designs from tested running software. No mandatory 48pt/1pt/90%-visible starting values.

Technical constraints to respect: non-activating panels, click-through transparent gaps, fullscreen/multi-Space/multi-screen, system screenshot including its own rift, and correct separation of upload-start positive evidence from eventual READY (READY still needs real target evidence). These remain unresolved engineering facts; don't assert tests passed.

**No product source code, new repository, deployment, or Codex assignment this round.**
