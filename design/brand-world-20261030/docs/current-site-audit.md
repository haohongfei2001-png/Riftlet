## 2. 应保留的基础

### 配色已经有合适的温度

主执行者实景观察到的浅纸色、柔和绿色和少量暖色，适合“轻量、安静、留在边缘”的产品方向。它没有被常见的紫蓝AI光效主导。这不是必须推翻的旧设计包袱；新候选保留青绿方向，改善色彩角色与跨媒介的一致性。

源码也明确将浅底、深色文字、青绿和雾绿色分配为不同角色，而不是把所有元素染成同一种高饱和色。旧站色值只是历史依据，不意味着新候选必须保留每一个数值。来源：[website-product.css](https://github.com/haohongfei2001-png/Riftlet/blob/eba1a4fc77648a665e1d5c1f2609df1314c3b079/website-product.css)。

### 衬线Hero与平静文案已有方向感

既有“不要寻找，位置就在那儿”的表达强调空间记忆，与产品机制有关。衬线标题使工具页面有阅读和思考的气质，不只剩技术感。新方案不需要为了显得更新而改成另一套科技字体；需要让大标题更直接连接“把眼前内容带进对话”，并由演示回答它如何发生。

### 已经有真实可操作的解释

旧站已有合成截图、边缘缩略图、可编辑草稿、语言切换和异常选项；公开状态也写明尚未开放下载。本地演示不会读取真实屏幕或发送消息，旧站并非完全缺乏交互或诚实范围。应继承这些优点，纠正它与最新产品契约的差异。

## 3. 阻碍成熟度的核心问题

### A. split-R把名称读出来了，但机制联系仍需补足

旧图标的青绿底与深色R有较清楚的对比，适合小图标环境。其两段结构可以解释为分界，但主要识别仍是首字母。用户若没有看产品，容易先得到“一个经过分割的R”，而非稳定边界与截图交接的具体关系。

这是创意判断，不是测试证明旧标志无法被记住。更有效的升级目标是让符号、网页构图与实际动作拥有同一关系，并减少额外解释。新推荐Passage因此从内容平面与固定边界构造形态，同时承认单独Logo不必承担整篇产品说明。旧标志来源：[favicon.svg](https://github.com/haohongfei2001-png/Riftlet/blob/eba1a4fc77648a665e1d5c1f2609df1314c3b079/favicon.svg)。

### B. 首屏与下方两套演示争夺叙事中心

主执行者实际浏览观察到Hero中的操作演示，往下又遇到完整桌面演示；HTML也分别提供 `hero-scene` 与 `experience`、两套草稿及对应脚本。两者都说明截图进入草稿，访客重复学习相近内容，页面的后续篇幅却没有同等清楚地推进到边缘的价值、发送控制和当前支持范围。

重复本身不是错误。问题在于它们没有承担明显不同的说明任务。新候选将首屏变成唯一主交互，下方以放大的空间关系、连续流程和控制权推进理解，避免再建另一套与首屏竞争的操作模型。

### C. 旧网站仍将最终ready当作退出条件

这是可直接复核的行为偏差，不能只按视觉喜好处理。旧 `website-product.js` 先创建 `data-ready=false` 的附件，随后把它设为 `true`，再给边缘微图加 `done`；CSS以 `done` 触发移入边缘及透明消失。`website-hero.js` 同样在 `ready=true` 后将按钮设为 `done`。旧首页文字甚至明确写着“图片就绪后，边缘的缩略图才会收起”。

最新正式契约已经要求：**获得绑定原操作的可靠上传开始证据后就快速退出可见队列；最终完成在后台稍后确认。** 网站若继续展示ready后才吞噬，会把创始人已经改正的体验重新教给用户，也可能误导后续实现。新候选因此明确分开click、positive_start、swallowed与ready。

来源：[旧主演示](https://github.com/haohongfei2001-png/Riftlet/blob/eba1a4fc77648a665e1d5c1f2609df1314c3b079/website-product.js)、[旧Hero演示](https://github.com/haohongfei2001-png/Riftlet/blob/eba1a4fc77648a665e1d5c1f2609df1314c3b079/website-hero.js)、[当前交互契约](https://github.com/haohongfei2001-png/Riftlet/blob/98e66a956d55b5fac71718bc627dd89705b2a506/docs/INTERACTION_CONTRACT_2026-10-27.md)。

### D. 旧异常说明没有充分区分开始前与开始后

旧站说明“无法确认结果时，也会保留”，模型将unknown图片继续留在边缘，没有独立表现“已证实开始但后来未知”的隐藏历史状态。它不应被机械沿用为最新契约。当前要求已开始者保持吞噬，在内部待核实；无开始证据者不假装退出。失败后重生和安全重试也不能仅因演示做得流畅，就被宣传为真实产品已经开放。

新网站通过明确标注的条件模拟展示异常，并保留原生准入仍关闭的说明。网页演示的成功不构成平台验收。

### E. 品牌愿景与当前功能仍应分层

旧站已诚实标注未开放下载，但页面后部列出剪贴板、Windows和更多输入框等后续方向。这样的长线想法可以保留在产品资料里，不应分散首次访客对Mac当前截图→草稿流程的理解，也不能当作已决定的近期承诺。

新候选以一个明确承诺组织主页：内容待在边缘，用户主动交接，草稿和最终发送权受到保护。支持范围与开发状态可查，但不让内部工程术语覆盖主叙事。

## 4. 本轮设计的明确取舍

| 保留 | 重构 | 不从官网推导 |
| --- | --- | --- |
| 青绿与浅纸色的温度 | 标志从字母优先转向空间机制 | 已完成正式品牌采纳 |
| 衬线标题与平静语气 | 首页价值表达与中英独立节奏 | 原生平台全面支持 |
| 合成内容、本地交互和不发送 | 两套重复演示整合为一个主模型 | 已解决自然物理首击 |
| 草稿保护、当前用户控制 | 开始与完成分离、UNKNOWN进历史 | 已开放安全失败重试 |
| 未公开下载的诚实状态 | 当前范围、FAQ和补充功能层级 | 已Developer ID签名、公证或公开发行 |

最终判断：旧站已经有值得保留的审美基础，真正需要升级的是**标志与机制的关联、页面信息的推进，以及演示与真实产品契约的一致性**。更换颜色或增加动效数量无法单独解决这三个问题。

本审查不提供转化率、可用性实验或品牌记忆度的虚构分数。推荐方向是本轮基于产品、实际页面观察和创意比较作出的设计裁决；采用与上线仍由创始人确认。
