# Riftlet｜候选采用步骤与交付边界

日期：2026-10-30。对象：Passage / 隙入品牌资产与独立官网候选。**当前交付是供创始人审阅的真实成果，尚未成为正式品牌，未替换线上官网或原生App。**

## 1. 本轮采用边界

本候选保留旧官网与旧Logo作为 `baseline/` 对照，新的网页在 `site/`，矢量与导出资产在 `brand/`。生成脚本、交互状态模型、验证脚本和研究说明随候选保留。

本专项不修改Swift、AppKit、附件适配器、数据库、Chrome集成或真实Mac测试，不向正式PR #1/#15写入产品变更；不合并main，不改变GitHub Pages生产设置、DNS、Cloudflare服务或riftlet.com。独立设计分支 `design/brand-passage-20261030` 与 [Draft PR #19](https://github.com/haohongfei2001-png/Riftlet/pull/19) 已创建，仅作为审阅入口；没有部署到公共生产站。

图标和网页均为候选。建立独立预览、提交设计源文件不等于批准正式采用；创始人的最终决定应指向具体候选版本，避免后续将探索图误当正式资产。

## 2. 最小正式采用顺序

### 第一步：一次明确的品牌决定

审阅三个方向与推荐方案，确认采用的标志、主色、App Icon、字标以及中文／英文H1。允许只批准其中一部分；如需改动，应在同一候选迭代，不重开另一个与正式工程竞争的品牌实现。

采纳后固定 `brand/mark.svg`、`mark-small.svg`、`app-icon.svg`、`wordmark.svg` 为几何来源。网站与App后续只从这组来源导出，不分别手工修形。保留被淘汰方案与基线用于追溯，不让多个方案同时作为正式主标志出现。

### 第二步：独立整合官网

由官网负责人在届时最新main基础上建立网站集成差异，只接入候选静态页面、样式、脚本和必要素材。保留原官网的恢复点，检查实际文件映射和相对链接；不要把研究包、对照基线、测试页及探索图全量部署为生产内容。

当前站点故意采用 `noindex,nofollow` 与 `robots.txt: Disallow: /`，避免候选被当作正式官网索引。正式上线前按真实域名设置canonical、独立中英文hreflang、自引用语言关系与绝对OG图地址，更新分享图、manifest与站点地图；确认后再解除候选索引限制。主CTA仍依据当时真实发行状态选择“体验演示／查看进展”或“下载”，不能因为上线官网而自动改为下载。

中文和英文入口分别校验桌面、移动端、键盘、reduced motion、主题和完整演示。在真实Safari/Chrome对一次关键交互与字体回退进行检查；如果主交付已验证某些相同输入，复用记录，只补当前集成引入的风险。网站可先维持“内部测试中”上线，品牌采用不必等待全部原生发行门槛；但网站不能掩盖这些门槛。

### 第三步：原生品牌资源接入

原生唯一集成负责人在自己的独立变更中导入已批准的App Icon和单色菜单栏标志，使用macOS资源机制核对图标尺寸、透明边距和深浅模式。准备的 `AppIcon.iconset/`、`app-icon.icns` 是输入资产，不是已经测试过的原生集成结果。

检查Dock、Finder、菜单栏、设置“关于”和安装包中的实际显示，尤其16/32px间隙、模板着色和系统缩放。只修改资源及必要引用，不把品牌任务扩成上传、权限或窗口架构重构。网站字体无需移植进原生控件；原生仍可使用系统字体和已有薄界语义色，以避免品牌装饰损害可读性。

### 第四步：确认后再合并与上线

创始人最终确认对应品牌版本、网站集成差异和实际预览。之后由有权限的负责人合并网站变更并使用既有部署路径。若既有域名和部署配置已可用，就不需要额外改DNS或新建云服务。

保留旧版可恢复提交、上线前后的版本记录，以及发布时准确的产品支持说明。这一步才是正式采用与上线；本候选制作阶段没有代行该决定。

## 4. 网页演示与验收的关系

网站使用原创合成素材与页面内存状态，不读取真实屏幕、剪贴板、文件、浏览器账号或ChatGPT对话，不连接真实附件入口，也不执行发送。示例文字与附件状态由本页内存处理；本页不上传，也不主动写入持久存储。pagehide时恢复默认文字并销毁模型、BFCache恢复时重建模型，是页面自身的处理措施，不构成浏览器缓存或表单恢复绝不保留内容的保证。它展示产品机制，不提供原生平台证据。

演示明确分开“点击”“模拟开始”“快速退出”“稍后完成”。开始后结果未知仍隐藏于历史，不盲目再传；失败重生仅是明确标注的条件模拟。演示重开保留textarea和固定旧附件，清理的只是合成新增内容。选择“无”或“磁力吸引”只影响演示入场；不改变上传开始的判据，也不裁决产品默认。

独立内容审查发现的队列不补位和横向压缩问题已按最新源码修正；浏览器实际渲染应以主任务最终QA记录为准。本文件不预先宣称尚未完成的桌面/移动/Safari/VoiceOver测试通过，也不把静态脚本通过称为完整无障碍认证。

## 5. 尚需保留的诚实限制

- **品牌认知未经用户实验。** 已有形态、尺寸与一致性评审不等于用户记忆度或商业转化验证；可在采用前让少量目标Mac用户看首屏后描述产品，确认是否理解“截图→当前草稿→不自动发送”。这应是一次有针对性的验证，不必成为持续重开设计的理由。
- **图形相似性审查不等于商标法律清查。** 本方案没有复制竞品资产；若决定长期商业使用并注册商标，应按实际地区和类别另行查询。不要把未发现明显相似升级为全球唯一。
- **原生Dock与菜单栏未在本专项实机接入。** 已导出多尺度PNG、SVG、ICO与ICNS；实际系统效果属于上述第三步。
- **网站艺术示意不是App录屏。** 放大空间关系可帮助理解，但不能把画面中的编辑器、合成桌面或装饰排版当作新原生UI。
- **网站演示无持久化或服务器。** 其本地状态与“原生历史本机保存”是不同事实；不添加虚假注册、邮件订阅或反馈已提交状态。

## 6. 给后续执行者的最短交接

采用获批几何，保留旧版恢复点；官网只整合 `site/` 所需文件；原生只整合品牌资源；按当前真实发行状态更新CTA与支持说明；完成实际集成的有限验证后，由创始人确认合并和上线。无需重建截图机制、另起产品分支、修改DNS或重新设计整套原生体验。
