## 2. 坐标、单位与屏幕选择

### 2.1 唯一坐标规则

设计文件中 `1 CSS px = 1 logical pt`；导出的 100% 评审图不乘 Retina 倍率。原生使用 AppKit screen points，尺寸不随 backingScaleFactor 乘大。

令选定屏幕的 `visibleFrame` 为 `F`，其宽高为 `W/H`。设计图以 F 左上角为原点，x 向右，y 向下。原生转换：

```text
screenPoint(x, y) = (F.minX + x, F.maxY − y)
screenRect(x, y, w, h) = (F.minX + x, F.maxY − y − h, w, h)
```

不要假设主屏在(0,0)、第二屏只有正坐标，也不要用全局主屏高度翻转另一块屏幕的 y。区域、窗口来源 rect 必须携带对应 display ID 和坐标系；不要从截图文件到达时的鼠标位置猜来源。

保留现有屏幕选择顺序：用户设置的稳定 display ID → 当前可用主屏 → 首个可用屏。原生重新获得有效 F 后重建几何；断屏、唤醒或比例变化取消未完成视觉插值，不回放截图或原点击。

### 2.2 backing 与绘制

图像缓存继续按显示尺寸乘实际 backingScaleFactor 解码，不重写原文件、不改上传 hash 或 ICC。绘制层和输入窗口用同一份逻辑几何，不各自独立舍入。窗口/视图转换使用 AppKit 的 `convert`、`convertToScreen` 和 backing 转换，避免手工乘 scale 后又乘一次。

主边界及 input rect 的边缘在同一 backing 坐标空间对齐；不要逐帧重新 round 造成0.5pt跳动。本轮推荐裂缝使用精确一物理像素单边：`lineWidth = 1 / backingScaleFactor`（1x为1pt，2x为0.5pt），100%逻辑图稿按Retina的0.5pt呈现。提高对比度时使用1pt实线（Retina为2px）。原0.7pt只属于来源基线，不再是新设计值。只画这一条边，不叠加内亮边、blur或glow。所有状态保持同一固定像素对齐策略。

Apple 的坐标 API 分别处理本地视图坐标和 backing pixels；材质也会随系统设置变化，不能把浏览器 blur 的像素数当作 AppKit 固定实现。[坐标转换依据](https://developer.apple.com/documentation/appkit/nsview/converttobacking(_:)-3zors) · [原生材质依据](https://developer.apple.com/documentation/appkit/nsvisualeffectview)

## 4. 裂缝几何与队列

### 4.1 位置与容量

固定遮挡平面 `E = F.maxX − 14`。第一张图片中心 `C0.y = F.maxY − 202`；第 i 张中心 `Ci.y = C0.y − 60i`。第一槽不因当前可见数量变化而移动；不随图的横竖比改变 pitch。

入口 anchor 在第一槽中心上方66pt：`A = (E − 18, C0.y + 66)`。因此入口右缘和裂缝共用一个平面，入口默认玻璃36×36；展开向上至132高。在设计顶坐标下，第一图中心202、入口中心136、三点中心40，展开顶部22。

底部安全线 `B = F.minY + 12`。以行高56计，未分页容量：

```text
capacityWithoutPager = max(0, floor((C0.y − B − 28) / 60) + 1)
capacityWithPager    = max(0, floor((C0.y − B − 28 − 28) / 60) + 1)
```

只有总数超过不分页容量时，才保留分页器的20pt高度+8pt间隔，并使用`capacityWithPager`；每次窗口/显示尺寸变化重新计算。切换分页时不因当前页剩余少量条目而改变capacity。若屏幕连一个完整可见行和入口都放不下，保留菜单栏历史入口并隐藏边缘组件；不生成越界或零尺寸命中窗口。

分页器在最后一个槽位底部8pt处，20pt高，最小52pt宽，右缘E；显示“1–8 / 12”这类可读范围，左右箭头是独立可见控制。翻页不改变原队列顺序或资产身份。最早/最新与历史仍可访问。新增截图不在鼠标按住、已接受选择或补位时突然切页；在安全边界提示并定位新页。是否自动定位最新页沿用现有工程行为，但不可打断拥有指针的原资产。

### 4.2 微图与编号

保留72×56等比fit，不裁掉截图来制造统一横图。`s=min(72/w,56/h)`，完整图`(w·s,h·s)`，露出宽`0.75·w·s`，隐藏25%。图片可见右缘永远在E。

普通编号在图片可见左缘左侧8pt，垂直居中。编号文本11pt等宽数字，实际原生字形测量决定宽度；所有两位数字保持稳定右对齐。编号不是永久asset ID，也不代替历史标识。

当图片露出宽<24pt，或fit高度<20pt时，编号升级为**可见的哑光小垫片**：默认22×24pt、radius5、surface×0.80、1px separator边；编号仍11pt。三位以上宽度取`max(22, ceil(measuredTextWidth)+8)`，只向左扩，不挤动图片或遮挡平面。垫片为真实可见点击区域，不把周围透明区域一起变成按钮。

图片矩形以及普通编号的可见文字矩形/极端比例垫片是两个独立输入岛。两岛之间的8pt空隙、图形的行包络留白、行间空白、外侧14pt条带、线和阴影都不创建输入面板。PNG本身的透明像素仍遵循图片矩形输入岛，除非后续另行实现与验证逐像素命中；本规格不声称已有逐像素穿透。

编号垫片是本轮新增可达性提案，需要在1:8长图和8:1宽条的100%图中明确展示，不能只在放大的组件页展示。

### 4.3 完整预览

本轮新增推荐：在同一张图的可见输入岛持续hover450ms后打开完整图peek。预览不进入上传路径，不更换焦点、不读取浏览器、不自动复制。最长边限制320×240pt等比fit，外框内边距8、radius10，距该图左侧12pt，优先向左展开，在F内至少留12pt。

预览NSPanel和其全部内容一律`ignoresMouseEvents=true`，不允许移入预览后把其变成可点击大区域。hover离开源图100ms后以80ms淡出；回到源图可取消关闭。按下任何原截图、开始输入、翻页、隐藏、归档、变屏或打开菜单时立即关闭且取消计时器，不能等待淡出后才响应原点击。

原AXPress始终表示“附加”，不改变成预览。AX提供独立自定操作“查看完整预览”；历史列表获得键盘焦点时可用Space预览。**不监听全局Space，不让非key裂缝抢走聊天输入。**设计原型的显式“预览”测试按钮属于模拟控制，不是产品新按钮。

## 5. 预测式截图入口

继承独立入口的36pt主控、30pt上方独立输入岛、32pt槽距、17pt锐利图标、1.65pt线宽。折叠面36×36，展开面36×132，圆角由10插值到12。只有一个连续玻璃面；活动取消盖片30×30、radius8。

### 5.1 固定槽与取消

固定指同一会话中不换位。会话开始时根据默认模式建立以下表（从底部到顶部）：

| 下一轮默认模式 | anchor | near | far | more |
| --- | --- | --- | --- | --- |
| 窗口 | 窗口 | 区域 | 全屏 | 三点 |
| 区域 | 区域 | 窗口 | 全屏 | 三点 |
| 全屏 | 全屏 | 区域 | 窗口 | 三点 |

点击折叠入口即执行默认模式，不等180ms展开结束。展开后点击另一模式立即切换语义，取消盖片100ms移动至该槽；所有基础图标、点击槽、原来源坐标不变。活动槽的动作已经是取消，不等盖片跑到位才更新。

截图完成后维持展开、当前模式及会话；不自动收回。X或Escape明确取消后，180ms收回底部默认入口，保留当时光学alpha；附近不闪灭，远离扩大退出区才消失。设置默认模式只影响下一会话，不能在进行中的指针下改槽序。

### 5.2 光学和预测

保留`ScreenshotEntryOptics`的双包络与预测函数作为实施基线，不另造一套靠hover延时才显示的模型：glyph full/enter为屏宽0.35/0.60，surface full/enter为0.08/0.46，退出范围1.5倍；预测上限700ms、衰减240ms；线条比玻璃更快上升。参数仍需实际桌面调校，但没有必要重做已批准运动机制。

图标不缩放、不模糊、不滑入，也不随当前OS更换成不同轮廓。预测只控制显示，不获得捕获或上传授权；鼠标从远处快速接近可以提前露出完整相机线条，玻璃延后。当前队列输入范围周围的availability抑制保留，不让相机与正在操作的微图竞争。

入口四个输入岛各自保持真实原生矩形；玻璃、阴影和其间缝隙穿透。原生分支的角色/几何命中不依赖动画alpha；实现时保留其已有事件门，另外验证完全不可见时不会留下不预期的交互。设计不通过改变alpha阈值来引入点击延迟。

## 6. 动态时间表与空间因果

所有t使用单调时钟，`p=clamp((now−start)/duration,0,1)`。同类视觉中断从presentation/current value开始；禁止一组未取消的异步回调在新会话之后继续修改窗口。**精确动态参数以[motion/MOTION_SPEC.md](motion/MOTION_SPEC.md)为唯一数值来源**；下面是同一模型的AppKit接线摘要，不另造一套曲线。outCubic记为`1−(1−p)³`。

| 动作 | 推荐时间 | 曲线 / 规则 |
| --- | ---: | --- |
| 无入缝动效 | 0ms | assetReady后直接到最终槽；只控制arrival |
| 磁力吸引 | 560ms | 下述四相；来源不可用时0ms |
| 按下 | 60ms | 向内1.5pt；outCubic |
| 普通松开/无效点击复位 | 80ms | 回0；outCubic；无吞噬、无成功色 |
| 真实开始吞噬 | 120ms | `offset=56×p¹·³⁵` pt；固定平面遮挡，严格事件触发 |
| 补位 | 160ms | outCubic；原指针与选择安全边界之后 |
| 获准明确失败重生 | 180ms | 从固定边缘向外至槽位，easeOut；当前只在模拟中展示 |
| 入口展开/收回 | 180ms | quintic `6p⁵−15p⁴+10p³` |
| 取消盖片换槽 | 100ms | 同quintic；角色立即生效 |
| hover预览进入 | 80ms | 仅alpha；450ms停留后 |
| hover预览离开 | 100ms延迟+80ms淡出 | 原点击等高优先事件立即关闭 |

“无”关闭截图入缝动画，不关闭真实开始吞噬，不关闭需要的点击反馈，也不把UNKNOWN显示成完成。这一点明确覆盖旧两模式设计稿里将none扩大至所有位移的写法。

### 6.1 磁力四相

来源必须是已知、同屏、可靠的捕获源矩形。没有来源、来源过期、跨屏映射不可靠、刚睡醒、用户减少动态，直接降级为无；不从鼠标或屏幕中心捏造来源。

1. **0–123ms：源头收束。** 在可信来源中心，以最多240×150pt的等比装饰副本开始，用outCubic收束到58×46pt包络内。只用一张等比图，不扭曲、不翻转。原件和收录已经存在，不等动画生成文件。
2. **123–224ms：定向微颤。** 保持小图尺寸；沿源中心至遮挡面的单位向量，位移`sin(3πp) × sin(πp) × (1−p) × 1.2pt`。这是有界阻尼包络，实际峰值小于1.2pt；无随机抖动、长循环或旋转。
3. **224–484ms：定向吸引。** 沿直线向固定遮挡面加速，位置进度`p²·²⁵`，尺寸从58×46包络内的等比图连续变到72×56包络内。终点中心为`(E + fittedWidth/2, rowCenter)`，此时整张副本完全在遮挡面之后，可见面积为0。
4. **484–560ms：反向显露到槽位。** 最后76ms以outCubic，从完全遮挡位置向左露出至75%的固定量。两段交接处均没有可见图像，完成空间交接；不加弹跳、闪光或第二次落位确认。

四相遵循同一确定性模型。第3→4段在完全遮挡之后反向，**不宣称物理轨迹C1速度连续**；保证的是交接处可见面积连续且为0，没有公开可见的瞬移。不要把反向显露误实现成仍有半张可见时的掉头。

assetReady立即更新收录模型和内部历史；飞行ghost全程无输入窗口、不占用全队列transition锁。新槽已有可见编号锚点；其输入响应不等待560ms。点击新编号时立即结束arrival到稳定呈现，再把同一个原生事件交给现有选择通路一次；不重新合成点击。既有行始终可操作。若真实uploadStarted先于arrival结束，终止arrival，由已提交状态启动120ms吞噬；不能晚到的arrival再次把已吞噬图片画回来。

### 6.2 吞噬和成功分离

按下、排队、prepare、输入、placeholder、倒计时、图像本身淡出都不是start证据。只有Core投影来的同一asset/operation/visibilityRevision上的`.swallowed(.uploadStarted)`才触发吞噬。保持图像沿自身横向移入固定平面；数字可在后半段淡出，输入窗口于交互资格失效时停止接收，不等视觉尾帧继续可点。

120ms完成后关闭原图绘制和输入窗口，剩余队列安全补位。最终succeeded后台记录，没有第二次吞噬、绿色勾、声音、Toast或自动发送消息。合成原型可以显示开发用事件表，但这些不进入产品界面。

### 6.3 减少动态

系统Reduce Motion覆盖所有设置：arrival立即最终呈现；入口高度/取消盖片位置直接切换，光学alpha可≤80ms；按下用明度/边框响应，不平移；吞噬仅≤80ms淡出；补位直接新位置；失败直接重现。不得以“把560ms压到80ms”保留高速空间飞行。

监听系统无障碍显示选项变化；变化发生于动画中时立即落到当前事实对应终态，取消旧回调。减少透明度使用不透明surface；区分颜色开启时增加文字/形状，不靠红绿二色。依据：[减少动态](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducemotion) · [减少透明度](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducetransparency)。

## 7. 呈现状态转换

| 事实 / 输入 | 裂缝呈现 | 说明与可用操作 |
| --- | --- | --- |
| 0张可见图 | 无线、无微图、无无效输入窗口 | 预测入口只在其既有意图显示规则下出现，不能充当空裂缝常驻装饰 |
| 新assetReady | 入缝或直接落位 | 原图保留、无上传 |
| 原点击按下 | 轻压 | 不切浏览器、不抢编辑器焦点 |
| 点击时无有效ACK/目标 | 保留原图、复位 | 按闭集原原因说明；不吞噬、不自动重新获取目标后回放 |
| 接受后在FIFO等待 | 保留原图，可显示小等待记号 | “已接收，正在等待附加；本次尚未上传。”只用于确切仍未输入的等待边界 |
| prepared投影 | 保留原图 | 使用中性“附加处理中，结果尚待确认”；不持续声称尚未输入 |
| 输入前确定取消/超时/原目标变化 | 原图保留 | 精确原因，下一次必须由用户新点击 |
| 严格uploadStarted | 120ms吞噬 | 不等最终完成；不改其他截图身份或目标 |
| 已吞噬后UNKNOWN | 保持隐藏 | 本地历史“结果待核实”；无新输入/重试/恢复按钮 |
| 独立succeeded | 保持隐藏 | 历史可读“已附加”；不弹成功消息 |
| 明确且获准安全失败 | 普通图片重生 | 用户新点击可再试；当前安全失败/重试准入关闭，仅目标状态模拟 |
| 隐藏/暂停 | 各自独立 | 隐藏不停止收录；暂停不删除/隐藏已有图 |
| 归档/移除 | 安全边界退出可见队列 | 原图/私有副本/聊天附件均保留；eligible项可由历史恢复显示 |

等待说明优先采用同一微图附近的小型非激活说明：最大240pt宽、13/18文字、12pt边距、radius8、距图左12pt；仅主动hover/AX读取或无效点击短时可见，不遮住邻图、不拦鼠标。行上可以用不旋转的小短线区别已接受等待，不能使用虚假百分比或每图常驻大spinner。若说明没有owner/revision匹配，则不展示旧原因。

取消上传前等待属于现有原操作撤销；只有还没有input intent的操作可取消。UI不能以关闭tooltip/动画作为取消成功。输入后没有新的“撤回上传”能力，不伪装成可撤销。

## 8. 辅助窗口与完整信息架构

下面尺寸均是**设计可见窗口外框尺寸，包含原生标题栏**。AppKit需用相应styleMask的frame/content转换，不能直接把这些值当现有contentRect。原型的交通灯仅作外观占位，原生保持系统交通灯、标题栏拖拽和系统菜单行为。

| 窗口 | 初始外框 | 最小外框 | 结构 |
| --- | --- | --- | --- |
| 首次使用 | 560×520 | 520×480 | 3屏依次呈现：认识→连接与权限→开始；固定底部动作 |
| 设置与运行状态 | 680×520 | 620×480 | 156侧栏+内容；状态不等于权限 |
| 内部历史 | 760×560 | 680×480 | 152分类栏+260列表+剩余详情 |
| 反馈 | 600×540 | 560×500 | 编辑主任务、同窗本机记录折叠区；本地状态持续可见 |

辅助窗口允许激活和成为key，边缘裂缝与入口不激活。后台刷新任何窗口内容都不调用show/activate。

### 8.1 首次使用

采用与本轮`windows.js`一致的三屏流程，始终在同一个560×520外框内切换；顶部进度依次是“认识 Riftlet”“连接与权限”“开始使用”。不是一页堆叠三个步骤卡。标题栏和首屏显式标“内部候选”，不作生产宣传页面。

1. **认识 Riftlet。** 标题“截图一次，点击一次”，说明“截图自然地停在桌面边缘。需要时，点一下，进入当前聊天草稿。”以克制的截图→边缘示意和三条原则说明系统截图、只附加不发送、原图及本地历史保留；主按钮“继续”。
2. **连接与权限。** 标题“连接你已经在用的工具”，只显示系统截图位置与Chrome当前草稿两张权限卡，卡间12pt。实际路径只在本机呈现；当前截图位置不可读时提供主动授权。Chrome Automation与Apple事件JavaScript要求分别说明；没有Chrome时让用户自行打开，不切后台聊天。权限允许不等于目标已经验证。主按钮“下一步”；不强制授权才能继续本地使用。
3. **开始使用。** 标题“下一张截图，从这里开始”，说明回到受支持的Chrome普通已有对话、使用另一张新截图。用“出现→点击→继续”解释动作，直接显示当前候选支持范围与仍关闭的能力。主按钮“开始使用”关闭引导，不自动截图、输入或发送。

三屏均保留“稍后设置”与原生关闭；关闭不授予权限，也不要求先真实上传。底部持续说明“不发送消息，不删除原截图”；当前阻断原因不可折叠隐藏。首次自动出现一次，以后从菜单重开。普通capture模式明确说“当前仅本地收录”，不把上传关闭包装成权限故障。

### 8.2 设置与运行状态

侧栏每项36高，内边距12：运行状态、截图入口、显示与动效、隐私与存储、关于与支持。主区边距24，行高至少44，section间距24。

- **运行状态**：收录开关、实际来源访问、裂缝显示、当前能力、待核实数量分开；暂停/显示用独立控件。当前异常与准确下一步在最上；不显示笼统“所有就绪”。
- **截图入口**：默认模式窗口/区域/全屏、启用已批准入口；默认模式改变下一会话。系统截图路径保留。
- **显示与动效**：入缝只两项“无 / 磁力吸引”；演示使用合成图；无正式默认裁决时沿用现有用户选择或明确首次选项，不暗中宣布磁力为默认。快吞噬为已批准行为，不与arrival合并开关。显示器选择绑定稳定ID。
- **隐私与存储**：闲置归档时长沿用可调值，24h标为当前设置而非强制政策；提供关闭与原有小时输入，不创建新的删除策略。用量按实际测量显示“约/至少”，不能当可释放空间。
- **关于与支持**：版本/内部候选、真实支持范围、打开反馈、已有诊断入口。产品日常页面不展示operation hash或CI编号。

### 8.3 历史

152pt侧栏列出全部、待核实、已附加、已归档、已移除，明确失败可以作为独立过滤入口但不能把输入前取消混为上传失败。260pt列表以64pt行、预览56×44、时间13/18、状态11/15；选中背景accent低透明。列表可以当前200条分页，搜索框提示“搜索本页”，不得冒充全库搜索。

右侧详情采用完整fit预览、尺寸/时间和一段状态解释；主要动作来自Core资格。待核实显示“结果尚不能确认；不会再次附加”，不提供重试、解锁或强制恢复。used显示后台记录，无庆祝。未输入且可恢复的archived/removed显示“放回裂缝”；按钮不会立即上传。Finder定位、移除可见项和页码必须保留；双击不上传。

Space只在历史列表已有键盘焦点时显示本地完整预览；Escape关闭预览。文本编辑焦点中的Space/Enter保持系统文本行为。无多选删除、OCR、云同步或新管理系统。

### 8.4 Feedback

主编辑区：20/26标题“哪里不顺手？”；13/18简短提示；类型选择；正文编辑区至少150高（外加类型/提示与字数行）、内边距12、13/18系统文本；“附带技术诊断（仅本次）”默认关闭；旁边“预览”；底部本地状态与两动作。

endpoint=nil时主按钮为**“保存待发送”**，辅助状态“接收服务尚未配置；当前不会上传”。草稿保存成功显示“草稿已保存在本机”；enqueue成功显示“已保存待发送”，不能“发送成功 / 已收到”。次按钮“保存并关闭”。此文案不改变FeedbackEngine。

“本机反馈记录”采用同窗折叠区，与本轮`windows.js`的`details`结构一致；默认收起，显示记录数量，展开后在同一可滚动内容区浏览，不切换次级页或重建编辑草稿。每条记录提供正文、状态与对应生命周期动作：从未发送的queued为“取消待发送”；删除申请中为“等待删除确认”；cancelled/deleted才有“移除本机正文与凭证…”。确认sheet描述只影响这一条反馈，不影响截图。折叠、展开及后台刷新仍须保留编辑焦点、选区与IME组合。

保留120ms autosave、revision、不重入保存、IME marked text检查、每次关窗保存、退出前锁定、诊断冻结快照、独立SQLite/Keychain和所有白名单。Return永远不提交正文。禁止为视觉演示创建endpoint或云端资源。

### 8.5 菜单栏

原生NSMenu，使用既有品牌资产或文字，不另批准logo。第一行显示“Riftlet · 内部候选”，随后当前简短状态；常用动作顺序：截图历史、暂停/继续收录、隐藏/显示裂缝、清空可见队列（保留文件）；分隔后设置与运行状态、反馈、支持范围；底部退出。合成/工程入口仅在内部构建组，不混入普通设置。

退出保持原有反馈保存和Core退出顺序。关闭窗口不退出App。隐藏/暂停持久状态仍由原有Host完成，视觉开关的动画不先假装存储成功。

## 9. 原生层级、事件所有权与可访问性

层级从低到高：底层App → 裂缝装饰与微图绘制 → 图片/编号输入岛 → 入口玻璃与图标 → 入口独立输入岛；peek/短说明处于可读层但完全忽略鼠标。不要用同一巨型overlay接管整个桌面。

微图绘制行仍是唯一AX元素；图片和编号输入岛对AX隐藏，避免一张图朗读三次。标签“截图3，可附加 / 等待附加 / 结果待核实”等由闭集状态生成，不能附带浏览器秘密或原始错误字符串。选中数量、pending状态不进行每帧announcement。必要错误可在操作后一次性通过AX提示；成功保持安静。

原NSPanel继续nonactivating、不能key/main；clickCount、doubleClickInterval、4pt旧位置保护、visibilityRevision、owner、原窗口身份与事件时间保留。新预览、垫片和分页不拥有上传授权。未解决的noACK冷首击不得靠hover替点击或延迟重放修饰成成功。

任何layout变化在mousedown/已接受选择拥有资产时推迟；输入岛移动与绘制必须同源。可见性变化已提交后继续观察旧operation，不能为了补位把旧operation绑给新行。隐藏/退出/变屏撤销视觉计时器，并保留原后台观察，不清UNKNOWN。

## 10. 实施验收与交接顺序

本轮不运行或改写正式App。下一阶段先确认本设计方向，再按[SOURCE_DELTA.md](SOURCE_DELTA.md)逐层实现：token与辅助窗口→裂缝几何/命中/预览→继承预测入口→两模式arrival接线→真实Mac的局部视觉交互验证。每批只修改必要文件；Main做最小组合，不整文件覆盖。

只验证改变带来的具体风险：100%逻辑尺寸下明暗/杂乱背景、1366×768/1440×900/1728×1117、横竖长宽混队列、0/1/3/12图、鼠标按住期间补位、双击原位保护、透明岛间穿透、Reduce Motion/Transparency/Contrast、Feedback关开/IME/未配置状态。源代码与浏览器原型不能替代macOS物理鼠标、WindowServer、Spaces与权限实测。

真实截图上传闭环已经有既有证据，本设计实施不以重复上传旧图作为验证方式。新视觉只有在获准的新样本上进行有限体验验证；旧H/F/UNKNOWN不重传、不清除、不解锁。正常生产、安全失败/重试与反馈云端继续关闭，直至各自独立工程准入改变。
