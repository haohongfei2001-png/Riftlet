## 2. 不能改变的底层事实

- 保留 Core、Capture、SQLite v3、原始媒体、hash、operation／attempt、完整目标、ACK先于原点击、唯一输入、历史与审计。
- 保留原 `selection owner`／`visibilityRevision` 保护；异步拒绝和 prepared／cancelled 文案不得覆盖新状态。
- 保留 `diagnostics.record(.selectionRejected)`、assets／operations 投影、`uiProjectionDeferred`、Feedback初始化、菜单、保存和退出逻辑。
- 仍只有真实已获准 `uploadStarted` 使微图退出；最终 attached证明与 succeeded持久化独立；开始不是成功，动画完成不是事实。
- 未开始不得假吞噬；开始后的UNKNOWN保持内部隐藏；旧UNKNOWN只读、不可重复输入、不清库、不解锁。
- 真正失败重生是目标产品契约，但真实安全失败／重试准入仍关闭。本设计不更改任何准入profile或失败阈值。
- 普通capture仍关闭生产上传；受限候选范围不扩大；不要求浏览器扩展，不自动发送消息。
- Feedback的SQLite、Keychain、隐私白名单和主动诊断保留；endpoint仍未配置，不部署Worker、不投递真实Issue、不显示云端提交成功。

## 3. 五阶段最小实施顺序

每阶段在独立 worktree 完成可审查的小变更；正式工程唯一负责人合流。既有同时进行的工程修复继续独立，设计实现不得抢写他们的App文件或重置来源。以下是视觉实施顺序，不是要求重新建立上传计划。

### 阶段一｜统一 tokens 与原生辅助界面

**目的：** 先让首次使用、日常状态、设置、历史、Feedback和菜单拥有一致的字体、间距、颜色角色与操作层级。

**主要接入点：** `RiftSetupController`、`SetupPresentation`、`RiftHistoryController`、`HistoryPresentation`、`FeedbackWindowController`及App菜单呈现；共享视觉tokens放在UI层，业务模块不依赖新的UI类型。

**执行要求：**

1. 首用与日常状态分层，保留实际截图来源、目录访问、权限、暂停、隐藏、无图和当前上传模式的区别。
2. 权限按钮只由用户主动触发，不随窗口打开、动画或状态刷新自动申请；刷新不得抢前台或改变当前草稿。
3. 历史继续使用现有查询与安全操作，改善预览、中文状态与信息密度；“查看原图”“在Finder显示”“移出可见队列”不得混同重新上传或删除原件。
4. Feedback保留关闭／重开草稿、取消、删除、退出保存及本地待发送；未部署服务时绝不出现“开发者已收到”。
5. 采用系统字体与原生窗口行为，不嵌入WebView还原HTML，不复制网页CSS作运行依赖。

**完成证据：** 100%逻辑尺寸的浅／深两套辅助窗口；窗口缩放与长文案无裁切；键盘顺序和草稿回开可操作；业务状态投影与原有模型相符。仅为视觉修改时不要重跑已经完成的真实截图上传。

### 阶段二｜裂缝几何、可见命中与可选完整预览

**目的：** 让日常三图、长队列和极端比例在真实桌面尺度上可辨、可点且不侵占透明区域。

**主要接入点：** `RiftConfiguration`、`RiftLayout`、`RiftPanelController`、`RiftDisplaySelection`、`ThumbnailCache`。沿用已有输入岛、非激活面板和selection gate。

**执行要求：**

1. 采用本轮推荐的72×56等比包络、25%遮挡、60pt行距、8pt编号间隙。裂缝线宽为 `1 / backingScaleFactor` pt（2×=0.5pt，1×=1pt）；旧0.7pt不再是最终token。不重编码或裁剪资产本身。
2. 队列首槽稳定放于入口下方；只有溢出时在底部预留20pt导航＋8pt间隔。溢出导航改变可见窗口，不丢资产、不变更真实队列顺序；新图可达与旧图位置记忆同时明确。
3. 极端长宽比使用可见22×24编号标记作辅助命中，不用覆盖整行的透明44×44窗口；图像、编号、间隙和真正透明像素分别定义。
4. 可选450ms悬停完整预览最大320×240；立即单击仍直接走原选择，绝不等待预览。按下、吞噬、隐藏、换代或目标失效及时撤销旧预览。
5. 完整预览为显示层，不能成为新点击目标选择器、重新读取浏览器、更新ACK或触发上传。提供AX自定义动作“查看完整预览”；不得拦截全局Space或AX按钮的默认Space激活。仅在历史窗口条目已聚焦时提供Space预览。
6. 保留原mousedown资产、owner、revision与双击抑制；补位结束再改编号；异步回调不得复活移除项。
7. 零可见图没有任何裂缝残线；暂停、隐藏与归档不混淆；hover／按下／菜单／动画仍保护闲置归档。

**完成证据：** 实际可用屏幕的2／3／12+图，横／竖／长图、明暗背景与滚动条边缘；图片和编号各一次有效点击，空隙透传；按下跨补位与重复点击不误选。浏览器原型测试只能证明几何逻辑，不替代AppKit穿透和WindowServer测试。

### 阶段三｜预测入口按真实祖先组合

**目的：** 正式继承已交付入口，与同一裂缝视觉和空间规则接合；不重新开发第二套入口。

**主要来源：** `codex/predictive-capture-entry-20261028`固定读取5d6a683；实施时重新核对最新实际HEAD和PR #11。主要组件为`ScreenshotEntryController`、`ScreenshotEntryModel`、`ScreenshotEntryHost`及既有Capture接线。

**执行要求：**

1. 按实际Git祖先做最小合流，正式Main截图逻辑与Feedback完整保留；不能整文件覆盖或重复fa74／Feedback提交。
2. 保留36×36／36×132单玻璃形态、固定三模式＋三点槽、相机线条提前稳定、两条独立alpha及预测迟滞。
3. 切换模式只改变取消盖片和即时语义；每次会话的槽位按默认模式确定后冻结，不要求不同默认设置采用同一排列。槽位不换、动画不阻塞输入；默认设置只影响下一次会话。
4. 截图完成后继续保持展开与当前模式，只有主动取消结束；取消途中可反向，不能闪灭后重现。
5. 捕获选择层展开时，队列仍可操作；点击图片不能穿透成新截图，入口与队列不能争用同一鼠标区域。
6. 仅使用正式实现的安全捕获结果导入与权限流程，不把浏览器canvas当原生截图，更不改写普通系统截图习惯。
7. 短屏、侧置Dock、多屏与不同缩放按精确约束回退，不能简单缩放全部界面或把面板挤出visibleFrame。

**完成证据：** 一会话内三模式多次切换保持坐标；成功后继续捕获；X／Escape真实退出；打开队列单击不额外捕获；多屏／缩放／权限的实际结果按范围记录。未验证普通系统入口的自排除不能宣传保证。

### 阶段四｜复用原生入缝层，对齐独立动态

**目的：** 接入“无／磁力吸引”，使源头→裂缝具有连续空间因果，同时保持既有上传与点击响应。

**主要接入点：** 已交付 `codex/arrival-none-magnet-native-20261028` 的Presenter、源元数据、偏好和设置。固定读取 `d552a7388af3890bf693bb3fb24f4b8fc5bc12e7`，详见[并行原生分支补充审计](research/arrival-native-branch-check.md)。不新建第二套Presenter、业务asset、数据库、上传Coordinator或成功状态机。

该分支现有440ms单sprite实现是工程候选，不是本轮560ms四相推荐。其none同时取消press／swallow、补位均0ms的接线须按本轮明确的独立语义审查调整；不能把“移除动效”当成取消既有点击保护。源空间元数据的OS-build准入仍为空，设计稿不能开放它。与预测入口合流必须按真实共同祖先1920e056处理共享Main/UI；这次设计分支不执行合流。

**执行要求：**

1. 模式只有none／magnet；默认模式未被批准，首用选择与保存真实偏好，不以演示初值自动决定产品默认。
2. “无”仅取消入缝装饰。uploadStarted后的快速吞噬与补位仍遵循独立规格；系统Reduce Motion作为显示覆盖，不是第三模式。
3. 磁力从`assetReady`起计算：凝缩、克制蓄力、近直线定向加速、穿过固定遮挡面。不做全屏闪烁、粒子、弹跳或随机漂浮。
4. 源矩形只接受可信且可转换的当前来源；无信息、陈旧、跨屏未验证、坐标越界或overlay失败，该次立即静态落位，保留用户偏好。
5. assetReady即进入真实队列并可点击；装饰不可延迟原输入窗口创建、选择、prepare或上传。点击时立即取消该资产飞行并使用原选择身份。
6. 一次最多一个源端飞行；新图只收束旧装饰，不丢资产、不让队列等待。隐藏／销毁／换代的旧回调不可复活图像。
7. 源复制窗口完全穿透且AX隐藏；不得为动效截获原系统快捷键、读取新桌面像素或更改原图字节。

**完成证据：** 真实已知源／缺失源／不可信跨屏、连续assetReady、飞行中点击、隐藏与唤醒；测量assetReady→可点独立于装饰时长。原型560ms演示不构成真实截图收录速度承诺。

### 阶段五｜原生100%体验与发行质量复核

**目的：** 比对批准后的设计规格与实际App，不重复已有上传证据，不以常规测试继续推迟创始人体验。

**执行要求：**

1. 在实际Mac按100%逻辑尺寸对照图稿：原生字体、玻璃、明暗、Retina像素对齐、极端比例、侧置Dock、菜单栏与不同屏幕。
2. 检查VoiceOver、键盘访问、减少动态、提高对比度、透明空隙、窗口关闭／重开、实际首次使用权限路径。
3. 只补本次实际改动带来的真实风险：焦点保留、旧按下身份、入口与队列层级、飞行装饰穿透、磁力缺源回退、Feedback草稿生命周期。
4. 正式源码组合后运行应有Native／Feedback CI与非作者审查；保留固定来源审计，不禁用、不把批准UI修改泛化成任意白名单。
5. 制作更新后的真实内部候选App及明确入口；普通模式关闭生产上传，候选数据根、旧UNKNOWN与所有历史保留。
6. 验证完成即交给创始人真实使用，以观察到的问题排序；不要求重传H／F、清空数据库、补造uploadStarted或再做已通过的上传机制实验。

## 5. 已知限制必须继续传递

- 当前已知H限定成功是预绑定软件CGEvent样本；人工物理鼠标与无ACK冷首击不能被本设计重新标为通过。
- 普通生产上传、安全失败／安全重试仍关闭；旧UNKNOWN不重传、不清除、不解锁。
- 当前内部候选只声明已准入的Chrome中文普通已有聊天与对应原始PNG范围；设计辅助窗口不能用泛化的“支持ChatGPT”隐藏此范围。
- 全系统截图入口自排除、不同OS／多屏／Spaces／缩放、Gatekeeper／签名公证、真实Keychain／IME／VoiceOver和反馈云端各有独立证据范围。
