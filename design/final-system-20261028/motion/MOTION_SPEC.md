## 1. 共用几何

本轮统一推荐保留72×56 pt拟合包络，不裁切源字节。影片中的示例图为8:5，因此实际拟合72×45 pt；右侧25%遮挡，露出54×45 pt。

| 参数 | 推荐值 |
| --- | --- |
| 画布 | 1440×900逻辑点 |
| 右侧固定遮挡面 | `x = W − 14 = 1426` |
| 队列首图中心 | `y = 230`（top-down设计坐标） |
| 行中心距 | 60 pt |
| 入口中心 | `(1408, 164)` |
| 原始入口／展开 | 36×36 → 36×132 pt，向上形成同一玻璃面 |
| mode槽中心 | y=164 /132 /100；more=68 |
| 上方mode与取消盖片 | 30×30 pt，radius8 |
| 外边缘 | `1/backingScaleFactor` pt；本Retina参照0.5 pt，强对比1 pt；稳定直线，不弯曲、不开合 |
| 队列编号 | 11 pt，tabular；数字可见右缘到图像可见左缘8 pt；本渲染使用Noto字形作跨平台替代 |

这些数值是本轮主方向的明确设计建议，不能被重新标记成早期用户已经批准的最终几何。影片所用`visibleFrame`简化为top28、足够的bottom空间；多屏、Dock/菜单栏、屏幕负坐标与Retina必须由原生实现按实施规格转换，不复制固定x/y。

## 2. 入缝动效设置：只保留无与磁力吸引

这项偏好 **只决定新截图到达裂缝的装饰运动**。上传开始后的快速吞噬、等待反馈与队列补位不由它关闭。旧两模式设计文件将none扩大到press/swallow/reflow/rebirth的文字，在本轮被最新用户的明确分离要求取代；该修正应在决策登记中公开保留。

**无：** durable assetReady 后直接显示最终位置，时长0；不制作源副本、不等待空间元数据。真实开始后仍使用独立的快速吞噬。系统Reduce Motion是整个表现层的无位移覆盖，不是第三种入缝模式。

**磁力吸引：** 使用同一资产的不可交互装饰副本。时间起点是assetReady，不是快捷键按下、捕获开始或文件系统通知。560 ms只是本轮推荐节奏，不是阻塞点击或上传的门槛。

### 四个阶段

| 阶段 | 时间 | 精确曲线与空间关系 |
| --- | --- | --- |
| 凝缩 | 0–123 ms | 在可信源中心，起始副本最多240×150；按 `1−(1−t)³` 缩到58×46包络内。本示例终值58×36.25；中心不漂移 |
| 定向微颤 | 123–224 ms | 沿源→遮挡面的单位向量；位移 `sin(3πt) × sin(πt) × (1−t) × 1.2 pt`；无随机抖动、无长时间循环 |
| 吸引 | 224–484 ms | 近直线，位置归一化进度`t²·²⁵`；图宽由58连续到72，保持8:5。终点中心`(edge+36, rowCenter)`，整张副本完全进入遮挡面后方 |
| 落位 | 484–560 ms | 新副本从完全遮挡处露出，以outCubic移动到54pt露出量；两段交接处可见面积同为0，不出现公开可见的瞬移 |

1.2 pt是本轮克制化建议，替代旧候选的最大1.85 pt；不是更改已批准模式。摇动幅度受上述阻尼包络压低，实际峰值小于1.2 pt。无particle、光晕爆发、反弹、夸张旋转或裂缝波动。

### 降级与中断

来源矩形缺失、过期、坐标不能可靠转换、跨屏路径未验证、装饰窗口创建失败、系统Reduce Motion开启时，该张直接静态显示。保持magnet偏好供后续有效来源使用。不得自行截获标准截图快捷键来补源信息，也不得伪造系统预览窗口的物理位置。

截图从assetReady起即占有最终行身份和有效命中区，**固定编号立即可见、可点**；飞行ghost不接鼠标。影片从700ms的assetReady事件起显示这一固定编号，不等待目标图像落位。pointerDown、隐藏、取消装饰、视图代际变化应立即结束对应源副本，保留资产。新截图结束旧装饰并仅飞最新一个，避免连续叠影。上传事实、原目标授权、队列顺序和UNKNOWN不受动画回调驱动。

影片演示原速四段连续性；**中断可用性由交互原型和后续原生实现验证，影片本身没有真实命中测试。**

## 3. 点击、等待、快速吞噬与补位

| 状态 | 表现 | 时间／曲线 | 触发与限制 |
| --- | --- | --- | --- |
| 有效press | 向内轻移并复位 | 60 ms outCubic到1.5 pt，再80 ms outCubic复位 | 原点击回应；不表示input或start；替代旧工程80 ms/2.5 pt基线 |
| 已接受、尚未开始 | 微图保留，数字下短线；无假百分比 | 无循环位移 | 只有准备/等待；不能提前吞噬 |
| 无法附加／无ACK | press/reset，按需说明 | 原位置保留 | 不猜目标、不延长原点击授权、不重试旧操作 |
| 正向证明start | 图像进入同一固定遮挡面 | 120 ms，`offset=56×t¹·³⁵` pt | 原asset/operation的uploadStarted；与arrival设置独立 |
| 补位 | 下方行沿纵向收紧 | 160 ms，outCubic | 吞噬后开始；旧标号与横向几何保持到结束，随后更新数字 |
| 最终完成 | 后台记录succeeded/used | 无Riftlet成功动效／Toast | 独立完成证据；在原ChatGPT草稿中看到附件结果 |
| 零可见图片 | 裂缝、编号、队列完全不绘制 | 最后一张吞噬完成同一边界 | 不留下线、幽灵槽或轮廓 |

120 ms跨60fps采样不恰好落在整数帧上。模型保留连续120 ms端点，影片在下一采样帧呈现端点；不能声称影片只用固定7帧或8帧替代120 ms规范。原生应按单调时间驱动而不是按帧数累加。

本片三个合成点击分别在700、2600、4500 ms；三个独立模拟start在1600、3500、5400 ms；对应完成在2600、4500、6400 ms。这里的900 ms等待与1 s后台核对是明确的演示安排，不是性能目标或已测服务延迟。

UNKNOWN保持原状态与身份，已吞噬的UNKNOWN不能自动重生。真实安全失败／安全重试当前继续关闭；未来仅获批的安全失败证据可使同一图按原顺序重生为普通可点图片。不得把UNKNOWN、超时或纯网络中断绘制成已确认失败。交互原型中的失败场景要以“未来准入模拟”标明。

## 4. 预测式入口：固定目标、连续光学

继续沿用已批准的两通道模型：glyph full/enter `.35W/.60W`，glass `.08W/.46W`，退出半径×1.5；glyph rise/fall 18/170ms、glass96/150ms；每60Hz帧增减限幅各自为`.26/.08`和`.065/.06`。

入口影片用这些相同的距离迟滞、独立时间常数和限幅渲染一条明确的靠近／离开路径。为了清晰比较纯光学响应，影片 **没有叠加速度预测boost**；交互原型／原生规格应保留正式参考中的最大700ms预测、240ms衰减与队列附近抑制。这是影片的公开简化，不是取消已批准预测机制。

开合180ms采用quintic smoothstep `6t⁵−15t⁴+10t³`。取消盖片100ms使用同曲线，统一到原生分支已有值；替代HTML参考的105ms Bezier，作为本轮明确的时间统一建议。整个symbol层受同一增长玻璃的clip约束，不允许上方图标浮在玻璃之外。

影片事件：1100ms点击默认窗口，2100ms选区域，2800ms得到合成图且保持区域会话，4000ms切全屏，4600ms再获一图，5600ms主动取消，6400ms起远离。三个模式位置始终不换；所有语义动作在事件时间立即生效，不等视觉结束。

取消后继续沿当前位置淡出到原入口，附近仍可见；成功截图不会触发取消。暴露期间临时自排除属于原生捕获流程，不得被表现为工具条自动收回。

## 5. Reduce Motion、透明穿透与实现约束

系统Reduce Motion：凝缩／微颤／飞行／press位移／吞噬位移／补位／盖片移动直接到对应合法端点；等待仍用静态短线和可读说明。事实事件先后不变，不为“动画关闭”合并上传开始与最终成功。透明度可以按系统无障碍偏好直接切换；不要保留一套持续闪烁的替代动画。

装饰裂缝、磁力副本与玻璃阴影层全部不接鼠标、从AX树隐藏。有效点击区仅属于图片、数字、固定入口槽与原生控件；透明空隙、裂缝线、screen-edge余量不能出现整片透明窗口拦截。pointerDown冻结原资产与布局代际，补位后释放不能命中另一张图。动画不改变原目标ACK、选择owner、visibilityRevision或Core原事件。

单调时钟驱动动画；中断从presentation进度继续，不能重启到0或播放过期completion。hide/close/display change为原动画generation失效；新generation不能被旧回调重新显示。原始图像不转码、不裁切保存，视觉mask不修改源媒体。

## 6. 生成、验证与证据边界

```sh
python3 design/final-system-20261028/motion/render-motion.py
```

依赖：Python3、Pillow、ffmpeg／ffprobe。脚本优先使用可用Noto CJK字体；实际字体名称与渲染器哈希记录在生成的verification.json中。字体文件不作为产品资源或设计包重分发。

`verification.json`记录实际MP4 SHA256、字节数、ffprobe读取的尺寸、帧率、帧数和时长，以及每一张静帧的连续模型时间。H.264/yuv420p编码是播放兼容性取舍；SVG/PNG保留未经过视频色度采样的形态参照。

最终文件已完成实际解码与关键帧目视检查，详见[交付核验](qa/REVIEW.md)。三段影片分别实读396／432／504帧，20张PNG和20份SVG全部通过文件完整性检查；本结论不扩大到原生运行验收。

当前影片并未声称：真实Chrome输入成功、原生NSVisualEffectView光学完全一致、物理鼠标命中、原生AX/WindowServer透明穿透、多屏/Spaces/Retina运行、源空间元数据可靠、实际系统截图自排除或真实安全重试通过。最终AppKit实施须保留已有工程的事实准入，并单独验收这些具体边界。
