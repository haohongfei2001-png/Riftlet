# Riftlet 体验升级：原生实现规格

状态：设计候选，完整可运行原型；生产 App 未修改。基线 main `71d726c5d6416346b84e1ac93047af5bb321d925`。

## 0. 实现范围与权威顺序

1. 已确认产品契约和真实事务状态优先于动画与截图。
2. 用户已有偏好与数据优先于演示默认值。
3. 本文、`SETTINGS-HANDOFF.md`、`SETTINGS-MAP.md`、`TOKENS.json` 定义原生意图。
4. `prototype/` 定义可观察视觉关系和交互结果；浏览器 DOM、模拟时间和示例数据不是新的生产架构。

只在独立实现分支修改表现层。不要重建截图发现、附件输入、事务收据、原图存储或永久删除机制，不覆盖已安装 Beta，不重置用户偏好。此设计分支只新增本目录。

## 1. 统一设计系统

### 颜色和原生材质

| 语义 | 浅色 | 深色 | 用法 |
|---|---|---|---|
| 内容表面 | `#FFFFFF` | `#292D2B` | 阅读区、设置主体、图像预览 |
| 次级表面 | `#FBFAF8` | `#242825` | 侧栏、标题栏、详情区 |
| 主要文字 | `#282B29` | `#E6E9E5` | 标签、值、标题 |
| 次级文字 | `#686F69` | `#A3ABA4` | 有用但低频的帮助信息 |
| 强调 | `#367B6B` | `#92CBB4` | 选中、主要动作、活动状态 |
| 强调底 | `#E8F0EB` | `#344C41` | 侧栏选中、小范围选中底 |
| 主按钮文字 | `#FFFFFF` | `#162C23` | 深色按钮不可沿用白字 |
| 需处理文字 | `#795326` | `#DFBD86` | 可恢复问题；配准确文字和动作 |
| 失败文字 | `#A3533C` | `#EDAA91` | 明确失败；不能只靠颜色 |

将以上实现为动态 `NSColor` 语义角色，不把 HEX 散落到控制器中。`NSVisualEffectView` 适用于侧栏和 popover 外壳；采用系统有效外观与窗口活跃状态。主体、原图和输入控件保持稳定可读表面。网页只模拟材质关系，不规定原生模糊半径。

浅色普通边界约为 `rgba(36,49,42,.12)`，深色约为 `rgba(224,236,225,.13)`。Retina 对齐使用逻辑点和 backingScaleFactor；不要让细边界落在任意半物理像素。外壳投影优先用 `NSWindow` / `NSPopover` 原生阴影，网页的大投影数值不要机械移植。

### 字体、空间和图标

- 正文使用系统字体；中文由系统选择 PingFang。设置标题 22 pt，中等字重；行标题/主要正文 13 pt；次级 12 pt；帮助/状态 11 pt。引导第一屏标题 29 pt，历史标题 20 pt。编号用系统等宽数字 11 pt。
- 基础间距 4/8/12/16/24/32 pt。设置内容左右 32 pt，上方 30 pt；组与组优先留白，普通设置不再各自放一个卡片。
- 微图圆角 1.5 pt，普通控件 6 pt，预览面板 6–8 pt，窗口视觉约 10 pt。系统窗口最终圆角由 AppKit 管理。
- 原生实现使用 SF Symbols，regular 约 14–16 pt；小状态约 12 pt。统一语义和光学重量，不混用彩色 emoji、填充大图标和线性小图标。网页中的线性图标仅表达语义。
- `RiftVisualStyle.swift` 与 `SettingsNativeStyle.swift` 应共享语义角色；可保留独立 API 以降低合并冲突，不要求重构所有控制器。

## 2. P0 桌面边缘与微图

### 几何与布局

| 项目 | 原生基线 | 本轮建议 | 约束 |
|---|---|---|---|
| 最大 Fit 框 | 72 × 56 pt | 保持 | 保留真实长宽比；禁止 crop-fill |
| 默认显示数量 | 3 | 保持 | 可调 1–10；容量不足时沿用分页策略 |
| 藏入比例 | 25% | 保持 | 0% 必须完整显示图像；支持既有范围 |
| 行距 | 60 pt | 新方案展示为 68 pt | 推荐值，不自动迁移既有值 |
| 屏幕边缘内距 | 6 pt | 保持可调 | “裂缝平面”与图片的裁切位置一致 |
| 编号字号/间隔 | 11 / 8 pt | 保持可调 | 独立于图像内容；复杂壁纸下稳定可读 |
| 最小行布局尺寸 | 44 × 44 pt | 保持 | 不因此扩大生产可点击区域 |
| Hover 原图预览 | 原策略为准 | 320 × 240 pt，450 ms 意向延迟 | Fit、不挡下一张主要点击入口 |

布局继续使用 `RiftLayout.swift` 的实际图像 Fit 与容量推导。中心、顶部、底部锚点使用所选屏幕 `visibleFrame`。保留六个位置以及已有 display identifier/UUID；`placement == nil` 代表旧配置语义，不能强制迁移到左中。演示选左中只是为了清楚查看。

**命中区域是不可跨越的实现边界：**原生最小行尺寸是布局约束，不等于整行透明大矩形可点。保留现有图像/编号命中与透明区域穿透，避免挡住桌面或其它窗口。网页按钮为了演示有自己的命中范围，不能照搬成 NSPanel 的 mouse region。

边缘只有一层窄的连接面，长度随当前可见队列收缩，不是完整可拖动工具条。队列为空、用户隐藏、应用退出时完全消失。隐藏与暂停不同：隐藏仍可收录；暂停只停止新收录，已有图像仍可操作。

### 状态表

| 状态/事件 | 图像与编号 | 队列/附件含义 | 用户操作 |
|---|---|---|---|
| 静止 | 真实 Fit、小投影、稳定编号 | 等待点击 | 单击、悬停、右键 |
| 悬停或键盘焦点 | 边界略增强；450 ms 后临时预览 | 不改变事务 | 离开/Esc 关闭预览 |
| 按下 | 朝边缘约 1.5 pt 的轻压，60 ms | 尚未表示上传成功 | 不增加第二步确认 |
| START 前等待 | 图片留在原处；短等待状态不循环吸睛 | 必须继续等待已有真实协调器 | 没有目标时保留截图 |
| 实际 START | 120 ms 吞噬；编号迅速隐去 | 当前附件开始；沿用既有收据权威 | 不自动发送、不修改已有附件 |
| 补位 | 剩余项160 ms平移到正确位置 | 不改变其它事务身份 | 连续点击可独立进行 |
| START 前失败 | 图片保持，不播放吞噬 | 没有开始 | 一个原因、一条恢复路径 |
| START 后明确失败 | 180 ms 恢复图像和命中；轻量一次性说明 | 明确失败 | 可由用户再次单击 |
| START 后结果不确定 | 保持隐藏；历史说明待核实 | 不推断为失败，不自动重新入队 | 先查看原聊天 |
| 用户主动收起/归档 | 从边缘移除 | 原图和已有附件保留；不改写历史事务事实 | 可恢复的项目由用户明确恢复 |

迟到失败必须尊重用户主动收起；不要把它自动重生。显式恢复开启新的展示代次，旧回调不能覆盖新状态。此规则是视觉反馈与现有事务事实的一致性要求，原型的 Set/Map 不是重写生产状态机的建议。

### 两种动效必须分清

**截图到来：**选择仍只有“无 / 磁力吸引”。磁力总时长保持 560 ms：约123 ms出现、101 ms收束、260 ms吸引、76 ms落位。缩放目标取实际 Fit 大小；左右镜像的是运动方向，不是图像内容。末段在目标内侧约3 pt收束，不做75 pt越界回弹。原图出现位置仍由现有 `ArrivalCaptureBridge` / `MagnetFlightPresenter` 决定；网页合成起点不是新生产坐标规则。

**点击附加：**保持60/120/160/180 ms的既有默认 press/swallow/shift/return。对应精细设置允许0，不用 `x || default` 吞掉0。等待 START 的时间是事务时间，不能为“好看”固定延长。原型里180 ms模拟等待只为可演示，不进入生产规格。

Reduce Motion：关闭飞行、位移和弹性，直接更新状态；保留文字状态和焦点。切换系统偏好时立即生效。没有自动循环、空闲动画或成功 Toast。

### 原生落点

`RiftThumbnailAppearance.swift`：边界/阴影/编号；`RiftPanelController.swift`：已有面板、事件与动画连接；`RiftLayout.swift`：保留布局事实；`RiftEdgeAccessories.swift`：编号/分页/预览；`MagnetMotionPlan.swift`、`MagnetFlightPresenter.swift`：收束形态与实际落点；`ArrivalMotionMode.swift`：保持只有两个选项。

## 3. P0 菜单栏控制中心

使用既有 `NSPopover`，推荐内容宽304 pt。正常状态约348 pt内容高度；以 Auto Layout 实际测量结果为准，错误和本地化自然增高。不要硬锁高度造成截断，也不要恢复520 pt空壳。

顺序固定：品牌+状态+设置 → 截图主动作 → 收录/显示两开关 → 历史/定位最新/收起全部 → 反馈与更多。主要按钮34 pt高，普通命令32 pt，两开关行40 pt；左右内边距14 pt。两开关用正向文案，内部 paused/hidden 语义不要泄漏给用户。

异常放在主动作附近，以单个说明区表达当前原因和恢复入口。保存失败文案为“这次保存尚未确认，请重试”，不要笼统承诺旧运行状态已回滚。权限异常指向权限与帮助。退出在更多菜单；不加入统计、推荐、升级推广或长期设置。

复用 `RiftControlCenterPresentation.swift` 的能力与状态判断，重排 `RiftControlCenterController.swift` 的视图。截图入口仍转交原 `ScreenshotEntryController`，不发明第二套截图服务。

## 4. 六页设置

窗口建议780 × 584 pt、导航176 pt，标题基线统一。最小尺寸优先保持既有760 × 540 pt底线；用户自由放大。内容区独立滚动，导航不跟随滚动。仅在有编辑或错误时出现操作栏，应用后的焦点回到稳定控件。

| 页面 | 第一眼可见 | 逐步展开/次级内容 |
|---|---|---|
| 通用 | 外观、暂停、隐藏、登录启动状态 | 使用引导与反馈 |
| 位置与显示 | 显示器、六位置预览、数量、藏入比例 | 尺寸与留白、精细参数 |
| 截图 | 系统快捷键、保存位置、内建入口、默认方式 | 权限恢复、原有截图会话选项 |
| 动效 | 无/磁力、主动预览、减少动态说明 | 四个时长字段 |
| 历史与存储 | 打开历史、自动归档、按需检查用量 | 自定义小数小时、收起边缘全部 |
| 权限与帮助 | 截图目录、Chrome自动化、屏幕录制三项状态 | Chrome JavaScript说明、诊断、配置、关于 |

全部字段、原生类型和保存所有权详见 [SETTINGS-MAP.md](SETTINGS-MAP.md) 与 [SETTINGS-HANDOFF.md](SETTINGS-HANDOFF.md)。不要删有效设置。精细参数不因重新组织而被重置。显示器断开保持所选身份，并解释当前回退显示；不能把临时断开当成重新选择。

## 5. 截图入口、历史与首次使用

### 截图入口

独立的小入口不占微图数量；空队列时可由自己的启用设置控制。展开为紧凑会话工具栏：窗口/区域/全屏；更多里保留指针、0/5/10秒延迟、截图后编辑。系统快捷键仍然是主要习惯。原型不打开编辑器、不请求屏幕录制；原生实现沿用已有能力和权限 gate。

### 历史

建议828 × 582 pt，图像网格区534 pt、详情区294 pt。标题/筛选/搜索和底部工具固定，只有图像区与详情必要时滚动。内部用可缩的剩余空间布局，不能把固定452 pt body叠在标题和footer上。

图片统一用 Fit 放在同一浏览槽；竖图和长图不裁切。按今天/昨天/更早分组，所有原有六状态筛选仍保留，搜索仍限定当前页。真实生产分页保留原有页码/前后页操作；网页只提供一页六条合成数据，不能因此删除生产分页。

点击选择，右侧原图、时间、尺寸与状态；无结果时详情也应为空。原图支持 Fit/100%/200%。已收起/已归档可由用户放回边缘，待核实项不出现自动重传。这里不增加永久删除、标签系统、文件夹或云同步。`HistoryPresentation.swift` 与 `HistoryPreviewLoader.swift` 继续决定真实数据和原图加载。

### 引导

建议620 × 516 pt：介绍、连接、摆放三个步骤，以及简短完成状态。介绍用连贯三步图和主动播放，避免自动动画。权限以能力解释：读取系统保存截图、把点击图像放入当前聊天；屏幕录制仅内建截图需要，不把它当作系统截图收录的前置条件。

权限三态是未检查/未允许/已允许；打开引导不撤销已授权状态。跳过后保留未授权事实，完成页不假装可用。显示器和位置选择来自原有设置，同步到设置中心。完成后关闭引导，等待用户照常截图，不强迫发出测试消息。

## 6. 错误与恢复语言

| 情况 | 推荐表达 | 主动作/行为 |
|---|---|---|
| 无可用聊天 | “暂时没有可用的聊天。请先打开要附加的聊天。” | 微图保留；不自动重试 |
| Chrome自动化未允许 | “允许 Riftlet 控制 Chrome，才能放入当前附件。” | 进入对应系统隐私项 |
| 截图目录不可读 | “还不能读取截图位置。” | 根据实际状态打开目录/重新授权/系统隐私 |
| 保存失败 | “这次保存尚未确认，请重试。” | 保留编辑、显示有效运行状态；不武断回滚 |
| 结果不确定 | “是否附加完成仍不确定，请先查看原聊天。” | 保持隐藏，无自动重生/重传 |
| 明确失败 | “这张图片未能附加，已回到边缘。” | 仅在确已恢复时使用此句；主动收起后不得如此显示 |
| 存储未计算 | “按需检查，不打扰日常使用。” | 主动检查后展示真实值，不能用演示值 |
| 显示器断开 | 说明所选显示器暂不可用与当前回退位置 | 保留显示器身份，恢复时遵循现有策略 |

状态先回答发生什么，再给一个能行动的入口。技术细节折叠到诊断。反馈保留用户主动提交；不默认附带截图、聊天或诊断。成功无弹窗，自动归档无弹窗。

## 7. 无障碍、深色与窗口状态

- 每个图标按钮、微图和预览具有准确辅助名称。关键状态不用颜色单独编码。
- 所有操作可键盘到达；设置重绘保持焦点和文本选择，弹窗圈住焦点，关闭/Escape返回触发来源；来源消失时回到稳定导航。
- `NSWorkspace.accessibilityDisplayShouldReduceMotion`、`accessibilityDisplayShouldReduceTransparency`、`accessibilityDisplayShouldIncreaseContrast` 以及对应通知应动态驱动表现。减少透明度使用不透明表面；增加对比度使用更清晰边界；Reduce Motion不改变事务语义。
- 深色不是浅色反转：主按钮深字、次级面板更深、边界与阴影分别校准。系统跟随外观在运行中变化时响应；非活跃窗口保持可读，不额外变灰到失去层级。
- 强调色不代替系统键盘焦点。网页轮廓示范可见性；原生保留系统 Focus Ring、VoiceOver 和原生控件行为。
- 多屏、不同DPI、菜单栏/刘海安全区、隐藏Dock、全屏窗口、Spaces与休眠恢复须在原生候选中验证，网页四种壁纸和六位置不能证明这些已经通过。

## 8. Codex 最短实施顺序与验收

1. 建立共享颜色/排版/边界角色；保留现有控制器与模型。
2. 边缘微图与两种动效：在隔离合成队列中对齐实际Fit、START门槛、失败/UNKNOWN、连续点击与透明穿透。
3. 重排现有NSPopover；复用原能力判断与恢复动作。
4. 按设置映射完成六页、失败保留和键盘连续性；先不迁移任何旧默认。
5. 接入历史图像网格和引导；保留真实分页、六状态和权限能力。
6. 在独立候选App进行浅/深、四背景、六位置、数量1/3/10、0/25/90藏入、两屏与断开、快速连续点击、减少动态、VoiceOver、中文输入验证。只修具体失败，不反复扩大无目标测试。

截图和录像应绑定候选hash、逻辑尺寸、设备/系统和测试数据身份。设计审查先确认空间/层级/动感，再由原有可靠性验收检查真实附件链路；任一方不能替代另一方。
