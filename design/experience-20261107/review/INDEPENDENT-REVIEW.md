# Riftlet 高保真方案：非作者独立审查

审查角色：独立产品与交互审查，未编写本轮 `prototype/` 源码。

## 当前结论

**推荐采用“截图沿同一个边缘平面收纳”的主方案，进入原生实现。** 实际Mac浏览器渲染中的桌面、控制中心、六页设置、历史与引导已形成一致语言；独立核心状态回归9组通过。初审发现已推动修复，逐项状态见本文件末尾，不能把下文保留的历史问题误读为最终版本仍全部存在。

六页设置采用一致的内容面、对齐行和低频展开，比反复套卡片更轻盈。P0 微图保留极小圆角、原图 Fit、固定边缘和克制编号，这组选择有产品辨识度，不需要增加炫光或玻璃装饰。本结论是设计交付判断，不替代Codex的原生可靠性与真实附件验收。

必须先修的是演示状态完整性、有效设置是否真正驱动视觉、焦点和窄屏查看。不能用一张漂亮的静态截图掩盖这些问题。下文区分已通过的代码证据、已复现的问题和仍待实际渲染的判断。

## 必须修复

### M01 · “连续两张”把 UNKNOWN 重新放回并再次发起

位置：`app.js` → `action('two')`。

当剩余队列少于两张时，代码直接写 `queue=[1,2,3]`，把相应历史记录写成 `waiting`，随后调用 `attach()`。这会把已经开始附加且结果待核实的截图重生并重新发起；它不是用户明确选择“重置示例”的动作。

**独立复现结果：** 对1、2分别完成 UNKNOWN 演示后，队列为 `[3]`、状态为 `[unknown, unknown, waiting]`；点击“连续两张”立刻变成 `[1,2,3]`、`[waiting,waiting,waiting]`。

修复要求：连续演示只消费当下普通可用项；数量不足时添加全新 synthetic asset，或说明需添加截图。只有明确的“重置”可以清空整套演示，不能复用 UNKNOWN 身份。

### M02 · 迟到失败覆盖用户的收起意图

位置：`app.js` → `attach()` failure 分支、`clearQueue()`、单项 context archive。

**独立复现结果：** START 后、120 ms 吞噬尚未结束时执行“收起全部”，记录变为 `removed`、队列为空；950 ms 失败计时完成后，原图又变为 `failed`、无条件加入 `[1]`。

修复要求：操作记录保存可见性意图/修订，迟到失败只对仍允许恢复的原操作重生。用户移除/归档优先；不得改掉保留的失败事实，也不得再附加。仅凭 `!queue.includes(id)` 不能推断用户想恢复。

### M03 · 多个设置控件保存了值，却没有驱动桌面效果

位置：`app.js` → `layout()`、`updateQueue()`、`attach()`、`addScreenshot()`；`app.css` → `.thumb-*` 和动画。

| 有效字段 | 初审中的实际缺口 |
| --- | --- |
| `fitWidth` / `fitHeight` | 主微图仍固定 72×56；藏入计算也固定72 |
| `outerInset` | 只移动 edge-line；按钮仍固定 left:6px，裂缝与微图分离 |
| `rowPitch` | 主舞台强制 `Math.max(60, value)`；与保留原生有效范围的说明矛盾 |
| `numberFontSize` / `numberGap` / `leftPadding` | 主舞台字体和偏移为常数 |
| `minimumHitWidth` / `minimumHitHeight` | 展示字段未改变对应几何 |
| `firstCenterFromTop` | legacy/null 路径未驱动主舞台；多处直接 `.startsWith` 还会在 null 下报错 |
| `pressDuration` / `swallowDuration` | JS 的 `value || default` 把合法0重新变成默认；CSS又固定120 ms吞噬 |
| `shiftDuration` / `returnDuration` | CSS固定160/180 ms，与设置无关 |
| `captureMode` | 保存值后，截图入口的执行未读取它 |

修复要求：由一套已应用布局/时长驱动 P0 和设置示意。零值使用 `??` 或显式有效性判断。若某几何项在浏览器中仅说明原生行为，必须明确标出，不能仍称为“实时预览已更新”。展示数量较多时，需要保持页面内可访问性，不能任由10张落到舞台外。

### M04 · 设置应用/放弃不应跨页误伤草稿

位置：`settings.js` → `saveArea()`、`refreshDraft()`、apply/discard。

初审 apply 校验并提交全部 `s.draft`；discard 直接清空全部 draft。例：在“位置与显示”改宽度，再去“动效”改时长并点击放弃，会同时丢掉宽度草稿。某页字段无误但别页草稿无效时，当前页会试图聚焦一个不存在的输入。

修复要求：当前页应用/放弃仅操作当前域；其他域草稿保留并可见。也可明确设计全局应用语义，但必须用全局位置/文案/错误导航完整表达，不能一半是页内、一半是全局。

### M05 · 权限和长期状态需要同一个事实来源

位置：`app.js` 的 `permissions`、`state.settings.*Permission`、引导、帮助、`attach()`。

初审引导默认 Chrome 未允许，帮助却默认已允许；跳过权限后提示“未授予的能力保持不可用”，微图仍可模拟成功附加。控制中心的权限场景也只改 `scenario`，没有改变对应权限状态。

修复要求：统一权限演示模型；跳过 Chrome 后仍可以收录，但点击应给出不吞噬的准确恢复入口。内置截图权限与系统截图收录继续独立。引导的显示器 select 也应从现有选择渲染，回到该步不能视觉上重置为主显示器。系统外观改变时，选择“跟随系统”必须同步更新；初审仅在点击该选项时取一次值。

### M06 · 恢复现有有效能力，并让无结果状态真实

位置：`captureEntry()`、`history()`、`overlay()`；原生依据 `ScreenshotEntryController.swift`、`RiftHistoryController.swift`。

- 截图会话现有“显示指针”“延时无/5/10秒”“截图后编辑”；初审原型只有固定3秒，缺少指针和编辑，且设置文案宣称它们可在每次截图选择。应收纳到会话“更多”，不删除或擅自换掉有效取值。
- 原生历史有六种筛选：全部、待核实、已附加、已归档、明确失败、已移除。初审把它缩成三项，也没有原有搜索当前页。轻量化应通过布局收纳，不能丢失有效检索路径。
- 历史筛选无结果时仍保留之前 `selectedHistory`，详情继续显示不属于本筛选的图片。应清空选择并展示中性空详情。
- 原生原图支持 Fit/100%/200%；初审“查看原图”仅 Fit。保留轻量缩放，避免让大图只能在小模态中阅读。

### M07 · 弹窗、菜单和重绘后的键盘焦点必须可用

位置：`render()`、`overlay()`、`showContext()`、root keydown、所有触发 render 的控件。

- `aria-modal=true` 没有配合焦点范围或背景 inert；Tab 可以走到弹窗后面的界面。
- `lastFocused` 被赋值，但从未恢复；关闭弹窗/Escape 后焦点丢失。
- 设置页、筛选、开关、主题切换普遍重新建立 DOM，焦点/滚动位置需要主动恢复。
- context menu 没有初始焦点、方向键/菜单项语义或键盘等价打开；仅右键路径不完整。
- 控制中心“更多”是只有 aria-hidden 图标的按钮，缺少可访问名称。
- tablist 的各 scene tab 缺少明确 tabpanel 关系/键盘切换策略。

修复要求：优先用原生语义；弹窗限制焦点、背景不可交互、关闭后回到触发控件；Escape按当前最上层关闭一次。辅助场景 chrome 也应可操作，避免评审者只能依靠鼠标。

### M08 · 减少透明度/高对比不能只写在说明中

初审 `reduceTransparency` / `increaseContrast` 只在 defaults 中存在；主舞台、菜单栏、历史和引导没有对应联动。settings.css 的 `prefers-contrast:more` 只覆盖 `.st-page`。

应为整个设计根层提供系统偏好映射，减少透明度关闭半透明材质与背景模糊，高对比增加边界/文本对比；演示控件可以验证，产品本身不新增权限。

独立按 sRGB 相对亮度计算：

| 小字号内容 | 前景 / 背景 | 对比 |
| --- | --- | --- |
| 控制中心警告 | `#916833` / `#F5EEE2` | 4.30:1 |
| 设置警告 | `#986C32` / `#F7F0E5` | 4.10:1 |
| 纹理壁纸较暗条上的编号 | `#4B5D50` / `#C1BDAE` | 3.74:1 |
| 一般浅色次级文本 | `#686F69` / `#FFFFFF` | 5.16:1 |
| 深色主按钮 | `#162C23` / `#92CBB4` | 8.05:1 |

前三项不满足普通小文本4.5:1的目标。调深警告文本；壁纸上的编号需要稳定的小背景/材质或有效的对比兜底。对比数值是代码色值计算，未包含抗锯齿和动态壁纸实际采样。

### M09 · 窄屏评审不能仅把整个 Mac 桌面缩成邮票

位置：`fit()` 与固定 `1184×720` 的 `.world`。

在390px视口、两侧各18px留白时，缩放约0.299；原12px文字约3.59px，29px控件约8.67px。settings.css 的容器查询无法修复父舞台的整体缩放，因为逻辑布局宽度没有缩窄。

修复要求：为评审壳提供原尺寸查看/可平移放大，或在窄屏把当前窗口独立呈现并可滚动。不能为了手机评审改变实际 macOS 产品布局，但必须使交付能够被打开、读清和操作。

### M10 · 正在进行的动作不能被页面重绘打断成另一种视觉

位置：`attach()` 保存的 row 引用、`render()` 全量重建 DOM、到达 flyer。

初审 attach 在 await 前保存 DOM row；若期间切换主题/场景/开关，后续 swallow class 加到已经脱离页面的旧 row，新的微图先停留、然后突然被队列移除。到达动画也有类似的已移除元素风险。

修复要求：操作事实按 asset/operation保存；重绘根据该事实恢复对应视觉阶段，或在提交阶段重新定位活元素。不能因更换窗口/主题产生第二次附加或恢复已隐藏项。重置属于明确的演示取消，需用 generation 拦截旧回调。

## 推荐改动：能明显提高品质

1. **保留同一条边缘平面，统一真实舞台与设置动效示意。** 初审桌面入缝是先迅速缩小再飞移，设置示意则是柔和弧形平移；两者都叫磁力吸引却表达不同。共用几何与相同的节奏关系，设置预览应直接验证主效果。
2. **保持图像是主角。** 1.5pt微图圆角、细边界和短阴影足够。不要再加大外框、胶囊底座、持续发光或常驻操作按钮。需要注意超宽/超高图在固定纸片里的识别性，实际渲染时用至少三种宽高比验证。
3. **区分产品反馈和评审说明。** 底部“START/120ms”等文字属于评审壳；真实产品只让附件状态和微图变化说话。当前正常成功没有产品内toast，这是正确选择。
4. **控制中心继续维持一眼扫描。** “收录”和“显示”是独立状态，两行不能合并。错误应占用固定状态区或就近替换说明，避免在头部反复堆高卡片。暂停/隐藏时状态圆点应有语义区别，不仅换文字。
5. **历史应更像看画面，而非读数据库。** 继续保留图片网格、时间分组、稳定详情。补全筛选后优先用简洁菜单/分段层次，不把六种筛选强塞成过宽的一行，也不为每一项常驻失败标签。
6. **菜单和预览采用自然结束条件。** 点击界面外关闭popover/context menu；从 hover 进入键盘焦点时预览应保持稳定。主微图的焦点环不应被裁切平面吞掉。
7. **缩小设置窗口是合理判断，但须验证滚动。** 780×584 比基线更克制；所有六页从顶部到底部、展开低频参数以及错误行出现时都须能访问最终操作。不要在原生实施里为了匹配截图强行固定高度。

## 纯审美备选：不构成采用阻碍

- 青绿色再偏冷或偏暖少量；当前中性底色+克制青绿可以作为最终选择，不需再开多套候选。
- 微图阴影扩散半径的微调、侧栏暖度、合成壁纸和示例画面的内容。
- 字标尾点是否保留。它不影响品牌识别核心；核心识别来自边缘的空间和动作。
- 历史介绍页三张纸片的角度。若显得装饰性太强，可以减小旋转，但不值得排在P0交互之前。

## 待闭环的视觉证据
