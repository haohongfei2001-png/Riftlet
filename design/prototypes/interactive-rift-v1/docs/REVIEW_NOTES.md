# 第一轮体验问题 / First-round review notes

这是体验提纲，不是最终设计裁决。基线保留当前原生参数，未加入艺术优化。先在 **100% 逻辑比例**下工作、输入文字、点击微图，再使用缩览比较整屏关系。原型的测试按钮和状态说明属于评审工具，不属于正式 Riftlet。

| 体验 | 值得记录的感受 |
| --- | --- |
| 2–3 张日常队列 | 不刻意寻找时能否发现？阅读和输入时会不会一直吸引注意？ |
| 横图、竖图、长条图 | 竖图露出宽度仅约 23.6 pt；能否靠内容选对图片，还是只能记住编号？遮住右侧四分之一是否丢掉了关键区别？ |
| 浅色与深色环境 | 微图、数字、0.7 pt 细线各自是否清晰？壁纸亮暗变化时，裂缝是否仍可理解为连续边界？ |
| 点击和等待 | 2.5 pt 浅入是否能被察觉？单下划线能否说明正在等待？成功吞噬和后续补位是否连贯？ |
| 失败与 UNKNOWN | 回退是否足以说明未完成？双下划线是否容易与等待区分？没有评审状态说明时，是否知道这张图仍需核对？ |
| 实际点击矩形 | 数字、细长图上下留白也能接收点击。这个范围是否自然，是否与底层工作区域产生意外争用？浏览器内体验不能证明系统级穿透。 |
| 5、8、12 张 | 从稀疏变密集时是否仍有相同的轻量感？首行因可用高度向上调整，会不会破坏位置记忆？ |
| 超出屏幕容量 | 在微图上按行滚动能否自然找到旧图？新图自动露出时是否迷失原来位置？ |
| 连续点击和补位 | 双击被抑制、正在补位的图片不接收新选择，是否感觉可靠或迟钝？只记录体验，不据此取消身份保护。 |

反馈最好指向一个可复现状态，例如：“竖图、深色桌面、12 张、100% 时，第 8 张很难分辨”，或“UNKNOWN 与等待看不出区别”。下一轮可在同一原型中保存基线并对照调整；本轮不冻结最终视觉，也不替换正式 App。

以上问题来自 [源码对应说明](SOURCE_MAPPING.md) 中的实际几何和行为；macOS 字体、动态系统色、AppKit 层级和首次点击体验仍需真机确认。
